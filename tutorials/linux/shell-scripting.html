Shell Scripting That Survives Production Skills

What you'll master: why unquoted variables are the number one cause of shell bugs and what exactly goes wrong, what set -euo pipefail genuinely protects against and the four places it silently does not, how to write cleanup that runs even when the script is killed, why for f in $(ls) breaks on real filenames and what replaces it, how to make a script safe to run twice and safe to run concurrently, and when a shell script has outgrown the shell. Prerequisites: The Shell Executes a Line and Redirection, Pipes & File Descriptors.

Part 1 — Quoting Is the Whole Game

As The Shell Executes a Line covered, an unquoted variable is not a value — it is text that gets re-split on whitespace and then glob-expanded. Nearly every catastrophic shell bug traces back to this one behaviour.

$ file="my report.txt"
$ rm $file                        # runs: rm "my" "report.txt"  — two wrong files
$ rm "$file"                      # runs: rm "my report.txt"    — correct

$ dir="/tmp/data *"
$ ls $dir                         # the * globs against the whole directory
$ ls "$dir"                       # literal, as intended
FormExpands toUse for
"$var"One word, alwaysThe default. Always.
$varSplit on $IFS, then globbedEssentially never — deliberate word splitting only
"$@"Each argument as its own wordPassing arguments through
"$*"All arguments joined into one wordRare; building a message string
"${arr[@]}"Each array element as its own wordIterating arrays
'$var'Literal — no expansion at allRegexes, awk programs, passwords
🔑 The empty-variable disaster. rm -rf "$DIR/" with DIR unset expands to rm -rf /. This is not hypothetical — it has wiped production systems and shipped in released installers. Three defences, all cheap: set -u makes an unset variable a fatal error; "${DIR:?DIR must be set}" aborts with a message naming the variable; and rm -rf "${DIR:?}/" is the idiom to use every single time you interpolate a path into a destructive command.

Parameter expansion handles defaults and validation without a single if:

${VAR:-default}      # use default if unset or empty (does not assign)
${VAR:=default}      # use AND assign default
${VAR:?message}      # abort with message if unset or empty
${VAR:+alt}          # use alt only if VAR IS set — good for optional flags
${#VAR}              # length
${VAR#prefix}        # strip shortest matching prefix   ${VAR##prefix} = longest
${VAR%suffix}        # strip shortest matching suffix   ${VAR%%suffix} = longest
${VAR/old/new}       # replace first    ${VAR//old/new} = replace all

$ path="/var/log/nginx/access.log.1"
$ echo "${path##*/}"          # basename, no subprocess
access.log.1
$ echo "${path%/*}"           # dirname
/var/log/nginx
$ echo "${path%.*}"           # drop the extension
/var/log/nginx/access.log

Part 2 — set -euo pipefail, and Its Four Blind Spots

Every serious script starts with the same three lines. They are worth understanding precisely, because each one has exceptions that catch people out.

#!/usr/bin/env bash
set -euo pipefail
IFS=$'\n\t'          # optional: stop splitting on spaces
OptionEffectThe catch
-e (errexit)Exit on any command failingIgnored in conditions, &&/|| chains, and functions called in a test
-u (nounset)Unset variable is a fatal error"$@" with no args tripped older bash; use ${1:-} for optionals
-o pipefailA pipeline fails if any stage failsWithout it, only the last command's status counts
-x (xtrace)Print each command before running itDebugging only — leaks secrets into logs
$ false | true; echo $?
0                                 # the failure vanished
$ set -o pipefail
$ false | true; echo $?
1                                 # now it is visible

Blind spot 1 — -e does not apply inside conditions. This is by design, since a test needs to be allowed to fail, but it surprises people:

set -e
if grep -q pattern file; then ...  # grep failing here is fine — that is the point
fi
some_function || true              # explicitly tolerated

Blind spot 2 — command substitution in an assignment hides failures:

set -e
result=$(failing_command)          # does NOT exit: the assignment succeeded
echo "still here"

local x=$(failing_command)         # WORSE: `local` itself returns 0, masking everything

# Correct:
result=$(failing_command) || { echo "fetch failed" >&2; exit 1; }
local x; x=$(failing_command) || return 1      # declare and assign separately

Blind spot 3 — arithmetic evaluating to zero is a "failure":

set -e
count=0
((count++))                        # returns 1 because the VALUE was 0 → script exits
((count++)) || true                # the idiom
count=$((count + 1))               # or just avoid (( )) for increments

Blind spot 4 — a failure in a background job or a subshell is invisible unless you wait on it and check the status.

❌ Adding set -e and assuming the script is now safe. It creates a false sense of coverage: the four cases above are exactly where real scripts fail, and every one of them passes set -e silently. A backup script whose tar failed inside a command substitution will report success and upload an empty archive.

✅ Use set -euo pipefail as a floor, then check explicitly where it matters. Any command whose failure would corrupt or lose data gets its own || { log; exit 1; }. And run shellcheck — it finds all four of these classes statically, before they run.

Part 3 — Cleanup That Actually Runs

A script that creates a temp directory, a lock file, or a database snapshot must remove it on every exit path, including the ones you did not write. trap is the mechanism.

#!/usr/bin/env bash
set -euo pipefail

readonly TMPDIR_="$(mktemp -d)"          # never a predictable name in /tmp
cleanup() {
  local rc=$?
  rm -rf "$TMPDIR_"
  [[ $rc -ne 0 ]] && echo "failed with status $rc" >&2
  return $rc
}
trap cleanup EXIT                        # runs on normal exit, error exit, and set -e
trap 'echo "interrupted" >&2; exit 130' INT TERM
Signal / pseudo-signalFires whenCatchable?
EXITAny exit — normal, error, or set -eAlways. The one you want
INTCtrl-CYes
TERMkill, systemd stopYes
ERRAny command fails (with -e)Yes — good for logging context
KILLkill -9No — nothing runs. Design for it

Since SIGKILL cannot be trapped, anything that must not leak needs a second line of defence — a lock file holding a PID that can be validated, or systemd's RuntimeDirectory= which the supervisor cleans up regardless of how the process died. See Signals & Job Control for the underlying mechanics.

# Temp files: let mktemp choose the name, always
tmp="$(mktemp)"                          # /tmp/tmp.8fJ2kL — unpredictable
tmpdir="$(mktemp -d)"
trap 'rm -rf "$tmp" "$tmpdir"' EXIT

# NOT this — predictable name is a symlink-attack vector and collides
tmp="/tmp/myscript.$$"

Part 4 — Iterating Over Files Without Breaking

for f in $(ls) is the most-copied broken idiom in shell. It breaks on spaces, newlines, glob characters, and leading dashes — all of which occur in real filenames.

$ touch "my file.txt" "weird*name.txt" "-rf.txt" "$(printf 'two\nlines.txt')"

$ for f in $(ls); do echo "[$f]"; done
[my]                             # split on the space
[file.txt]
[-rf.txt]
[two]                            # split on the newline
[lines.txt]
[weird*name.txt]                 # and this one will glob later
TaskCorrect form
Files in one directoryfor f in ./*; do [[ -e "$f" ]] || continue; ...; done
Recursivefind . -type f -print0 | while IFS= read -r -d '' f; do ...; done
Recursive, run a commandfind . -type f -exec cmd {} +
Recursive, parallelfind . -print0 | xargs -0 -P4 -n1 cmd
Reading a file line by linewhile IFS= read -r line; do ...; done < file

[./-rf.txt]                      # the ./ prefix prevents it being read as a flag

IFS= read -r deserves unpacking, since each part fixes a specific bug: IFS= stops leading and trailing whitespace being stripped, -r stops backslashes being interpreted as escapes, and -d '' reads NUL-delimited records so embedded newlines cannot split a filename.

The pipeline-subshell trap catches everyone once: each stage of a pipe runs in a subshell, so variables set inside a while loop fed by a pipe are lost when it ends:

$ count=0
$ find . -type f | while read -r f; do count=$((count+1)); done
$ echo "$count"
0                                # the loop ran in a subshell

# Fix: process substitution keeps the loop in the current shell
$ while IFS= read -r -d '' f; do count=$((count+1)); done < <(find . -type f -print0)
$ echo "$count"
4

Part 5 — Idempotence, Locking, and Safe Re-runs

A production script will be re-run: by a retry, by an impatient operator, by two overlapping cron invocations. Two properties make that safe.

Idempotent means running it twice has the same effect as running it once:

mkdir -p /opt/app/data                       # not: mkdir (fails if it exists)
ln -sfn /opt/app/v2 /opt/app/current         # not: ln -s (fails if it exists)
grep -qxF "$line" "$file" || echo "$line" >> "$file"    # not: blind append
useradd app 2>/dev/null || true              # or: id -u app >/dev/null 2>&1 || useradd app
rm -f "$tmp"                                 # -f: no error if already gone

Mutual exclusion stops two copies running at once. flock is the correct tool — it is a kernel lock tied to a file descriptor, so it is released automatically if the process dies, including under SIGKILL:

#!/usr/bin/env bash
set -euo pipefail
exec 200>/var/lock/myjob.lock
flock -n 200 || { echo "already running" >&2; exit 0; }
# ... work ...
# no unlock needed: the fd closes when the process exits, however it exits

# One-liner form, useful in a crontab or a systemd ExecStart
$ flock -n /var/lock/myjob.lock /usr/local/bin/myjob.sh
Locking approachSurvives SIGKILL?Verdict
flock on an fdYes — kernel releases itUse this
PID file, checked with kill -0Stale, but detectableAcceptable; racy without care
mkdir /var/lock/x as an atomic testNo — leaves a stale directoryPortable fallback only
[[ -f lockfile ]] && exitNo, and it racesBroken — check and create are not atomic

Argument parsing should use getopts rather than hand-rolled $1/shift chains, which quietly mishandle bundled flags and missing values:

usage() { echo "usage: $0 [-v] [-o output] input..." >&2; exit 64; }
verbose=0 output=""
while getopts ":vo:h" opt; do
  case "$opt" in
    v) verbose=1 ;;
    o) output="$OPTARG" ;;
    h) usage ;;
    :) echo "-$OPTARG requires an argument" >&2; usage ;;
    \?) echo "unknown option -$OPTARG" >&2; usage ;;
  esac
done
shift $((OPTIND - 1))
[[ $# -gt 0 ]] || usage

Part 6 — Robustness, Testing, and Knowing When to Stop

shellcheck is not optional. It statically finds the entire class of bugs above, and it should run in CI on every script:

$ shellcheck deploy.sh
In deploy.sh line 12:
  rm -rf $BUILD_DIR/*
         ^--------^ SC2086: Double quote to prevent globbing and word splitting.

In deploy.sh line 20:
  cd /opt/app
  ^--------^ SC2164: Use 'cd ... || exit' in case cd fails.

Structure a script so failures are visible and retries are safe:

log()  { printf '%s [%s] %s\n' "$(date -u +%FT%TZ)" "$1" "${*:2}" >&2; }
die()  { log ERROR "$*"; exit 1; }

require() { command -v "$1" >/dev/null || die "missing dependency: $1"; }
require jq; require curl

retry() {                                   # exponential backoff
  local -i attempts=$1 delay=1; shift
  local -i i
  for ((i=1; i<=attempts; i++)); do
    "$@" && return 0
    log WARN "attempt $i/$attempts failed: $*"
    sleep "$delay"; delay=$((delay * 2))
  done
  return 1
}
retry 5 curl -fsS --max-time 10 "$URL" -o "$TMPDIR_/payload.json" \
  || die "download failed after 5 attempts"

curl needs -f specifically: without it, an HTTP 500 response body is written to the file and curl exits 0, so the script happily processes an error page as data.

A dry-run mode costs three lines and makes a destructive script reviewable:

DRY_RUN="${DRY_RUN:-0}"
run() { if [[ $DRY_RUN == 1 ]]; then echo "+ $*" >&2; else "$@"; fi; }
run rm -rf "${TARGET:?}/old"

And know when the shell has run out. Shell is unbeatable for gluing commands together; it is a bad language for logic:

Signal it is time to switchWhy
Past ~200 lines, or nested functions with real logicNo modules, no types, no debugger worth the name
Parsing JSON/XML/YAML beyond a jq one-linerData structures in shell are strings with rules
Arithmetic beyond countersNo floats; bc is a subprocess per operation
Associative arrays, nested databash 4+ only, and painful even there
It needs unit testsPossible with bats, but Python gets you further faster

Interview Questions

Beginner: Why must you quote variables in bash?

Because an unquoted variable is not treated as a value. After substituting the text, the shell performs word splitting on $IFS (space, tab, newline by default) and then pathname expansion on any glob characters in the result.

$ file="my report.txt"
$ rm $file            # becomes: rm "my" "report.txt"   — two wrong files
$ rm "$file"          # becomes: rm "my report.txt"     — correct

The same applies to globs: a variable containing * will expand against the directory contents unless quoted.

The dangerous case is an empty or unset variable. rm -rf "$DIR/" with DIR unset expands to rm -rf /. This has destroyed real production systems and has shipped in released software.

The defences are cheap and layered: set -u makes referencing an unset variable a fatal error, and "${DIR:?DIR must be set}" aborts with a message naming the variable. I would use "${DIR:?}" as a reflex in any destructive command.

The rule I follow is simply: quote every expansion unless you have a specific reason not to — and shellcheck flags the ones you miss.

Beginner: What does set -euo pipefail do?

Three separate protections:

-e exits the script if any command returns non-zero. Without it a script continues past failures, which is how a backup script "succeeds" after its tar failed.

-u makes referencing an unset variable a fatal error rather than an empty string — catching typos and the rm -rf "$UNSET/" disaster.

-o pipefail makes a pipeline return the first non-zero status instead of only the last command's:

$ false | true; echo $?
0                          # failure silently swallowed
$ set -o pipefail
$ false | true; echo $?
1

The important part is knowing where -e does not apply, because that is where real scripts fail:

  • Inside if/while conditions and &&/|| chains — by design, a test must be allowed to fail.
  • result=$(failing_cmd) — the assignment succeeds, so the script continues.
  • local x=$(failing_cmd) — worse, because local itself returns 0.
  • ((count++)) when the value is 0 — returns 1 and exits the script.

So I treat it as a floor rather than a guarantee: anything whose failure would corrupt or lose data gets an explicit || die "...".

Mid: Why is for f in $(ls) wrong, and what should you use?

$(ls) produces one string, which the shell then word-splits on whitespace and glob-expands. Filenames legitimately contain spaces, newlines, *, and leading dashes, and every one of those breaks it:

$ touch "my file.txt" "weird*name.txt" "-rf.txt"
$ for f in $(ls); do echo "[$f]"; done
[my]
[file.txt]              # one file became two iterations
[-rf.txt]               # will be read as a FLAG by the next command
[weird*name.txt]        # will glob when used

The -rf.txt case is the genuinely dangerous one: passed unquoted to rm, it is interpreted as options.

For a single directory, a glob is correct — the shell produces a proper word list:

for f in ./*; do
  [[ -e "$f" ]] || continue        # handles the no-matches case
  process "$f"
done

The ./ prefix matters: it prevents a filename starting with - being taken as an option.

For recursion, use NUL delimiters, since NUL is the only byte that cannot appear in a filename:

find . -type f -print0 | while IFS= read -r -d '' f; do
  process "$f"
done

Each piece matters: IFS= preserves leading/trailing whitespace, -r stops backslash interpretation, -d '' splits on NUL.

One trap to mention: the piped while runs in a subshell, so variables set inside it are lost. If the loop needs to accumulate state, use process substitution instead: while ... done < <(find . -print0). Or skip the loop entirely with find . -type f -exec cmd {} +.

Mid: How do you ensure a script's temporary files are always cleaned up?

With trap ... EXIT, which runs on every exit path — normal completion, an error under set -e, and an explicit exit:

#!/usr/bin/env bash
set -euo pipefail
readonly TMP="$(mktemp -d)"
cleanup() {
  local rc=$?
  rm -rf "$TMP"
  return $rc                     # preserve the original exit status
}
trap cleanup EXIT
trap 'echo interrupted >&2; exit 130' INT TERM

Two details are easy to get wrong. Capture $? first inside the handler, or the commands in the trap overwrite the exit status the caller sees. And use mktemp rather than /tmp/script.$$ — a predictable name in a world-writable directory is a symlink-attack vector and collides between concurrent runs.

The limit worth stating: SIGKILL cannot be trapped. kill -9, an OOM kill, or a power loss runs nothing, so anything that must not leak needs a second mechanism. In practice that means one of:

  • systemd's RuntimeDirectory= / PrivateTmp=yes, which the supervisor cleans up regardless of how the process died
  • A lock file holding a PID that a later run can validate with kill -0 and reclaim
  • systemd-tmpfiles or a boot-time sweep for stale entries

Related: flock is preferable to a lock file precisely because the kernel releases the lock when the fd closes — including on SIGKILL — so it needs no cleanup at all.

Senior: Review this deployment script and identify the problems. 
#!/bin/bash
BUILD_DIR=/tmp/build
rm -rf $BUILD_DIR/*
mkdir $BUILD_DIR
cd $BUILD_DIR
curl https://releases.example.com/app-$VERSION.tar.gz -o app.tar.gz
tar xzf app.tar.gz
for f in $(ls *.conf); do
  cp $f /etc/app/
done
systemctl restart app
echo "deployed successfully"

Nearly every line has a defect, and they compound.

1. No set -euo pipefail. Every failure below is ignored, and the script prints "deployed successfully" regardless — the worst property a deploy script can have.

2. rm -rf $BUILD_DIR/* unquoted, with $VERSION never validated. If BUILD_DIR were unset this is rm -rf /*.

3. mkdir without -p fails on a second run — not idempotent.

4. cd $BUILD_DIR unchecked. If it fails, everything after it — including the tar extraction and the config copy — happens in the wrong directory.

5. curl without -f. An HTTP 500 error page is written to app.tar.gz and curl exits 0. There is no timeout and no retry either.

6. No verification of the download. A deploy pipeline should check a checksum or signature before extracting.

7. tar xzf into the current directory unchecked, with no protection against a malicious archive containing ../ paths.

8. for f in $(ls *.conf) — broken on any filename with a space, and ls is redundant since *.conf is already a glob.

9. cp $f /etc/app/ unquoted, and it is a non-atomic partial update: if the third of five configs fails, the service restarts with a mixed set.

10. systemctl restart unchecked, with no health check afterwards and no rollback path.

The corrected version:

#!/usr/bin/env bash
set -euo pipefail

readonly VERSION="${1:?usage: $0 VERSION}"
readonly BUILD_DIR="$(mktemp -d)"
trap 'rm -rf "$BUILD_DIR"' EXIT

log() { printf '%s %s\n' "$(date -u +%FT%TZ)" "$*" >&2; }
die() { log "ERROR: $*"; exit 1; }

cd "$BUILD_DIR" || die "cannot enter $BUILD_DIR"

curl -fsSL --max-time 60 --retry 3 \
  "https://releases.example.com/app-${VERSION}.tar.gz" -o app.tar.gz \
  || die "download failed for version $VERSION"

sha256sum -c <(curl -fsS "https://releases.example.com/app-${VERSION}.sha256") \
  || die "checksum mismatch"

tar xzf app.tar.gz || die "extract failed"

shopt -s nullglob
configs=(./*.conf)
[[ ${#configs[@]} -gt 0 ]] || die "no config files in the archive"
install -m 0644 -o root -g root "${configs[@]}" /etc/app/ || die "config install failed"

systemctl restart app || die "restart failed"
sleep 2
systemctl is-active --quiet app || die "app is not active after restart"
curl -fsS --max-time 5 http://localhost:8080/health >/dev/null \
  || die "health check failed — investigate before declaring success"

log "deployed $VERSION successfully"

The changes that matter most are the ones that make failure visible: an explicit die on every step, a health check before claiming success, and a version argument that is validated rather than inherited from the environment. I would also note that a real deployment wants atomic config replacement and a rollback path — at which point this has outgrown a shell script and belongs in the configuration-management tool.

Senior: How do you make a script safe to run concurrently, and when should it stop being a shell script?

Concurrency safety has two halves: exclusion and idempotence.

1. Exclusion with flock, which is the only approach that is both atomic and self-releasing:

exec 200>/var/lock/myjob.lock
flock -n 200 || { echo "already running"; exit 0; }

The lock lives on the file descriptor, so the kernel releases it when the process exits — including under SIGKILL, where a trap would never run. A [[ -f lockfile ]] check is broken because testing and creating are two operations with a gap between them, and a PID file needs stale-entry handling that is easy to get subtly wrong.

Choose the failure mode deliberately: -n means "exit if another instance holds it", which is right for a periodic job; omitting it means "wait", which is right for a queue worker but can pile up processes if the holder hangs. flock -w 30 bounds the wait.

2. Idempotence, so a retry after a partial failure is safe:

mkdir -p "$dir"                              # not mkdir
ln -sfn "$target" "$link"                    # not ln -s
grep -qxF "$line" "$f" || echo "$line" >> "$f"
mv "$tmp" "$final"                           # atomic rename, not a partial write in place

The last one is the general principle: write to a temp file and rename, so a reader never observes a half-written state and a crash leaves the old version intact.

3. Bound the runtime so a hung instance does not hold the lock indefinitely: timeout 300 ./job.sh, or systemd's RuntimeMaxSec=.

When to leave the shell — I would switch when any of these appear:

SignalWhy shell stops paying off
Beyond ~200 linesNo modules, no real debugger, testing is awkward
Parsing structured data beyond a jq one-linerShell has strings, not data structures
Any floating-point arithmeticRequires bc — a subprocess per operation
Error handling with recovery, not just abortNo exceptions; every call site checks by hand
It needs unit testsbats exists, but Python gets there faster
Concurrency beyond & and waitNo safe shared state

The dividing line I use: shell is excellent glue and a poor language. If the script is mostly invoking other programs in sequence, shell is the right tool and rewriting it adds nothing. Once it contains real logic — branching on parsed data, retry state machines, partial-failure recovery — the cost of every subsequent change exceeds the cost of the rewrite, and that is the moment to move.

$ bash -c 'set -e;               false | true; echo "exit=$?"'
exit=0                              # failure swallowed
$ bash -c 'set -e -o pipefail;   false | true; echo "unreachable"'; echo "exit=$?"
exit=1

The takeaway: set -euo pipefail is a floor, not a guarantee, and the four cases above are exactly where production scripts fail silently.

Cleanup: rm /tmp/etest.sh.

3 (medium): Write a script whose cleanup survives every exit path.
Solution 
$ cat > /tmp/cleanup_demo.sh <<'EOF'
#!/usr/bin/env bash
set -euo pipefail

readonly TMP="$(mktemp -d)"
readonly MODE="${1:-normal}"

cleanup() {
  local rc=$?                          # capture FIRST — later commands overwrite it
  echo "[cleanup] removing $TMP (exit status was $rc)" >&2
  rm -rf "$TMP"
  return $rc
}
trap cleanup EXIT
trap 'echo "[trap] interrupted" >&2; exit 130' INT TERM

echo "working in $TMP"
dd if=/dev/zero of="$TMP/data" bs=1M count=10 2>/dev/null

case "$MODE" in
  normal) echo "finishing normally" ;;
  fail)   echo "about to fail"; false ;;
  exit7)  echo "exiting with 7"; exit 7 ;;
  hang)   echo "sleeping — press Ctrl-C"; sleep 300 ;;
esac
echo "end of script"
EOF
$ chmod +x /tmp/cleanup_demo.sh

Every path cleans up, and the exit status is preserved:

$ /tmp/cleanup_demo.sh normal; echo "exit=$?"
working in /tmp/tmp.k2Jf8L
finishing normally
end of script
[cleanup] removing /tmp/tmp.k2Jf8L (exit status was 0)
exit=0

$ /tmp/cleanup_demo.sh fail; echo "exit=$?"
about to fail
[cleanup] removing /tmp/tmp.9dLm2X (exit status was 1)
exit=1                                   # status preserved through the trap

$ /tmp/cleanup_demo.sh exit7; echo "exit=$?"
[cleanup] removing /tmp/tmp.4pQr7Z (exit status was 7)
exit=7

Ctrl-C is handled:

$ /tmp/cleanup_demo.sh hang
sleeping — press Ctrl-C
^C[trap] interrupted
[cleanup] removing /tmp/tmp.2wEr5T (exit status was 130)

But SIGKILL is not — and this is the point of the exercise:

$ /tmp/cleanup_demo.sh hang & sleep 1; kill -9 %1
[1]+  Killed                  /tmp/cleanup_demo.sh hang
$ ls -d /tmp/tmp.* 2>/dev/null
/tmp/tmp.8kLm3P                          # LEAKED — no trap ran

Show why capturing $? first matters:

$ bash -c 'cleanup(){ echo cleaning; }; trap cleanup EXIT; exit 5'; echo "exit=$?"
cleaning
exit=0                                   # the echo overwrote the status!
$ bash -c 'cleanup(){ local rc=$?; echo cleaning; return $rc; }; trap cleanup EXIT; exit 5'; echo "exit=$?"
cleaning
exit=5

The second line of defence for SIGKILL — let the supervisor own the directory:

$ sudo systemd-run --unit=cleandemo -p PrivateTmp=yes -p RuntimeDirectory=cleandemo \
>   /bin/sh -c 'echo data > /run/cleandemo/f; sleep 300'
$ ls /run/cleandemo/
f
$ sudo systemctl kill -s KILL cleandemo
$ ls /run/cleandemo/ 2>&1
ls: cannot access '/run/cleandemo/': No such file or directory     # systemd cleaned up

Cleanup: rm -f /tmp/cleanup_demo.sh; rm -rf /tmp/tmp.*.

4 (medium): Iterate over hostile filenames correctly.
Solution

Build a directory designed to break naive loops:

$ mkdir -p /tmp/hostile && cd /tmp/hostile
$ touch "simple.txt" "with space.txt" "with*star.txt" "-rf.txt" \
>       "tab	inside.txt" "$(printf 'new\nline.txt')" "back\\slash.txt"
$ ls -b
-rf.txt  back\\slash.txt  new\nline.txt  simple.txt  tab\tinside.txt  with\ space.txt  with*star.txt

The broken idiom:

$ for f in $(ls); do echo "[$f]"; done
[-rf.txt]
[back\slash.txt]
[new]                        # split by the newline
[line.txt]
[simple.txt]
[tab]                        # split by the tab
[inside.txt]
[with]                       # split by the space
[space.txt]
[with*star.txt]              # will glob on use

7 files became 10 iterations, one of which looks like a command-line flag.

Correct, single directory:

$ for f in ./*; do
>   [[ -e "$f" ]] || continue
>   printf '[%s]\n' "$f"
> done
[./-rf.txt]
[./back\slash.txt]
[./new
line.txt]
[./simple.txt]
[./tab	inside.txt]
[./with space.txt]
[./with*star.txt]

7 files, 7 iterations, and the ./ prefix means -rf.txt can never be read as a flag.

Correct, recursive:

$ count=0
$ while IFS= read -r -d '' f; do
>   count=$((count+1)); printf '%d: %s\n' "$count" "$f"
> done < <(find . -type f -print0)
1: ./-rf.txt
...
7: ./with*star.txt
$ echo "total=$count"
total=7                      # process substitution keeps the loop in THIS shell

Prove the subshell trap:

$ count=0
$ find . -type f -print0 | while IFS= read -r -d '' f; do count=$((count+1)); done
$ echo "count after pipe: $count"
count after pipe: 0          # the loop ran in a subshell; the variable is gone

Show what each read flag protects against:

$ printf '  leading and trailing  \n' | while read -r l; do printf '[%s]\n' "$l"; done
[leading and trailing]                    # whitespace stripped
$ printf '  leading and trailing  \n' | while IFS= read -r l; do printf '[%s]\n' "$l"; done
[  leading and trailing  ]                # preserved

$ printf 'a\\tb\n' | while read l;    do printf '[%s]\n' "$l"; done
[atb]                                     # backslash eaten
$ printf 'a\\tb\n' | while read -r l; do printf '[%s]\n' "$l"; done
[a\tb]                                    # preserved

Or avoid the loop entirely, which is both faster and safe by construction:

$ find . -type f -exec stat -c '%s %n' {} + | sort -rn | head -3
$ find . -type f -print0 | xargs -0 -P4 -n1 md5sum | sort -k2

Cleanup: cd / && rm -rf /tmp/hostile.

5 (hard): Make a script idempotent and concurrency-safe, then prove it.
Solution 
$ cat > /tmp/safejob.sh <<'EOF'
#!/usr/bin/env bash
set -euo pipefail

readonly LOCK=/tmp/safejob.lock
readonly STATE=/tmp/safejob.state
readonly TARGET=/tmp/safejob.out

log() { printf '%s [pid %d] %s\n' "$(date -u +%T)" "$$" "$*" >&2; }

exec 200>"$LOCK"
if ! flock -n 200; then
  log "another instance holds the lock — exiting cleanly"
  exit 0
fi
log "acquired lock"

# Idempotent operations
mkdir -p "$(dirname "$TARGET")"
grep -qxF "configured" "$STATE" 2>/dev/null || {
  log "performing one-time setup"
  echo "configured" >> "$STATE"
}

# Atomic write: temp file + rename, so a reader never sees a partial file
tmp="$(mktemp "${TARGET}.XXXXXX")"
trap 'rm -f "$tmp"' EXIT
log "working..."
{ echo "generated by pid $$ at $(date -u +%T)"; sleep 3; echo "complete"; } > "$tmp"
mv "$tmp" "$TARGET"                     # atomic within the same filesystem
log "done"
EOF
$ chmod +x /tmp/safejob.sh

1. Prove idempotence — run it three times:

$ rm -f /tmp/safejob.state /tmp/safejob.out
$ for i in 1 2 3; do /tmp/safejob.sh; done 2>&1 | grep -E 'setup|done'
09:41:02 [pid 67100] performing one-time setup
09:41:05 [pid 67100] done
09:41:08 [pid 67210] done
09:41:11 [pid 67320] done
$ wc -l /tmp/safejob.state
1 /tmp/safejob.state                    # setup ran exactly once

2. Prove mutual exclusion — five concurrent runs:

$ for i in 1 2 3 4 5; do /tmp/safejob.sh & done 2>&1 | sort | grep -cE 'acquired lock'
1
$ wait
$ # 1 acquired, 4 exited cleanly — no overlap, no error

3. Prove the lock releases on SIGKILL, which a trap-based lock file would not:

$ /tmp/safejob.sh & sleep 1
$ kill -9 %1
[1]+  Killed                  /tmp/safejob.sh
$ /tmp/safejob.sh 2>&1 | grep acquired
09:42:14 [pid 67500] acquired lock       # kernel released it — no stale lock

4. Prove the write is atomic — a reader never sees a partial file:

$ (for i in $(seq 1 300); do
>    if [[ -f /tmp/safejob.out ]]; then
>      grep -q complete /tmp/safejob.out || echo "PARTIAL READ at $i"
>    fi; sleep 0.02
>  done) &
$ /tmp/safejob.sh >/dev/null 2>&1
$ wait
                                         # no PARTIAL READ lines at all

Compare with the naive version, which writes in place:

$ ( echo "generated"; sleep 2; echo "complete" ) > /tmp/naive.out &
$ sleep 1; cat /tmp/naive.out
generated                                # a reader sees a half-written file

5. Bound the runtime so a hung instance cannot hold the lock forever:

$ timeout 10 /tmp/safejob.sh || echo "timed out — lock released by process exit"
# or, in systemd:
#   RuntimeMaxSec=300

6. Choose the waiting behaviour deliberately:

FormBehaviourRight for
flock -n 200Exit immediately if heldPeriodic jobs — skipping one run is fine
flock 200Block until freeQueue workers
flock -w 30 200Wait up to 30s, then failMost things — bounded, and it surfaces contention

Cleanup: rm -f /tmp/safejob.* /tmp/naive.out.

Solution

The starting point — a log archiver with defects on almost every line:

The hardened version:

$ cat > /tmp/archive_v2.sh <<'EOF'
#!/usr/bin/env bash
set -euo pipefail

readonly SRC="${SRC:-/tmp/archdemo/logs}"
readonly DST="${DST:-/tmp/archdemo/archive}"
readonly LOCK=/tmp/archive.lock
DRY_RUN="${DRY_RUN:-0}"

log() { printf '%s [%s] %s\n' "$(date -u +%FT%TZ)" "$1" "${*:2}" >&2; }
die() { log ERROR "$*"; exit 1; }
run() { if [[ $DRY_RUN == 1 ]]; then echo "+ $*" >&2; else "$@"; fi; }

command -v gzip >/dev/null || die "gzip not found"

exec 200>"$LOCK"
flock -n 200 || { log INFO "another run in progress"; exit 0; }

[[ -d "$SRC" ]] || die "source directory missing: $SRC"
run mkdir -p "$DST"

shopt -s nullglob                       # an empty glob yields NO elements, not a literal '*.log'
files=("$SRC"/*.log)
if [[ ${#files[@]} -eq 0 ]]; then
  log INFO "nothing to archive"; exit 0
fi

archived=0 failed=0
for f in "${files[@]}"; do
  base="${f##*/}"                       # basename without a subprocess
  target="$DST/${base}.gz"
  if [[ -e "$target" ]]; then
    log INFO "skipping (already archived): $base"; continue      # idempotent
  fi
  tmp="$(mktemp "${target}.XXXXXX")"
  if run gzip -c "$f" > "$tmp" && run mv "$tmp" "$target"; then
    run rm -f "$f"
    archived=$((archived + 1))
    log INFO "archived: $base"
  else
    rm -f "$tmp"
    failed=$((failed + 1))
    log WARN "FAILED: $base"
  fi
done

log INFO "archived=$archived failed=$failed"
[[ $failed -eq 0 ]] || die "$failed file(s) failed"
EOF
$ chmod +x /tmp/archive_v2.sh

🎯 Key Takeaways

  • Unquoted variables are word-split and glob-expanded — quote every expansion, and use "${VAR:?}" in any destructive command.
  • set -euo pipefail is a floor, not a guarantee: it does not fire in conditions, in result=$(cmd) assignments, after local x=$(cmd), or on ((n++)) evaluating to zero.
  • trap cleanup EXIT runs on every exit path — capture $? first inside the handler so the caller's status is preserved.
  • SIGKILL cannot be trapped, so anything that must not leak needs systemd's RuntimeDirectory=, a validatable lock, or a boot-time sweep.
  • Always use mktemp; a predictable name in /tmp is a symlink-attack vector and collides between runs.
  • for f in $(ls) breaks on spaces, newlines, globs and leading dashes — use for f in ./*, or find -print0 with IFS= read -r -d ''.
  • A while loop fed by a pipe runs in a subshell and loses its variables; process substitution < <(cmd) keeps it in the current shell.
  • Idempotence is a design property: mkdir -p, ln -sfn, rm -f, check-before-append, and write-then-rename.
  • flock on a file descriptor is the only locking that is atomic and self-releasing — the kernel frees it even after SIGKILL.
  • Write to a temp file and mv into place so readers never see a partial file and a crash leaves the old version intact.
  • curl needs -f or an HTTP 500 body is saved as data with exit status 0.
  • Parameter expansion (${p##*/}, ${p%/*}, ${V:-default}) replaces basename, dirname and most if statements without a subprocess.
  • Run shellcheck in CI — every bug class in this lesson is statically detectable.
  • Leave the shell when the script exceeds ~200 lines, parses structured data, needs floats, needs recovery rather than abort, or needs unit tests.
