Decorators & Context Managers Intermediate

What you'll master: decorators as ordinary functions that return replacements, why functools.wraps is not optional, the three-layer factory pattern for decorators that take arguments, decorating methods and classes, lru_cache including the memory leak it causes on methods, the __enter__/__exit__ protocol and what returning True from __exit__ silently does, @contextmanager and its one real limitation, and ExitStack for cleanup that is decided at runtime. Prerequisites: Control Flow & Functions (closures) and Comprehensions, Iterators & Generators (yield).

Part 1 — Decorators: The Mechanism

# A decorator is a callable that takes a function and returns a replacement.
# @ is only syntax for a rebinding you could write yourself.

@timed
def slow(n): ...

# is EXACTLY:
def slow(n): ...
slow = timed(slow)

# ── THE MINIMAL CORRECT DECORATOR ────────────────────────────────────────
import functools, time

def timed(fn):
    @functools.wraps(fn)                     # 1. copy the metadata
    def wrapper(*args, **kwargs):            # 2. accept ANY signature
        start = time.perf_counter()
        result = fn(*args, **kwargs)         # 3. call the original
        elapsed = time.perf_counter() - start
        log.info("%s took %.3fs", fn.__name__, elapsed)
        return result                        # 4. RETURN the result
    return wrapper                           # 5. return the replacement

# Each numbered line is a real bug when omitted:
#   1 missing → slow.__name__ becomes "wrapper"; docs, tracebacks, pickling,
#               pytest fixture names and Flask route registration all break
#   2 missing → works only on the signatures you happened to test
#   3 missing → the function never runs
#   4 missing → every decorated function returns None. Silently.
#   5 missing → the decorated name becomes None → TypeError on call

# ── WHAT wraps ACTUALLY COPIES ───────────────────────────────────────────
def timed(fn):
    def wrapper(*a, **k): return fn(*a, **k)
    return wrapper
slow.__name__      # 'wrapper'   ← without wraps
slow.__doc__       # None
slow.__module__    # wrong module

# functools.wraps copies __name__, __doc__, __module__, __qualname__,
# __dict__ and __annotations__, and sets __wrapped__ = fn. That last one
# lets inspect.signature() see THROUGH the wrapper:
inspect.signature(slow)        # (n) — the real signature, not (*args, **kwargs)
slow.__wrapped__               # the undecorated function — useful in tests

# ── STACKING: BOTTOM UP ──────────────────────────────────────────────────
@log_calls          # applied SECOND (outermost)
@timed              # applied FIRST  (innermost, closest to the function)
def fetch(): ...
# fetch = log_calls(timed(fetch))
#
# At CALL time the order reverses: log_calls runs first, then timed, then
# the real function. Order matters when it changes semantics — @cache above
# @retry caches the successful result; below it, retries hit the cache and
# never actually retry.

# ── WHERE DECORATORS EARN THEIR KEEP ─────────────────────────────────────
# Cross-cutting concerns: timing, retry, caching, auth checks, logging,
# rate limiting, transactions, metrics. The rule is that a decorator should
# be ORTHOGONAL to what the function does. If it needs to know about the
# function's business logic, it is coupling, not a decorator.

Part 2 — Decorators With Arguments

# @retry(times=5) is a CALL that must return a decorator. That is one more
# layer than a plain decorator, and it is the part people get wrong.

def retry(times=3, delay=1.0, exceptions=(Exception,)):
    def decorator(fn):                                   # ← takes the function
        @functools.wraps(fn)
        def wrapper(*args, **kwargs):                    # ← takes the call
            for attempt in range(times):
                try:
                    return fn(*args, **kwargs)
                except exceptions:
                    if attempt == times - 1:
                        raise                            # last one: propagate
                    time.sleep(delay * 2 ** attempt)     # backoff
        return wrapper
    return decorator

@retry(times=5, exceptions=(TimeoutError,))
def fetch(url): ...

# Read it as:  fetch = retry(times=5, ...)(fetch)
#   retry(...)          → decorator      (captures the OPTIONS)
#   decorator(fetch)    → wrapper        (captures the FUNCTION)
#   wrapper(url)        → the actual call
# Three layers, three closures, each capturing one thing.

# ── THE CLASSIC MISTAKE ──────────────────────────────────────────────────
@retry                        # ✗ no parentheses — fn is passed as `times`
def fetch(url): ...
fetch("http://x")             # TypeError, or worse: silently loops
                              # range(fetch) times

# ── SUPPORTING BOTH @deco AND @deco(...) ─────────────────────────────────
def retry(fn=None, *, times=3):
    if fn is None:                          # called WITH arguments
        return functools.partial(retry, times=times)
    @functools.wraps(fn)
    def wrapper(*a, **k): ...
    return wrapper

@retry                # works
@retry(times=5)       # also works
def fetch(): ...
# The keyword-only * forces options to be named, so a bare function
# argument can never be mistaken for one.

# ── DECORATING METHODS ───────────────────────────────────────────────────
# Nothing special is needed: self arrives in *args like any argument.
class Client:
    @retry(times=3)
    def fetch(self, url): ...
# wrapper(*args) receives (self, url). It works because you forwarded
# *args instead of naming parameters.

# ── DECORATING A CLASS ───────────────────────────────────────────────────
def register(cls):
    REGISTRY[cls.__name__] = cls
    return cls                    # MUST return the class

@register
class Handler: ...
# @dataclass works this way: it takes the class, inspects __annotations__,
# adds generated methods, and returns it.

Part 3 — functools

from functools import cache, lru_cache, wraps, partial, cached_property, singledispatch

# ── MEMOISATION ──────────────────────────────────────────────────────────
@lru_cache(maxsize=1024)
def parse_rule(text: str) -> Rule:
    ...                                # expensive, pure, hashable args

parse_rule.cache_info()                # hits, misses, maxsize, currsize
parse_rule.cache_clear()               # essential in tests

@cache                                 # == lru_cache(maxsize=None)
def fib(n):
    return n if n < 2 else fib(n - 1) + fib(n - 2)
fib(100)                               # instant; without the cache this is
                                       # exponential and never finishes

# ── WHEN CACHING IS WRONG ────────────────────────────────────────────────
@cache
def get_user(user_id): return db.query(...)     # ✗ IMPURE — returns a stale
                                                #   user forever after an
                                                #   update elsewhere
@cache
def now(): return datetime.now()                # ✗ time is not an argument
@cache
def process(items: list): ...                   # ✗ TypeError: unhashable

# ── THE MEMORY LEAK PEOPLE SHIP ──────────────────────────────────────────
class Report:
    @lru_cache(maxsize=None)           # ✗ the cache lives on the CLASS
    def compute(self, key):            #   and `self` is part of the key
        ...
# Every Report instance ever passed to compute() is held alive by the cache
# forever. The objects are unreachable by your code and never collected —
# a leak that looks like "memory grows over time" with no obvious owner.
#
# ✓ Per-instance cache instead:
class Report:
    def __init__(self):
        self.compute = lru_cache(maxsize=128)(self._compute)
# ✓ Or, for a no-argument property computed once per instance:
class Report:
    @cached_property
    def stats(self): return expensive_scan(self.rows)
# (cached_property needs a __dict__, so it is incompatible with slots=True.)
#
# And bound the size. @cache on a function called with unbounded distinct
# arguments — user ids, request payloads — grows without limit.

# ── partial: FREEZE ARGUMENTS ────────────────────────────────────────────
from functools import partial
to_json = partial(json.dumps, indent=2, ensure_ascii=False)
to_json(obj)                            # the options are baked in
callback = partial(handle, source="webhook")
# Clearer than a lambda for this, and it survives pickling.

# ── singledispatch: TYPE-BASED OVERLOADS ─────────────────────────────────
@singledispatch
def serialise(obj):
    raise TypeError(f"cannot serialise {type(obj)}")

@serialise.register
def _(obj: datetime) -> str: return obj.isoformat()

@serialise.register
def _(obj: Decimal) -> str: return str(obj)
# Replaces an isinstance chain with something extensible from outside the
# module — a new type registers its own handler without editing serialise.

# ── total_ordering ───────────────────────────────────────────────────────
from functools import total_ordering
@total_ordering
class Version:
    def __eq__(self, o): ...
    def __lt__(self, o): ...           # define these two, get <= > >= free

Part 4 — Context Managers

# `with expr as name:` is:
mgr = expr
name = mgr.__enter__()
try:
    body
finally-ish:
    mgr.__exit__(exc_type, exc_value, traceback)
# __exit__ ALWAYS runs — normal exit, exception, return, break, continue.

class Timer:
    def __enter__(self):
        self.start = time.perf_counter()
        return self                       # ← the `as` value
    def __exit__(self, exc_type, exc, tb):
        self.elapsed = time.perf_counter() - self.start
        log.info("took %.3fs", self.elapsed)
        return False                      # do NOT suppress the exception

with Timer() as t:
    do_work()                             # timed whether it raises or not
t.elapsed

# ── THE RETURN VALUE OF __exit__ IS A TRAP ───────────────────────────────
def __exit__(self, exc_type, exc, tb):
    self.conn.close()
    return True          # ✗ SWALLOWS EVERY EXCEPTION IN THE BLOCK
# A truthy return means "I handled it, do not propagate". Silently. The
# `with` block appears to succeed and execution continues past it with
# half-finished work.
#
# Return False, or None — which is what falling off the end gives you, so
# the safe habit is to simply not return anything unless suppression is
# the deliberate goal.

# ── THE ARGUMENTS TELL YOU WHAT HAPPENED ─────────────────────────────────
def __exit__(self, exc_type, exc, tb):
    if exc_type is None:
        self.conn.commit()                # clean exit
    else:
        self.conn.rollback()              # the block raised
    self.conn.close()                     # both ways
    return False

# ── @contextmanager: THE EASY WAY ────────────────────────────────────────
from contextlib import contextmanager

@contextmanager
def transaction(conn):
    conn.execute("BEGIN")
    try:
        yield conn                        # ← everything before is __enter__,
        conn.execute("COMMIT")            #   everything after is __exit__
    except Exception:
        conn.execute("ROLLBACK")
        raise                             # ← DO NOT SWALLOW
    finally:
        conn.close()

with transaction(db) as conn:
    conn.execute("INSERT ...")
# Commit on success, rollback on failure, close either way — and the
# exception still reaches the caller.

# EXACTLY ONE yield. Zero yields raises RuntimeError("generator didn't
# yield"); two raises RuntimeError("generator didn't stop"). And without
# try/finally, an exception in the body means the teardown NEVER RUNS —
# because the exception is thrown in at the yield point and propagates out
# of the generator.

@contextmanager
def bad(conn):
    conn.execute("BEGIN")
    yield conn
    conn.execute("COMMIT")     # ✗ never reached if the body raises, and
                               #   the connection is never closed

# ── SUPPRESSING DELIBERATELY ─────────────────────────────────────────────
from contextlib import suppress
with suppress(FileNotFoundError):
    Path("cache.tmp").unlink()
# Better than a bare try/except/pass because the intent is in the name and
# the scope of what is ignored is one line.
Key insight: both features exist to move a concern out of the code that has real work to do. A decorator lifts behaviour that repeats around many functions — timing, retry, auth — so the function body contains only its own logic. A context manager lifts the try/finally that guarantees cleanup, so the block contains only what you meant to do with the resource. The failure mode is the same for both: when the wrapper starts needing to know what the wrapped code actually does, the abstraction has stopped paying for itself and is now hiding control flow from the reader.

Part 5 — contextlib and Real Patterns

from contextlib import (contextmanager, closing, suppress, ExitStack,
                        nullcontext, redirect_stdout)

# ── closing: FOR OBJECTS WITH close() BUT NO __exit__ ────────────────────
with closing(urlopen(url)) as page:
    data = page.read()

# ── ExitStack: CLEANUP DECIDED AT RUNTIME ────────────────────────────────
# `with` needs to know how many resources at compile time. ExitStack does
# not.
with ExitStack() as stack:
    files = [stack.enter_context(open(p, encoding="utf-8")) for p in paths]
    merge(files)
# Every file closes on exit, including if open() fails partway through the
# list — the ones already opened are still cleaned up.

# Conditional acquisition without duplicating the block:
with ExitStack() as stack:
    conn = stack.enter_context(db.connect())
    if needs_lock:
        stack.enter_context(lock)                 # sometimes
    stack.callback(metrics.flush)                 # arbitrary teardown fn
    do_work(conn)

# ── nullcontext: OPTIONAL CONTEXT WITHOUT AN if ──────────────────────────
cm = open(path) if path else nullcontext(sys.stdin)
with cm as f:
    process(f)
# Avoids duplicating the whole block for the two cases.

# ── REENTRANCY AND REUSE ─────────────────────────────────────────────────
tx = transaction(db)
with tx: ...
with tx: ...              # ✗ RuntimeError — a @contextmanager generator is
                          #   single-use, exactly like any generator
# Call the factory again for each use: `with transaction(db):`. Class-based
# managers CAN be reusable, but only if __enter__ builds fresh state; the
# stdlib's threading.Lock is reusable but NOT reentrant, which is why
# RLock exists.

# ── A CLASS THAT IS BOTH ─────────────────────────────────────────────────
from contextlib import ContextDecorator

class timed(ContextDecorator):
    def __enter__(self): self.t = time.perf_counter(); return self
    def __exit__(self, *exc):
        log.info("%.3fs", time.perf_counter() - self.t)
        return False

@timed()                  # as a decorator
def work(): ...
with timed():             # and as a context manager
    work()
# @contextmanager gives this for free — its result is already usable both
# ways.

# ── ASYNC VERSIONS ───────────────────────────────────────────────────────
from contextlib import asynccontextmanager

@asynccontextmanager
async def session():
    s = await create_session()
    try:
        yield s
    finally:
        await s.close()

async with session() as s: ...
# async with calls __aenter__/__aexit__. A regular `with` on an async
# resource is a common bug: the coroutine is never awaited and cleanup
# never happens. See Concurrency: GIL, Threads, Async.

Part 6 — When Not To Use Them

# ── DECORATORS HIDE CONTROL FLOW ─────────────────────────────────────────
@retry(times=3)
@rate_limit(per_minute=60)
@cache
@authenticate
@audit_log
def charge(customer_id, amount): ...
# Reading charge() tells you nothing about what happens on call. Whether
# the cache sits above or below the retry changes behaviour materially,
# and nothing in the source says so. Five decorators is a stack trace
# nobody can follow at 3am.
#
# ✓ Two or three orthogonal concerns is a good decorator stack. Past that,
#   make the composition explicit — the wrapper-object approach from the
#   OOP lesson puts the order in one readable line:
charge = Audited(Retrying(RateLimited(processor)))

# ── DECORATORS THAT ARE ACTUALLY COUPLING ────────────────────────────────
@requires_admin
def delete_user(user_id): ...
# Fine: orthogonal, and it fails closed.

@apply_discount_if_premium
def calculate_total(order): ...
# ✗ Business logic pulled out of the function that owns it, into a place
#   nobody looks. Put it in the body.
# The test: could this decorator be applied to an unrelated function and
# still make sense? If not, it is not a cross-cutting concern.

# ── DECORATORS AND TYPE CHECKERS ─────────────────────────────────────────
def timed(fn):
    def wrapper(*args, **kwargs): ...       # signature erased to (*a, **k)
    return wrapper

from typing import Callable, TypeVar, ParamSpec
P, R = ParamSpec("P"), TypeVar("R")

def timed(fn: Callable[P, R]) -> Callable[P, R]:      # ✓ preserves it
    @functools.wraps(fn)
    def wrapper(*args: P.args, **kwargs: P.kwargs) -> R:
        return fn(*args, **kwargs)
    return wrapper
# Without ParamSpec, mypy sees every decorated function as accepting
# anything, and the decorator silently disables type checking at each call
# site. See Type Hints & Typing.

# ── DEBUGGING A DECORATED FUNCTION ───────────────────────────────────────
fetch.__wrapped__(url)         # call the original, bypassing the wrapper
inspect.unwrap(fetch)          # peel every layer
# Both only work because functools.wraps set __wrapped__ — one more reason
# it is not optional.

# ── CONTEXT MANAGERS: THE LINE ───────────────────────────────────────────
# ✓ Anything with a lifetime: files, sockets, locks, transactions, temp
#   directories, changed global state (cwd, env vars, log level, mocked
#   time) that must be restored.
# ✗ Plain sequencing. `with step_one():` for something with no teardown is
#   just an obscured function call.
#
# The test: is there something that MUST happen even if the block raises?
# Yes → context manager. No → it is a function.

Interview Questions

Beginner: What is a decorator, and what does the @ syntax actually do?

A decorator is a callable that takes a function and returns a replacement for it, usually a wrapper that adds behaviour around a call to the original. The @ is only syntax: @timed above def slow(): ... means exactly slow = timed(slow), evaluated at import time when the def executes. Nothing magic happens — it is a function call and a rebinding, which is why you can also apply a decorator manually or keep a reference to the undecorated version. It works because functions are ordinary objects that can be passed around and returned, and the wrapper keeps a reference to the original through a closure. Stacked decorators apply bottom-up, so the one nearest the def wraps the function first and the one at the top ends up outermost.

Beginner: How does a with block guarantee cleanup?

with expr as name evaluates the expression, calls its __enter__ and binds the return value to name, then runs the body inside the equivalent of a try/finally whose finally calls __exit__. Because that call is in the finally position, it runs on every way out of the block — a normal fall-through, a return, a break, or an exception — so teardown is deterministic rather than dependent on the code reaching a particular line. When an exception is in flight, __exit__ receives its type, value and traceback, which is how a transaction manager knows to roll back instead of commit; when the block exited cleanly, those three arguments are None. The everyday examples are open() closing and flushing a file, a lock releasing, a transaction committing or rolling back, and a temporary directory being removed — and the same guarantee is why hand-rolling try/finally at every call site is a worse version of the same idea.

Mid: Write a retry decorator that takes arguments. What is easy to get wrong?

It needs three nested layers, because @retry(times=5) is a call whose result must then be a decorator: the outer function captures the options, the middle one receives the function, and the innermost wrapper receives the actual call arguments. So retry(times=5)(fetch) returns the wrapper, and each layer is a closure over one thing.

The mistakes are consistent. Forgetting functools.wraps leaves the wrapper's own __name__ in place, which breaks anything that introspects — Flask registering routes by function name, pytest matching fixtures, pickling, and every traceback you will read later. Not forwarding *args, **kwargs produces a decorator that only works on the signature you happened to test, and specifically breaks on methods where self is the first argument. Forgetting to return the result of the inner call makes every decorated function return None, which is the quietest of the failures. Writing @retry without parentheses passes the function itself as times. And on the retry logic specifically: re-raising on the final attempt rather than swallowing, sleeping with exponential backoff rather than hammering, and catching a specific exception tuple rather than bare Exception — otherwise you retry programming errors and bad input, which will never succeed no matter how many attempts you make.

Mid: What does @lru_cache do and when is it dangerous?

It memoises: results are stored in a dictionary keyed by the call arguments, so repeat calls with the same arguments return in O(1) without executing the body, with the least-recently-used entry evicted once maxsize is reached. It is close to free for pure, expensive functions — parsing, recursive computations, configuration lookups — and it exposes cache_info() and cache_clear(), the latter being necessary in tests since the cache otherwise persists across them.

It is dangerous in four situations. Arguments must be hashable, so passing a list or dict raises TypeError. The function must be pure: caching anything that touches a database, the clock, or randomness serves a stale value indefinitely, and the bug appears long after the deploy that caused it. @cache with no size bound on a function called with unbounded distinct arguments — user ids, request bodies — grows forever. And the one that actually reaches production most often is decorating a method: the cache is stored on the function object, which lives on the class, and self is part of the key, so every instance ever passed in is held alive permanently. That presents as memory growing steadily with no obvious owner, and the fix is either a per-instance cache built in __init__ or cached_property when the value takes no arguments.

Senior: Write a transaction context manager. Walk through the failure modes.

The @contextmanager version is a generator with exactly one yield: begin the transaction, try, yield the connection, commit on the normal path, except to roll back and then raise, and finally to release the connection. Everything before the yield is __enter__ and everything after is __exit__, with the body's exception thrown in at the yield point.

Four failure modes matter. Without try/finally around the yield, an exception in the body propagates straight out of the generator and the commit, rollback and close never execute — the connection leaks and the transaction is left open until the server times it out. Catching the exception and not re-raising is worse: the rollback happens, the caller sees a clean return, and the program carries on believing work was persisted that was not. In the class-based form the equivalent bug is returning True from __exit__, since a truthy return means "handled, suppress" — which is why the safe habit is returning nothing at all unless suppression is deliberate. And having more than one yield, or a yield inside a loop, raises RuntimeError: generator didn't stop during teardown, which surfaces as a confusing error at the end of the block rather than at the mistake.

Two more things I would raise in review. A @contextmanager instance is single-use because the underlying generator is, so tx = transaction(db) reused across two with statements raises — always call the factory per block. And nested transactions need savepoints rather than a nested BEGIN, so if the manager can be entered recursively it has to track depth and issue SAVEPOINT/RELEASE, otherwise an inner rollback silently discards the outer transaction's work too.

Senior: When do decorators become a liability?

Decorators buy separation of a cross-cutting concern from the logic it surrounds, and they charge for it in visibility. A stack of five means that reading the function body tells you almost nothing about what happens when it is called: authentication, rate limiting, caching, retry and audit logging all execute in an order determined by the source order of the decorators, and nothing states that order's significance. It matters concretely — @cache above @retry caches the final successful result, while below it the retry loop hits the cache and never actually retries. Both arrangements look identical at a glance and one of them is a bug. Tracebacks through several wrappers are also genuinely harder to read, and debuggers step into wrapper frames that have nothing to do with the problem.

My test for whether something belongs in a decorator is whether it could sensibly be applied to an unrelated function. Timing, retry, authorisation and metrics pass that test; a decorator called @apply_discount_if_premium does not, because it is business logic that has been moved out of the function that owns it into a place nobody thinks to look. The second signal is a decorator that needs to inspect or modify the function's arguments in a domain-specific way — at that point it is coupled to the function's meaning, not orthogonal to it.

Beyond two or three layers I prefer explicit composition, the wrapper-object approach: writing Audited(Retrying(RateLimited(processor))) puts the order on one readable line where it can be discussed in review, and each layer stays independently testable. There is also a typing cost worth knowing about — a decorator written without ParamSpec erases the wrapped signature to (*args, **kwargs), so every call site of every decorated function silently loses type checking. That is a large amount of safety to give up for a wrapper, and it is invisible until someone checks why mypy stopped catching things.

1 (easy): Write a @timed decorator correctly, then list what breaks if each piece is omitted.
Solution 
import functools, time

def timed(fn):
    @functools.wraps(fn)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        try:
            return fn(*args, **kwargs)
        finally:                                  # times failures too —
            elapsed = time.perf_counter() - start # often the ones you care
            log.info("%s took %.3fs", fn.__name__, elapsed)   # about most
    return wrapper

@timed
def fetch(url, timeout=5): ...

# ── EACH PIECE, AND THE BUG WITHOUT IT ───────────────────────────────────
#
# @functools.wraps
#   fetch.__name__ == "wrapper", __doc__ is None, __module__ is wrong.
#   Real breakage: Flask registers routes by endpoint name → all decorated
#   views collide on "wrapper"; pytest cannot resolve fixtures; Sphinx
#   documents nothing; pickle fails; every traceback says "wrapper".
#   It also sets __wrapped__, which is what lets inspect.signature() report
#   (url, timeout=5) instead of (*args, **kwargs).
#
# *args, **kwargs
#   def wrapper(url) works on fetch and breaks on everything else —
#   including any METHOD, where self is the first positional argument.
#
# return fn(...)
#   Every decorated function returns None. No exception, no warning. The
#   quietest bug on this list.
#
# return wrapper
#   The decorator returns None, so `fetch` IS None → TypeError on call.
#
# try/finally
#   Without it, a raising call is never timed — so the slow path that
#   times out is invisible in your metrics.

# ── VERIFY ───────────────────────────────────────────────────────────────
assert fetch.__name__ == "fetch"
assert str(inspect.signature(fetch)) == "(url, timeout=5)"
assert fetch.__wrapped__ is not None      # the undecorated original
2 (easy): Convert this try/finally into a context manager, both ways.
Solution 
# BEFORE — repeated at every call site, and easy to get wrong once
old_level = logger.level
logger.setLevel(logging.DEBUG)
try:
    run_diagnostics()
finally:
    logger.setLevel(old_level)

# ── WAY 1: @contextmanager (preferred for simple cases) ──────────────────
from contextlib import contextmanager

@contextmanager
def log_level(logger, level):
    old = logger.level
    logger.setLevel(level)
    try:
        yield logger                      # ← the `as` value
    finally:
        logger.setLevel(old)              # restored on ANY exit path

with log_level(logger, logging.DEBUG):
    run_diagnostics()

# ── WAY 2: A CLASS ───────────────────────────────────────────────────────
class log_level:
    def __init__(self, logger, level):
        self.logger, self.level = logger, level
    def __enter__(self):
        self.old = self.logger.level
        self.logger.setLevel(self.level)
        return self.logger
    def __exit__(self, exc_type, exc, tb):
        self.logger.setLevel(self.old)
        return False                      # do not suppress

# ── WHICH ONE ────────────────────────────────────────────────────────────
# @contextmanager  — shorter, and setup/teardown sit next to each other so
#   they cannot drift apart. Single-use per call.
# Class            — when you need state readable afterwards (a Timer's
#   .elapsed), reusability, or inheritance.

# ── THE TWO MISTAKES ─────────────────────────────────────────────────────
@contextmanager
def bad(logger, level):
    old = logger.level
    logger.setLevel(level)
    yield logger
    logger.setLevel(old)        # ✗ NEVER RUNS if the body raises. The
                                #   process is left at DEBUG forever.

def __exit__(self, exc_type, exc, tb):
    self.logger.setLevel(self.old)
    return True                 # ✗ swallows every exception in the block
3 (medium): Write @retry with backoff, usable on both functions and methods, and say what should not be retried.
Solution 
import functools, random, time

def retry(times=3, base_delay=0.5, exceptions=(TimeoutError, ConnectionError)):
    def decorator(fn):
        @functools.wraps(fn)
        def wrapper(*args, **kwargs):
            for attempt in range(times):
                try:
                    return fn(*args, **kwargs)
                except exceptions as e:
                    if attempt == times - 1:
                        raise                       # exhausted — propagate
                    delay = base_delay * 2 ** attempt      # exponential
                    delay *= 0.5 + random.random()         # JITTER
                    log.warning("%s failed (%s), retry %d in %.1fs",
                                fn.__name__, e, attempt + 1, delay)
                    time.sleep(delay)
        return wrapper
    return decorator

class ApiClient:
    @retry(times=5)
    def fetch(self, url): ...      # works: self arrives in *args

# ── THE THREE LAYERS ─────────────────────────────────────────────────────
#   retry(times=5)      → decorator   captures the OPTIONS
#   decorator(fetch)    → wrapper     captures the FUNCTION
#   wrapper(self, url)  → the call    captures the ARGUMENTS

# ── WHAT MUST NOT BE RETRIED ─────────────────────────────────────────────
except Exception:              # ✗ retries ValueError, KeyError, TypeError —
                               #   deterministic bugs that will fail
                               #   identically 3 more times, 3x slower,
                               #   with the real traceback buried
# Retry TRANSIENT failures only: timeouts, connection resets, 429, 503.
# Never 4xx (except 429) — the request is wrong and repeating it will not
# fix it.

# ── NON-IDEMPOTENT OPERATIONS ────────────────────────────────────────────
@retry(times=3)
def charge(customer, amount): ...
# ✗ A timeout does NOT mean the charge failed — it may have succeeded with
#   the response lost. Three retries can mean three charges.
# ✓ Requires an idempotency key so the server dedupes:
@retry(times=3)
def charge(customer, amount, idempotency_key): ...

# ── WHY JITTER ───────────────────────────────────────────────────────────
# Without it, every client that failed at t=0 retries at exactly t=0.5,
# t=1.5, t=3.5 — synchronised waves that keep a recovering service down.
# This is the thundering herd, and it turns a blip into an outage.

# ── AND A CEILING ────────────────────────────────────────────────────────
delay = min(base_delay * 2 ** attempt, 30)     # cap it
# 10 retries of pure exponential backoff is a 512-second sleep holding a
# worker, a connection and a request slot.

from functools import lru_cache, cache, cached_property

# ── THE GOOD CASE: PURE, HASHABLE ARGS, BOUNDED ──────────────────────────
@lru_cache(maxsize=1024)
def parse_rule(pattern: str) -> Rule:

parse_rule.cache_info()      # CacheInfo(hits=980, misses=20, currsize=20)
parse_rule.cache_clear()     # call this in test teardown, or the cache
                             # leaks between tests

# ── THE LEAK ─────────────────────────────────────────────────────────────
class ReportBuilder:
    @lru_cache(maxsize=None)              # ✗
    def summarise(self, period):
        return expensive_scan(self.rows, period)

# The cache is an attribute of the FUNCTION OBJECT, which lives on the
# CLASS — one cache shared by all instances, for the life of the process.
# `self` is part of every cache key, so the cache holds a strong reference
# to every ReportBuilder ever passed in.
#
# Symptom: memory grows steadily and nothing shows up as the owner. The
# builders are unreachable from your code and will never be collected.
# maxsize=None means it never even evicts.

# ── FIX 1: PER-INSTANCE CACHE ────────────────────────────────────────────
class ReportBuilder:
    def __init__(self, rows):
        self.rows = rows
        self.summarise = lru_cache(maxsize=32)(self._summarise)
    def _summarise(self, period):
        return expensive_scan(self.rows, period)
# The cache now lives on the instance and dies with it.

# ── FIX 2: cached_property, WHEN THERE ARE NO ARGUMENTS ──────────────────
class ReportBuilder:
    @cached_property
    def totals(self):
        return expensive_scan(self.rows)
# Computed once per instance, stored in the instance __dict__, collected
# with the instance. Note: needs a __dict__, so it does NOT work with
# @dataclass(slots=True), and it never invalidates — only correct when
# self.rows is fixed for the object's lifetime.

# ── WHEN CACHING IS SIMPLY WRONG ─────────────────────────────────────────
@cache
def get_user(user_id): return db.query(...)   # ✗ stale after any update,
                                              #   forever, process-wide
@cache
def process(items: list): ...                 # ✗ TypeError: unhashable
@cache
def current_rate(): return api.fetch_rate()   # ✗ no arguments = one entry
                                              #   that never changes

# For anything backed by mutable state you need explicit invalidation and
# a TTL — which means a real cache (Redis, cachetools.TTLCache), not
# lru_cache. lru_cache is for pure functions.
5 (hard): A @contextmanager transaction sometimes leaves connections open and sometimes reports success after a rollback. Find both bugs.
Solution 
# ✗ BUG 1 — no try/finally
@contextmanager
def transaction(pool):
    conn = pool.acquire()
    conn.execute("BEGIN")
    yield conn
    conn.execute("COMMIT")
    pool.release(conn)

with transaction(pool) as c:
    c.execute("INSERT ...")
    raise ValueError("boom")
# The exception is thrown in AT the yield and propagates straight out of
# the generator. COMMIT never runs — correct. But release() never runs
# either, so the connection is never returned to the pool and the
# transaction stays open until the server's idle timeout.
#
# Under load the pool drains and every request blocks on acquire(). The
# symptom is "the app hangs", far from the exception that caused it.

# ✗ BUG 2 — swallowing
@contextmanager
def transaction(pool):
    conn = pool.acquire()
    conn.execute("BEGIN")
    try:
        yield conn
        conn.execute("COMMIT")
    except Exception:
        conn.execute("ROLLBACK")          # ← no re-raise
    finally:
        pool.release(conn)

with transaction(pool) as c:
    c.execute("INSERT ...")
    charge_customer()                     # raises
send_confirmation_email()                 # ← RUNS. The insert was rolled
                                          #   back and the customer gets a
                                          #   receipt for nothing.
# The `with` block appears to have succeeded. Every line after it executes
# on the assumption that the work was persisted.

# ✓ CORRECT
@contextmanager
def transaction(pool):
    conn = pool.acquire()
    conn.execute("BEGIN")
    try:
        yield conn
    except Exception:
        conn.execute("ROLLBACK")
        raise                             # ← the caller MUST know
    else:
        conn.execute("COMMIT")            # only on the clean path
    finally:
        pool.release(conn)                # ALWAYS

# try/except/else/finally maps exactly onto the four cases:
#   try     the body runs
#   except  it failed        → roll back, re-raise
#   else    it succeeded     → commit
#   finally either way       → release

# ── THE CLASS-BASED EQUIVALENT OF BUG 2 ──────────────────────────────────
def __exit__(self, exc_type, exc, tb):
    if exc_type: self.conn.rollback()
    else:        self.conn.commit()
    self.conn.close()
    return True        # ✗ truthy = "handled, suppress" — same silent bug
                       # ✓ return False, or nothing at all

# ── THIRD BUG, WORTH KNOWING ─────────────────────────────────────────────
tx = transaction(pool)
with tx: ...
with tx: ...           # RuntimeError: generator didn't yield
# A @contextmanager instance is single-use, because the generator behind it
# is. Always call the factory inside the `with`.
6 (hard): Design the decorator and context-manager layer for a service with auth, rate limiting, caching, retry and audit — and decide what should not be a decorator.
Solution 
from contextlib import ExitStack, contextmanager
from typing import Callable, ParamSpec, TypeVar
import functools

P, R = ParamSpec("P"), TypeVar("R")

# ── 1. TYPE-PRESERVING DECORATORS ────────────────────────────────────────
def audited(fn: Callable[P, R]) -> Callable[P, R]:
    @functools.wraps(fn)
    def wrapper(*args: P.args, **kwargs: P.kwargs) -> R:
        audit.record(fn.__name__, "start")
        try:
            result = fn(*args, **kwargs)
        except Exception as e:
            audit.record(fn.__name__, "failed", error=str(e))
            raise
        audit.record(fn.__name__, "ok")
        return result
    return wrapper
# Without ParamSpec, mypy sees charge(...) as accepting anything, and type
# checking is silently disabled at every call site of every decorated
# function. That is a lot of safety to lose to a wrapper.

# ── 2. WHAT IS A DECORATOR, AND WHY ──────────────────────────────────────
#
#   @requires_role("admin")   ✓ orthogonal, fails closed, applies to any
#                               endpoint identically
#   @rate_limit(60)           ✓ orthogonal, config not logic
#   @audited                  ✓ orthogonal, must not be forgotten
#
#   @retry(3)                 ⚠ ONLY on idempotent operations. On charge()
#                               a timeout may mean the charge SUCCEEDED and
#                               the response was lost — three retries can
#                               be three charges. Needs an idempotency key
#                               first.
#
#   @apply_premium_discount   ✗ business logic hidden outside the function
#                               that owns it. Put it in the body.
#   @validate_order           ✗ domain-specific; belongs in the function or
#                               in a Pydantic model at the boundary.
#
# THE TEST: could this decorator be applied to an unrelated function and
# still make sense? Yes → cross-cutting. No → it is coupling.

# ── 3. STACK ORDER IS A DESIGN DECISION ──────────────────────────────────
@audited                       # outermost — records the caller's INTENT,
@requires_role("admin")        #   one logical operation, not 3 attempts
@rate_limit(per_minute=60)
@cache(ttl=60)
@retry(times=3)                # innermost — retries only the raw call
def get_report(report_id): ...

# Call order is top-down: audit → auth → rate limit → cache → retry → body.
#
# Swap @cache and @retry and you get a real bug: the retry loop would hit
# the cache on every attempt and never actually retry. Swap @audited below
# @retry and one user action produces three audit entries.
#
# Nothing in the source says any of this. Which is exactly the problem.

# ── 4. PAST THREE LAYERS, COMPOSE EXPLICITLY ─────────────────────────────
service = Audited(RateLimited(Cached(Retrying(ReportService()))))
# The order is now one readable line that can be discussed in review, each
# layer is independently testable with a fake, and a new engineer can see
# the pipeline without knowing how decorators stack. Same objects, same
# behaviour, visible instead of implicit. (See OOP & Dataclasses.)

# ── 5. CONTEXT MANAGERS FOR THE LIFETIMES ────────────────────────────────
@contextmanager
def request_scope(request_id, user):
    token = current_request.set(RequestContext(request_id, user))
    start = time.perf_counter()
    try:
        yield
    finally:
        current_request.reset(token)      # a ContextVar MUST be reset, or
                                          # it leaks into the next request
                                          # on a reused worker thread
        metrics.observe("request_duration",
                        time.perf_counter() - start)

# Runtime-determined cleanup — the case a plain `with` cannot express:
with ExitStack() as stack:
    conn = stack.enter_context(pool.acquire())
    stack.enter_context(request_scope(rid, user))
    if needs_lock:
        stack.enter_context(distributed_lock(key))     # conditional
    stack.callback(cache.flush_pending)                # arbitrary teardown
    handle(conn)
# Everything unwinds in reverse order, including if a later enter_context
# raises — the earlier ones are still cleaned up.

# ── 6. WHAT IS DELIBERATELY NOT HERE ─────────────────────────────────────
# No @transactional decorator. A transaction's SCOPE is rarely one whole
#   function — it is usually a few statements inside it, and a decorator
#   cannot express that. `with transaction(db):` in the body can.
# No @log_arguments. It leaks PII into logs by default, which is a
#   compliance problem, not a debugging feature.
# No decorator that reads or rewrites domain arguments — that is coupling
#   wearing a decorator's syntax.

🎯 Key Takeaways

  • @deco is only fn = deco(fn), evaluated at import time — no magic.
  • functools.wraps is not optional: without it, Flask routes, pytest fixtures, tracebacks and inspect.signature all break.
  • Forward *args, **kwargs and return the result — omitting the return makes every decorated function silently yield None.
  • A decorator with arguments needs three layers: options, function, call.
  • lru_cache on a method holds every instance alive forever; use a per-instance cache or cached_property.
  • Cache only pure functions, and bound the size — @cache on unbounded arguments grows without limit.
  • __exit__ runs on every exit path; a truthy return from it silently swallows the exception.
  • @contextmanager needs exactly one yield inside try/finally, and must re-raise after rolling back.
  • ExitStack is for cleanup whose shape is only known at runtime — conditional or variable-length resources.
  • Two or three orthogonal decorators is a good stack; past that, compose objects explicitly so the order is visible.
