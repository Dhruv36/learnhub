Linked List In-place Reversal Core Pattern

What you'll master: the three-pointer reversal loop and why the order of its four assignments is forced rather than arbitrary; the dummy-node technique that eliminates every "what if it's the head" special case; reversing a sublist between positions m and n in one pass; the k-group reversal that most candidates fail, including the "check the length first" requirement; and the composite problems — reorder, palindrome, add-two-numbers, swap-pairs — that are reversal combined with fast/slow pointers. Prerequisites: Fast & Slow Pointers, Big-O.

Part 1 — The Three-Pointer Loop

Reversal means redirecting every next pointer backwards. The difficulty is that overwriting cur.next destroys the only reference to the rest of the list — so it must be saved first.

before:   null   1 → 2 → 3 → null
                 ↑
                cur

step:     save nxt = cur.next        (2)
          cur.next = prev            (1 → null)
          prev = cur                 (prev = 1)
          cur = nxt                  (cur = 2)

after:    null ← 1   2 → 3 → null
                 ↑   ↑
               prev cur

function reverseList(head) {                     // LC 206
  let prev = null, cur = head;
  while (cur) {
    const nxt = cur.next;                        // 1. SAVE — or the rest is lost
    cur.next = prev;                             // 2. REVERSE
    prev = cur;                                  // 3. advance prev
    cur = nxt;                                   // 4. advance cur
  }
  return prev;                                   // cur is null; prev is the new head
}
// O(n) time, O(1) space
🔑 The four lines are in the only order that works, and each has a reason. Saving nxt must come first because line 2 overwrites the pointer it reads. Advancing prev must come after line 2, or cur.next would point at itself. And cur = nxt must be last, because it uses the value saved in line 1. Reordering any pair either loses the list or creates a self-loop — which is why "memorise four lines" fails under pressure and "derive the dependencies" does not.

Return prev, not cur. The loop exits when cur becomes null, at which point prev holds the last node processed — the original tail, which is the new head.

InputResultWhy it works
nullnullLoop never runs; prev stays null
[1][1]One iteration; 1.next = null
[1,2][2,1]Two iterations

The recursive version is elegant and worth knowing, but it is O(n) stack space — a real disqualifier when the problem says O(1):

function reverseListRec(head) {
  if (!head || !head.next) return head;          // base: empty or single node
  const newHead = reverseListRec(head.next);     // reverse everything after
  head.next.next = head;                         // the node after me points BACK at me
  head.next = null;                              // and I become the tail
  return newHead;                                // unchanged all the way up
}
// O(n) time, O(n) stack — stack overflow on long lists

Part 2 — Dummy Nodes Remove Special Cases

Most linked-list bugs come from one question: "what if the node I am modifying is the head?" A dummy node makes the head an ordinary node, and the question disappears.

without dummy:   head → 1 → 2 → 3          removing 1 needs a special branch
with dummy:      dummy → 1 → 2 → 3         every node has a predecessor
                   ↑
             return dummy.next at the end

function removeElements(head, val) {             // LC 203
  const dummy = { val: 0, next: head };
  let cur = dummy;
  while (cur.next) {
    if (cur.next.val === val) cur.next = cur.next.next;   // no head special case
    else cur = cur.next;
  }
  return dummy.next;                             // ← NOT head, which may be removed
}
Use a dummy whenBecause
The head might be removedDeleting needs a predecessor
The head might changeReversal, partitioning, merging
Building a new listAvoids "is this the first node?" checks
Merging sorted listsThe first node could come from either input

Always return dummy.next, never the original head — the head variable may point at a node that was removed or is no longer first.

Part 3 — Reversing a Sublist

Reverse only positions m through n, in one pass. The technique is to reach the node before position m, then repeatedly pull the next node to the front of the reversed section.

1 → 2 → 3 → 4 → 5,  m=2, n=4

prev = 1 (node before the section)
      1 → 2 → 3 → 4 → 5
          └─ reverse this ─┘

pull 3 in front of 2:   1 → 3 → 2 → 4 → 5
pull 4 in front of 3:   1 → 4 → 3 → 2 → 5

function reverseBetween(head, m, n) {            // LC 92
  const dummy = { val: 0, next: head };
  let prev = dummy;
  for (let i = 1; i < m; i++) prev = prev.next;  // node BEFORE position m

  const start = prev.next;                       // stays put; becomes the section's tail
  for (let i = 0; i < n - m; i++) {
    const moved = start.next;                    // the node to pull forward
    start.next = moved.next;                     // unlink it
    moved.next = prev.next;                      // splice it after prev
    prev.next = moved;
  }
  return dummy.next;
}
// O(n) time, O(1) space, ONE pass

start never moves. It begins as the first node of the section and ends as its last — every iteration pulls the node after it forward, so it drifts backwards relative to the others without its own pointer ever changing. Understanding that is what makes the three-line splice memorable.

Part 4 — Reverse Nodes in k-Group

The hardest common variant: reverse every consecutive group of k nodes, leaving a final partial group untouched.

1 → 2 → 3 → 4 → 5,  k = 2   →   2 → 1 → 4 → 3 → 5
                                                ↑ fewer than k left, unchanged

function reverseKGroup(head, k) {                // LC 25
  const dummy = { val: 0, next: head };
  let groupPrev = dummy;

  while (true) {
    // 1. CHECK there are k nodes remaining — before touching anything
    let kth = groupPrev;
    for (let i = 0; i < k && kth; i++) kth = kth.next;
    if (!kth) break;                             // fewer than k → leave the rest alone

    const groupNext = kth.next;

    // 2. reverse the group, stopping at groupNext
    let prev = groupNext, cur = groupPrev.next;
    while (cur !== groupNext) {
      const nxt = cur.next;
      cur.next = prev;
      prev = cur;
      cur = nxt;
    }

    // 3. relink: groupPrev.next was the group's head, now its tail
    const newGroupPrev = groupPrev.next;
    groupPrev.next = kth;
    groupPrev = newGroupPrev;
  }
  return dummy.next;
}
// O(n) time, O(1) space
StepWhy it is required
Count k nodes firstA partial final group must be left untouched — reversing then undoing is wrong
prev = groupNextSeeds the reversal so the group's new tail links to the next group
Save groupPrev.next before relinkingAfter reversal it becomes the group's tail — the next groupPrev

Initialising prev = groupNext rather than null is the detail that makes this a single clean loop: the group's last node ends up pointing at the following group automatically, with no separate stitching step.

Part 5 — Composite Problems

Most "hard" linked-list problems are reversal plus one other technique. Recognising the composition is the whole difficulty.

function reorderList(head) {                     // LC 143: 1→2→3→4 becomes 1→4→2→3
  if (!head || !head.next) return;

  let slow = head, fast = head.next;             // 1. find the FIRST middle
  while (fast && fast.next) { slow = slow.next; fast = fast.next.next; }

  let second = slow.next;                        // 2. split
  slow.next = null;

  let prev = null;                               // 3. reverse the second half
  while (second) { const n = second.next; second.next = prev; prev = second; second = n; }

  let a = head, b = prev;                        // 4. interleave
  while (b) {
    const an = a.next, bn = b.next;
    a.next = b;
    if (an) b.next = an;
    a = an; b = bn;
  }
}

function swapPairs(head) {                       // LC 24
  const dummy = { val: 0, next: head };
  let prev = dummy;
  while (prev.next && prev.next.next) {
    const first = prev.next, second = first.next;
    first.next = second.next;
    second.next = first;
    prev.next = second;
    prev = first;                                // ← first is now the SECOND of the pair
  }
  return dummy.next;
}
ProblemComposition
Palindrome List (234)Middle + reverse + compare
Reorder List (143)Middle + reverse + interleave
Add Two Numbers II (445)Reverse both + add + reverse result (or use stacks)
Rotate List (61)Find length + close into a ring + cut
Sort List (148)Middle + split + merge sort
Swap Pairs (24)k-group with k = 2

Add Two Numbers II is worth noting because the intended solution avoids reversal entirely: push both lists onto stacks and pop, which gives least-significant-first order without mutating the inputs.

❌ Writing cur.next = prev before saving cur.next. The assignment overwrites the only reference to the remainder of the list, so the loop's next step reads a pointer that now points backwards — producing either an infinite loop (traversing 2 → 1 → 2 → 1 …) or a list truncated to a single node. The code looks symmetric and reasonable, and the failure appears only at runtime as a hang or a wrong-length result.

✅ Derive the order from the data dependencies instead of memorising it. Line 2 destroys what line 1 needs, so the save must come first; line 3 must follow line 2 or cur points at itself; line 4 consumes the value saved in line 1, so it goes last. Drawing three boxes and the arrows between them takes fifteen seconds and reconstructs the loop correctly every time — including for the sublist and k-group variants, where the same dependency reasoning applies to a longer sequence of splices.

Two debugging habits worth having, because linked-list bugs hang rather than throw:

function toArray(head, limit = 100) {            // cycle-safe printing
  const out = [];
  let p = head, n = 0;
  while (p && n++ < limit) { out.push(p.val); p = p.next; }
  if (p) out.push("...CYCLE?");
  return out;
}

function assertNoCycle(head) {                   // Floyd — see Fast & Slow Pointers
  let slow = head, fast = head;
  while (fast && fast.next) {
    slow = slow.next; fast = fast.next.next;
    if (slow === fast) throw new Error("cycle created by the reversal");
  }
}

Beginner: Reverse a linked list iteratively and explain the pointer order. 
function reverseList(head) {
  let prev = null, cur = head;
  while (cur) {
    const nxt = cur.next;      // 1. save
    cur.next = prev;           // 2. reverse
    prev = cur;                // 3. advance prev
    cur = nxt;                 // 4. advance cur
  }
  return prev;
}
// O(n) time, O(1) space

The order is forced by data dependencies, not convention:

LineMust come…Because
nxt = cur.nextFirstLine 2 overwrites the value it reads
cur.next = prevAfter the saveOtherwise the remainder is unreachable
prev = curAfter the reverseOtherwise cur.next points at itself
cur = nxtLastIt consumes the saved value
1 → 2 → 3 → null

start:  prev=null  cur=1
iter1:  nxt=2, 1.next=null, prev=1, cur=2      null ← 1     2 → 3
iter2:  nxt=3, 2.next=1,    prev=2, cur=3      null ← 1 ← 2     3
iter3:  nxt=null, 3.next=2, prev=3, cur=null   null ← 1 ← 2 ← 3
return prev = 3  ✓

Return prev, not cur — the loop exits with cur null, and prev holds the last node processed, which is the original tail and therefore the new head.

Edge cases need no special handling: an empty list skips the loop and returns null; a single node runs once and sets 1.next = null, which it already was.

The recursive alternative is O(n) stack space, so I would mention it and then note that it fails the O(1)-space requirement and risks stack overflow on a list of 10⁵ nodes.

Beginner: What is a dummy node and when do you need one?

A dummy (sentinel) node is a throwaway node placed before the real head, so that every real node has a predecessor. It removes the "what if this is the head?" branch from list-modifying code.

const dummy = { val: 0, next: head };
// ... modify freely, treating dummy as the node before the head ...
return dummy.next;                               // NOT head

Without it, deleting the head needs its own branch:

// no dummy — two code paths
function removeElements(head, val) {
  while (head && head.val === val) head = head.next;      // special case for the head
  let cur = head;
  while (cur && cur.next) {
    if (cur.next.val === val) cur.next = cur.next.next;
    else cur = cur.next;
  }
  return head;
}

// with dummy — one code path
function removeElements(head, val) {
  const dummy = { val: 0, next: head };
  let cur = dummy;
  while (cur.next) {
    if (cur.next.val === val) cur.next = cur.next.next;
    else cur = cur.next;
  }
  return dummy.next;
}
SituationWhy a dummy helps
Head might be deletedDeletion requires a predecessor
Head might changeReversal, partition, k-group
Building a new listNo "is this the first node?" check
Merging two sorted listsThe first node can come from either

The critical rule is returning dummy.next rather than head. If the original head was removed or displaced, head now points into the middle of the list or at a detached node — a bug that passes tests where the head happens to survive.

The cost is one allocation, which is negligible against the elimination of an entire class of edge-case bugs.

Mid: Reverse a sublist between positions m and n in one pass.

Walk to the node before position m, then repeatedly pull the node after start to the front of the section.

function reverseBetween(head, m, n) {
  const dummy = { val: 0, next: head };
  let prev = dummy;
  for (let i = 1; i < m; i++) prev = prev.next;

  const start = prev.next;
  for (let i = 0; i < n - m; i++) {
    const moved = start.next;
    start.next = moved.next;                     // unlink moved
    moved.next = prev.next;                      // put it at the section's front
    prev.next = moved;
  }
  return dummy.next;
}
// O(n) time, O(1) space, one pass

1 → 2 → 3 → 4 → 5,  m=2, n=4      prev=1, start=2

i=0: moved=3   1 → 3 → 2 → 4 → 5
i=1: moved=4   1 → 4 → 3 → 2 → 5
→ [1,4,3,2,5]  ✓

start never moves, and that is the elegant part. It begins as the section's first node and ends as its last, drifting backwards relative to everything else as nodes are pulled in front of it — without its own pointer ever being reassigned.

The three splice lines must be in this order, for the same dependency reason as the basic reversal: start.next = moved.next reads moved.next before moved.next = prev.next overwrites it.

The dummy handles m = 1, where the section includes the head. Without it, reversing from position 1 changes the head and needs a separate branch — exactly the case that gets missed.

The alternative two-pass approach — detach the sublist, reverse it with the standard loop, reattach — is easier to explain but requires keeping four boundary pointers straight, and it is more error-prone in practice despite looking simpler.

Mid: Determine whether a linked list is a palindrome in O(1) space.

Find the middle, reverse the second half, compare the halves — three techniques composed.

function isPalindrome(head) {
  if (!head || !head.next) return true;

  let slow = head, fast = head;                  // 1. middle
  while (fast && fast.next) { slow = slow.next; fast = fast.next.next; }

  let prev = null, cur = slow;                   // 2. reverse from the middle
  while (cur) { const n = cur.next; cur.next = prev; prev = cur; cur = n; }

  let a = head, b = prev;                        // 3. compare
  while (b) { if (a.val !== b.val) return false; a = a.next; b = b.next; }
  return true;
}
// O(n) time, O(1) space

The comparison loop must be driven by b, not a. On odd lengths the reversed half is shorter by one:

[1,2,3,2,1]:  slow stops at 3
  reversed second half: 1 → 2 → 3   (3 nodes)
  first half from head: 1 → 2 → 3 → 2 → 1  (untruncated)

looping on b: compares (1,1), (2,2), (3,3) → correct
looping on a: runs past the end of b → null dereference

The first half is deliberately not truncated, which is safe because b controls the loop — but it is why the direction matters.

A production version would restore the list, since mutating a caller's data structure is a genuine side effect:

const secondHalf = reverse(slow);
let ok = compare(head, secondHalf);
reverse(secondHalf);                             // put it back
return ok;

The O(n)-space alternative — copy values into an array and check with two pointers — is simpler and perfectly acceptable unless O(1) space is required. I would state it first, then give this when asked to improve the space.

Senior: Reverse nodes in k-group, leaving a trailing partial group unchanged.

The requirement that a final group of fewer than k nodes stays untouched is what makes this hard: you must know the group is complete before reversing it.

function reverseKGroup(head, k) {
  const dummy = { val: 0, next: head };
  let groupPrev = dummy;

  while (true) {
    let kth = groupPrev;                         // 1. verify k nodes exist
    for (let i = 0; i < k && kth; i++) kth = kth.next;
    if (!kth) break;

    const groupNext = kth.next;

    let prev = groupNext, cur = groupPrev.next;  // 2. reverse, seeded with groupNext
    while (cur !== groupNext) {
      const nxt = cur.next;
      cur.next = prev;
      prev = cur;
      cur = nxt;
    }

    const newGroupPrev = groupPrev.next;         // 3. the old head is the new tail
    groupPrev.next = kth;
    groupPrev = newGroupPrev;
  }
  return dummy.next;
}
// O(n) time, O(1) space

Three decisions carry the solution:

1. Count before reversing. Reversing first and undoing on a short group is both slower and much harder to get right. Walking k steps costs O(k) and the total stays O(n) because each node is counted once per group it belongs to.

2. prev = groupNext, not null. Seeding the reversal with the following group means the group's new tail already points to the right place — no separate stitching pass.

with prev = null:      2 → 1 → null    ✗ the rest of the list is orphaned
with prev = groupNext: 2 → 1 → 3...    ✓

3. Save groupPrev.next before relinking. After reversal that node is the group's tail, which is exactly the groupPrev for the next iteration — and groupPrev.next = kth overwrites the pointer to it.

1 → 2 → 3 → 4 → 5, k = 2

group 1: kth=2, groupNext=3 → reverse → 2 → 1 → 3
         groupPrev.next was 1; 1 is now the tail → groupPrev = 1
group 2: kth=4, groupNext=5 → reverse → 4 → 3 → 5
group 3: only node 5 remains → kth becomes null → break

→ [2,1,4,3,5]  ✓

The recursive formulation is shorter — reverse the first k, recurse on the rest, link — but it is O(n/k) stack depth, which violates a strict O(1)-space requirement and can overflow for small k on a long list.

Senior: Reorder a list so it reads first, last, second, second-last, and so on.

Three composed techniques: find the middle, reverse the second half, interleave. Each is straightforward; the difficulty is the boundary conditions between them.

function reorderList(head) {
  if (!head || !head.next) return;

  let slow = head, fast = head.next;              // FIRST middle
  while (fast && fast.next) { slow = slow.next; fast = fast.next.next; }

  let second = slow.next;
  slow.next = null;                               // SEVER — essential

  let prev = null;
  while (second) { const n = second.next; second.next = prev; prev = second; second = n; }

  let a = head, b = prev;
  while (b) {
    const an = a.next, bn = b.next;
    a.next = b;
    if (an) b.next = an;
    a = an; b = bn;
  }
}
// O(n) time, O(1) space

Two details decide whether this works:

1. fast = head.next gives the FIRST middle. With fast = head on an even-length list, slow lands in the right half and the split is uneven:

[1,2,3,4]  with fast = head.next:  slow=2 → halves [1,2] and [3,4]   ✓
           with fast = head:       slow=3 → halves [1,2,3] and [4]   ✗

2. slow.next = null severs the halves. Without it, reversing the second half walks back into the first and creates a cycle — the failure appears as a hang, not an exception.

[1,2,3,4]:  halves [1,2] and [3,4] → reversed [4,3]

interleave: 1 → 4 → 2 → 3
  a=1,b=4: an=2, bn=3 → 1.next=4, 4.next=2
  a=2,b=3: an=null, bn=null → 2.next=3, (an null, skip)
→ [1,4,2,3]  ✓

The if (an) guard handles odd lengths, where the second half is shorter and the last node of the first half has nothing left to link to.

The O(n)-space alternative is to collect nodes into an array and re-link by index — far easier to write and reason about. I would mention it as the straightforward solution and present this as the O(1)-space version, noting that in production code the array approach is usually preferable for readability unless memory is genuinely constrained.

function reverseBetween(head, m, n) {
  const dummy = { val: 0, next: head };
  let prev = dummy;
  for (let i = 1; i < m; i++) prev = prev.next;
  const start = prev.next;
  for (let i = 0; i < n - m; i++) {
    const moved = start.next;
    start.next = moved.next;
    moved.next = prev.next;
    prev.next = moved;
  }
  return dummy.next;
}

function referenceReverse(vs, m, n) {            // array-based reference
  const a = [...vs];
  const seg = a.slice(m-1, n).reverse();
  return [...a.slice(0, m-1), ...seg, ...a.slice(n)];
}

function reverseKGroup(head, k) {
  const dummy = { val: 0, next: head };
  let groupPrev = dummy;
  while (true) {
    let kth = groupPrev;
    for (let i = 0; i < k && kth; i++) kth = kth.next;
    if (!kth) break;
    const groupNext = kth.next;
    let prev = groupNext, cur = groupPrev.next;
    while (cur !== groupNext) { const n = cur.next; cur.next = prev; prev = cur; cur = n; }
    const ngp = groupPrev.next;
    groupPrev.next = kth;
    groupPrev = ngp;
  }
  return dummy.next;
}

function referenceKGroup(vs, k) {
  const out = [];
  for (let i = 0; i + k <= vs.length; i += k) out.push(...vs.slice(i, i+k).reverse());
  const rem = vs.length % k;
  if (rem) out.push(...vs.slice(vs.length - rem));
  return out;
}

function reorderList(head) {
  if (!head || !head.next) return;
  let slow = head, fast = head.next;
  while (fast && fast.next) { slow = slow.next; fast = fast.next.next; }
  let second = slow.next;
  slow.next = null;
  let prev = null;
  while (second) { const n = second.next; second.next = prev; prev = second; second = n; }
  let a = head, b = prev;
  while (b) { const an = a.next, bn = b.next; a.next = b; if (an) b.next = an; a = an; b = bn; }
}

function isPalindrome(head) {
  if (!head || !head.next) return true;
  let slow = head, fast = head;
  while (fast && fast.next) { slow = slow.next; fast = fast.next.next; }
  let prev = null, cur = slow;
  while (cur) { const n = cur.next; cur.next = prev; prev = cur; cur = n; }
  let a = head, b = prev;
  while (b) { if (a.val !== b.val) return false; a = a.next; b = b.next; }
  return true;
}

function addTwoNumbersII(l1, l2) {               // LC 445 — stacks, no mutation
  const s1 = [], s2 = [];
  for (let p = l1; p; p = p.next) s1.push(p.val);
  for (let p = l2; p; p = p.next) s2.push(p.val);
  let carry = 0, head = null;
  while (s1.length || s2.length || carry) {
    const sum = (s1.pop() ?? 0) + (s2.pop() ?? 0) + carry;
    carry = sum >= 10 ? 1 : 0;
    head = { val: sum % 10, next: head };        // prepend — builds in the right order
  }
  return head;
}

6 (hard): Build a structural-integrity checker for list mutations.
Solution

Linked-list bugs hang or silently truncate rather than throwing. This harness catches all three failure modes — cycles, lost nodes, and duplicated nodes — automatically:

function snapshot(head) {
  const nodes = new Set();
  const vals = [];
  let p = head, guard = 0;
  while (p) {
    if (nodes.has(p)) throw new Error("cycle detected during snapshot");
    if (guard++ > 1e6) throw new Error("runaway traversal");
    nodes.add(p);
    vals.push(p.val);
    p = p.next;
  }
  return { nodes, vals };
}

function checkMutation(buildFn, mutateFn, label) {
  const head = buildFn();
  const before = snapshot(head);

  let after;
  try {
    const result = mutateFn(head);
    after = snapshot(result === undefined ? head : result);
  } catch (e) {
    console.log(`${label.padEnd(20)} ✗ ${e.message}`);
    return false;
  }

  const lost = [...before.nodes].filter(n => !after.nodes.has(n));
  const gained = [...after.nodes].filter(n => !before.nodes.has(n));
  const sameMultiset =
    [...before.vals].sort().join() === [...after.vals].sort().join();

  const ok = lost.length === 0 && gained.length === 0 && sameMultiset;
  console.log(`${label.padEnd(20)} ${ok ? "✓" : "✗"} ` +
    `nodes=${after.nodes.size}/${before.nodes.size} ` +
    `lost=${lost.length} gained=${gained.length} ` +
    `multiset=${sameMultiset ? "same" : "CHANGED"}`);
  return ok;
}

🎯 Key Takeaways

  • The three-pointer loop is save, reverse, advance prev, advance cur — and that order is forced by data dependencies, not convention.
  • Return prev, not cur: the loop exits with cur null and prev holding the new head.
  • Reversing before saving cur.next destroys the rest of the list — the single most common linked-list bug.
  • The recursive version is O(n) stack and overflows around 10⁵ nodes; it also needs head.next = null or it creates a two-node cycle.
  • A dummy node gives every real node a predecessor, eliminating the "what if it's the head" branch entirely.
  • With a dummy, always return dummy.next — head may have been removed or displaced.
  • In sublist reversal, start is never reassigned: it begins as the section's head and ends as its tail while others are pulled in front of it.
  • k-group reversal must count k nodes before mutating, or a trailing partial group gets reversed when it should be left alone.
  • Seed the k-group reversal with prev = groupNext, not null, so the group's new tail links onward automatically.
  • Save groupPrev.next before relinking — after reversal it is the group's tail and the next iteration's groupPrev.
  • Composite problems dominate this pattern: palindrome, reorder and sort are all middle-finding plus reversal plus one more step.
  • Use fast = head.next for the first middle when splitting, or the halves come out unequal.
  • Sever the halves with slow.next = null before reversing, or the reversal walks back into the first half and creates a cycle.
  • Add Two Numbers II is better solved with two stacks than by reversing, because it leaves the inputs unmutated.
  • Building a result by prepending (head = {val, next: head}) produces reversed order without a second pass.
  • Linked-list bugs hang or truncate rather than throwing — keep a cycle-safe printer and a Floyd assertion in the test harness.
  • Structural checks (no lost nodes, no cycles, same multiset) catch most bugs but never catch wrong order — a reference comparison is still required.
