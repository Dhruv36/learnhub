Topological Sort Trees & Graphs

What you'll master: what a topological order is and the exact condition under which one exists; Kahn's algorithm and why its queue-emptying behaviour is cycle detection rather than needing a separate check; the DFS formulation and why reversed finishing order produces a valid ordering; how "can these courses be completed" and "what build order works" are the same question; the level-by-level variant that answers "how many rounds" — the key to Course Schedule III-style and parallel-execution problems; and the harder applications, Alien Dictionary and Sequence Reconstruction, where building the graph correctly is most of the work. Prerequisites: BFS / DFS, Hashing.

Part 1 — What It Is and When It Exists

A topological order is a linear arrangement of a directed graph's vertices such that every edge points forward: if there is an edge u → v, then u appears before v.

    A → B → D              valid orders:  A B C D E
    ↓       ↑                             A C B D E
    C ──────┘                             (both respect every edge)
        ↘
          E

    every edge goes LEFT to RIGHT in the output
🔑 A topological order exists if and only if the graph is a DAG — directed and acyclic. The reason is immediate once stated: if a cycle a → b → c → a existed, then a must come before b, b before c, and c before a, which is impossible in a linear order. This is why every topological sort algorithm doubles as a cycle detector, and why "can you finish all courses" and "sort the courses" are literally the same computation with a different return value.
PropertyConsequence
Requires a DAGAny cycle makes ordering impossible
Usually not uniqueIndependent nodes can appear in any relative order
Unique iff a Hamiltonian path existsEvery consecutive pair must have an edge
O(V + E)Both algorithms are linear

Non-uniqueness matters for testing — a correct solution may not match the expected output string for string, so verification must check the ordering property rather than compare to one answer.

Part 2 — Kahn's Algorithm

The BFS formulation: repeatedly take a node with no remaining prerequisites, output it, and remove its outgoing edges.

function topoSortKahn(n, edges) {                // edges: [from, to]
  const adj = Array.from({length: n}, () => []);
  const indeg = new Array(n).fill(0);
  for (const [u, v] of edges) { adj[u].push(v); indeg[v]++; }

  const queue = [];
  for (let i = 0; i < n; i++) if (indeg[i] === 0) queue.push(i);

  const order = [];
  let head = 0;
  while (head < queue.length) {
    const node = queue[head++];
    order.push(node);
    for (const nb of adj[node]) {
      if (--indeg[nb] === 0) queue.push(nb);     // ← its last prerequisite is gone
    }
  }
  return order.length === n ? order : [];        // ← short output means a CYCLE
}
// O(V + E) time, O(V + E) space

indegree = number of unmet prerequisites

    A(0) → B(1) → D(2)
    ↓             ↑
    C(1) ─────────┘

start: queue = [A]
pop A → B:1→0 (push), C:1→0 (push)     order = [A]
pop B → D:2→1                          order = [A,B]
pop C → D:1→0 (push)                   order = [A,B,C]
pop D                                  order = [A,B,C,D]  ✓ all 4 emitted

The cycle check is free. Nodes in a cycle never reach indegree 0 — each is waiting on another member of the cycle — so they are never enqueued. If the output is shorter than n, exactly the nodes in or downstream of a cycle are missing.

ResultMeaning
order.length === nValid DAG; order is a topological sort
order.length < nCycle; the missing nodes are in or after it

Course Schedule (LC 207) is this function with a boolean return:

function canFinish(numCourses, prerequisites) {
  // prerequisites[i] = [course, prereq] → edge prereq → course
  const edges = prerequisites.map(([c, p]) => [p, c]);
  return topoSortKahn(numCourses, edges).length === numCourses;
}

Edge direction is the single most common bug here. LeetCode gives [course, prerequisite], which means the prerequisite must come first — so the edge runs prereq → course, not the order the pair is written in.

Part 3 — The DFS Formulation

Run DFS; when a node finishes (all descendants explored), prepend it to the output. The reversed finishing order is a valid topological sort.

function topoSortDFS(n, edges) {
  const adj = Array.from({length: n}, () => []);
  for (const [u, v] of edges) adj[u].push(v);

  const color = new Array(n).fill(0);            // 0=white 1=gray 2=black
  const order = [];
  let hasCycle = false;

  const dfs = node => {
    color[node] = 1;                             // GRAY: on the current path
    for (const nb of adj[node]) {
      if (color[nb] === 1) { hasCycle = true; return; }   // back edge
      if (color[nb] === 0) { dfs(nb); if (hasCycle) return; }
    }
    color[node] = 2;
    order.push(node);                            // ← finished: everything after me is placed
  };

  for (let i = 0; i < n && !hasCycle; i++) if (color[i] === 0) dfs(i);
  return hasCycle ? [] : order.reverse();        // ← REVERSE the finishing order
}

Why reversing works: a node is appended only after every node it points to has already been appended. So in the raw finishing order, every node appears after its successors — reversing puts it before them, which is exactly the topological property.

The three-colour marking is the same machinery as directed cycle detection, and for the same reason: a GRAY node means a back edge, while BLACK means a converging path, which is normal in a DAG.

Kahn (BFS)DFS
Cycle detectionOutput length < nReaching a GRAY node
Which nodes are in the cycleDirectly visible (the missing ones)Needs extra bookkeeping
Level informationNaturalNot available
Lexicographically smallest orderUse a min-heap instead of a queueAwkward
Stack overflow riskNoneDeep graphs

Kahn's is the better default for interviews — the cycle check is free, it is iterative, and it extends naturally to the level-counting variant below.

Part 4 — Level-by-Level: Counting Rounds

When the question is "how many semesters" or "how many parallel rounds", process an entire indegree-0 frontier at a time — the same level trick as BFS.

function minimumSemesters(n, relations) {        // LC 1136
  const adj = Array.from({length: n + 1}, () => []);
  const indeg = new Array(n + 1).fill(0);
  for (const [a, b] of relations) { adj[a].push(b); indeg[b]++; }

  let frontier = [];
  for (let i = 1; i <= n; i++) if (indeg[i] === 0) frontier.push(i);

  let studied = 0, semesters = 0;
  while (frontier.length) {
    const next = [];
    for (const course of frontier) {             // ← everything in this level runs in parallel
      studied++;
      for (const nb of adj[course]) if (--indeg[nb] === 0) next.push(nb);
    }
    frontier = next;
    semesters++;
  }
  return studied === n ? semesters : -1;         // -1 → cycle
}

Each level is one round, because everything with no remaining prerequisites can be done simultaneously. The number of levels is the length of the longest path in the DAG — the critical path.

The lexicographically smallest order replaces the queue with a min-heap, which is a genuinely different requirement:

function topoSortSmallest(n, edges) {            // needs a MinHeap — see Heaps lesson
  const adj = Array.from({length: n}, () => []);
  const indeg = new Array(n).fill(0);
  for (const [u, v] of edges) { adj[u].push(v); indeg[v]++; }

  const heap = new MinHeap();
  for (let i = 0; i < n; i++) if (indeg[i] === 0) heap.push(i);

  const order = [];
  while (heap.size()) {
    const node = heap.pop();                     // ← smallest available, not oldest
    order.push(node);
    for (const nb of adj[node]) if (--indeg[nb] === 0) heap.push(nb);
  }
  return order.length === n ? order : [];
}
// O(V log V + E)

Part 5 — Building the Graph Is the Hard Part

In the harder problems, the algorithm is standard and the difficulty is deriving the edges. Alien Dictionary is the canonical example.

function alienOrder(words) {                     // LC 269
  const adj = new Map(), indeg = new Map();
  for (const w of words) for (const c of w) {
    if (!adj.has(c)) { adj.set(c, new Set()); indeg.set(c, 0); }
  }

  for (let i = 0; i < words.length - 1; i++) {
    const a = words[i], b = words[i + 1];
    if (a.length > b.length && a.startsWith(b)) return "";   // ← "abc" before "ab" is INVALID

    for (let j = 0; j < Math.min(a.length, b.length); j++) {
      if (a[j] !== b[j]) {
        if (!adj.get(a[j]).has(b[j])) {
          adj.get(a[j]).add(b[j]);
          indeg.set(b[j], indeg.get(b[j]) + 1);
        }
        break;                                    // ← ONLY the first difference matters
      }
    }
  }

  const queue = [...indeg.keys()].filter(c => indeg.get(c) === 0);
  const out = [];
  let head = 0;
  while (head < queue.length) {
    const c = queue[head++];
    out.push(c);
    for (const nb of adj.get(c)) if (indeg.set(nb, indeg.get(nb) - 1).get(nb) === 0) queue.push(nb);
  }
  return out.length === indeg.size ? out.join("") : "";
}

Three subtleties, each of which fails a test case:

SubtletyWhy
break after the first differenceLater characters carry no ordering information
The prefix check["abc","ab"] is impossible in any valid ordering
Deduplicate edgesAdding the same edge twice inflates the indegree and fakes a cycle

Only adjacent word pairs give information, and only up to their first differing character — comparing every pair or every position produces edges that do not follow from the dictionary.

Uniqueness has a clean test: the order is unique exactly when, at every step of Kahn's algorithm, the queue contains exactly one node. Two available nodes means two valid orders.

DAG shortest/longest paths are worth knowing as a bonus: once nodes are in topological order, a single pass computes them, because every predecessor is finalised before a node is processed — no heap needed even with negative weights.

❌ Reversing the edge direction when reading the input. LeetCode gives prerequisites[i] = [course, prereq], which reads naturally as "course, then prereq" — so the edge gets added as course → prereq. The algorithm then runs perfectly on a graph that encodes the opposite dependency, and returns a completely valid topological order of the reversed graph. Nothing crashes; the cycle check still passes; the answer is simply backwards, and on symmetric test cases it may even look right.

✅ Say the dependency aloud before writing the edge. "To take course, you must first take prereq" means prereq comes earlier, so the edge points prereq → course and the indegree belongs to course. Then sanity-check with a two-node example: with [[1,0]] the answer must start with 0. That one check catches the reversal immediately, and it costs five seconds.

Interview Questions

Beginner: What is a topological sort and when does one exist?

It is a linear ordering of a directed graph's vertices in which every edge points forward — if u → v exists, u appears before v.

    A → B → D          valid: A B C D E
    ↓       ↑                 A C B D E
    C ──────┘
        ↘ E             every edge points left→right in the output

One exists if and only if the graph is a DAG. The proof is one sentence: a cycle a → b → c → a would require a before b, b before c, and c before a — impossible in a linear order. Conversely, any acyclic directed graph always has at least one node with no incoming edges, which can be placed first, and induction does the rest.

Orders are usually not unique. Nodes with no dependency relationship can appear in either order, so a problem asking for "a valid order" has many correct answers — which matters when testing, because comparing against one expected string will produce false failures.

uniqueness test: the order is unique iff, at every step of Kahn's algorithm,
                 exactly one node has indegree 0

The practical framing is dependency resolution: build systems ordering compilation units, package managers installing dependencies, spreadsheets recomputing cells, task schedulers. In all of them, a cycle is a real error condition and the algorithm detecting it is the same one producing the order.

Both standard algorithms — Kahn's BFS and the DFS finishing-order method — run in O(V + E).

Beginner: Determine whether all courses can be finished given a prerequisite list.

The question is exactly "is this graph a DAG", so run a topological sort and check whether every node was emitted.

function canFinish(numCourses, prerequisites) {
  const adj = Array.from({length: numCourses}, () => []);
  const indeg = new Array(numCourses).fill(0);

  for (const [course, prereq] of prerequisites) {
    adj[prereq].push(course);                    // ← prereq comes FIRST
    indeg[course]++;
  }

  const queue = [];
  for (let i = 0; i < numCourses; i++) if (indeg[i] === 0) queue.push(i);

  let done = 0, head = 0;
  while (head < queue.length) {
    const c = queue[head++];
    done++;
    for (const nb of adj[c]) if (--indeg[nb] === 0) queue.push(nb);
  }
  return done === numCourses;
}
// O(V + E)

The edge direction is the trap. The input pair is [course, prereq], but the dependency runs the other way: to take course you must first take prereq, so the edge is prereq → course and the indegree belongs to course.

sanity check: prerequisites = [[1,0]] means "take 0 before 1"
              → a valid order must start with 0

Why the count detects cycles: every node in a cycle is waiting on another node in that same cycle, so none of them ever reaches indegree 0 and none is ever enqueued. The nodes that never get emitted are precisely those in or downstream of a cycle.

[[1,0],[0,1]]:  indeg[0]=1, indeg[1]=1  → queue starts EMPTY → done=0 ≠ 2 → false ✓

Course Schedule II (LC 210) is the same function returning the order instead of a boolean — which is a good illustration that "can it be done" and "how" are one computation.

Mid: Explain Kahn's algorithm and compare it with the DFS approach.

Kahn's repeatedly emits a node whose prerequisites are all satisfied:

1. compute indegree for every node
2. enqueue all nodes with indegree 0
3. pop a node, output it, decrement each neighbour's indegree
4. a neighbour hitting 0 is enqueued
5. if fewer than n nodes were output → cycle

DFS instead uses finishing times:

1. DFS from every unvisited node with three-colour marking
2. append a node to the output when it FINISHES (all descendants done)
3. reaching a GRAY node → cycle
4. reverse the finishing order

Reversing works because a node finishes only after everything it points to has finished — so in raw finishing order every node comes after its successors, and reversal puts it before them.

KahnDFS
Cycle detectionFree — count the outputGRAY node check
Identifies cycle membersYes — the missing nodesExtra bookkeeping
Level / round countingNaturalNot available
Lexicographically smallestSwap the queue for a min-heapAwkward
Recursion depthIterative — safeOverflows on deep graphs

I would default to Kahn's in an interview. The cycle check requires no extra code, it is iterative so there is no stack-overflow discussion, and the two most common follow-ups — "how many semesters?" and "give me the lexicographically smallest order" — are one-line modifications.

DFS is preferable when the topological sort is a sub-step of a larger DFS-based algorithm — Tarjan's strongly-connected-components, for instance, or when you also need entry/exit times.

Both are O(V + E): each node is processed once and each edge relaxed once.

Mid: Find the minimum number of semesters to complete all courses.

Courses with no outstanding prerequisites can all be taken simultaneously, so this is level-by-level Kahn's — the number of levels is the answer.

function minimumSemesters(n, relations) {
  const adj = Array.from({length: n + 1}, () => []);
  const indeg = new Array(n + 1).fill(0);
  for (const [a, b] of relations) { adj[a].push(b); indeg[b]++; }

  let frontier = [];
  for (let i = 1; i <= n; i++) if (indeg[i] === 0) frontier.push(i);

  let studied = 0, semesters = 0;
  while (frontier.length) {
    const next = [];
    for (const c of frontier) {
      studied++;
      for (const nb of adj[c]) if (--indeg[nb] === 0) next.push(nb);
    }
    frontier = next;
    semesters++;
  }
  return studied === n ? semesters : -1;
}
// O(V + E)

n = 3, relations = [[1,3],[2,3]]

level 1: {1, 2}  → both have no prerequisites, taken together
level 2: {3}     → now unlocked
answer: 2 semesters (not 3 courses)

The answer is the longest path in the DAG, also called the critical path — because the number of levels is determined by the longest dependency chain, not by the total number of nodes.

Counting nodes instead of levels is the mistake: that gives the sequential time, which answers a different question.

The studied === n check is still required. A cycle causes the frontier to empty early, and without the check the function would report a plausible small number instead of −1.

The natural extension is a capacity limit — at most k courses per semester — and it is worth flagging that this becomes much harder: greedily taking any k available courses is not optimal, and the general problem is NP-hard. If asked, I would note that and propose a heuristic (prioritise courses on the critical path) rather than claim an exact polynomial solution.

With per-task durations, the same topological order supports a one-pass DP: finish[v] = max(finish[u] + dur[v]) over predecessors u — which is DAG longest-path and the basis of project scheduling.

Senior: Derive the alphabet order of an alien language from a sorted dictionary.

The algorithm is a standard topological sort; the work is extracting the edges correctly.

function alienOrder(words) {
  const adj = new Map(), indeg = new Map();
  for (const w of words) for (const c of w)
    if (!adj.has(c)) { adj.set(c, new Set()); indeg.set(c, 0); }

  for (let i = 0; i < words.length - 1; i++) {
    const a = words[i], b = words[i + 1];
    if (a.length > b.length && a.startsWith(b)) return "";   // invalid input

    for (let j = 0; j < Math.min(a.length, b.length); j++) {
      if (a[j] !== b[j]) {
        if (!adj.get(a[j]).has(b[j])) {
          adj.get(a[j]).add(b[j]);
          indeg.set(b[j], indeg.get(b[j]) + 1);
        }
        break;                                    // only the FIRST difference informs
      }
    }
  }

  const queue = [...indeg.keys()].filter(c => indeg.get(c) === 0);
  const out = [];
  let head = 0;
  while (head < queue.length) {
    const c = queue[head++];
    out.push(c);
    for (const nb of adj.get(c)) {
      indeg.set(nb, indeg.get(nb) - 1);
      if (indeg.get(nb) === 0) queue.push(nb);
    }
  }
  return out.length === indeg.size ? out.join("") : "";
}

Three details, each of which is a distinct failing test case:

1. Only adjacent pairs, only the first difference. From ["wrt","wrf"] the only deduction is t < f. The characters after the first difference tell you nothing, and comparing non-adjacent words adds edges that do not follow from the dictionary.

2. The prefix check. ["abc","ab"] cannot occur in any valid ordering — a prefix always sorts before the longer word — so it is invalid input rather than a cycle, and returns "".

3. Deduplicate edges. If t → f appears in two word pairs and both increment the indegree, f never reaches 0 and a false cycle is reported. The Set membership check prevents it.

["wrt","wrf","er","ett","rftt"]

wrt/wrf → t < f
wrf/er  → w < e
er/ett  → r < t
ett/rftt→ e < r

order: w → e → r → t → f  = "wertf"  ✓

Characters never constrained still belong in the output, in any position — which is why every character of every word is registered up front rather than only those appearing in an edge.

Ambiguity is worth mentioning: if the queue ever holds more than one character, several valid alphabets exist and the problem accepts any of them. A follow-up asking for a unique answer would require checking that condition.

Senior: Determine whether a sequence is the unique shortest supersequence of given subsequences.

Sequence Reconstruction (LC 444) asks whether nums is the only valid topological order of the graph implied by the sequences — which turns the uniqueness property into the whole problem.

function sequenceReconstruction(nums, sequences) {
  const n = nums.length;
  const adj = Array.from({length: n + 1}, () => new Set());
  const indeg = new Array(n + 1).fill(0);
  const seen = new Set();

  for (const seq of sequences) {
    for (const v of seq) {
      if (v < 1 || v > n) return false;           // out of range
      seen.add(v);
    }
    for (let i = 0; i + 1 < seq.length; i++) {
      const [u, v] = [seq[i], seq[i+1]];
      if (!adj[u].has(v)) { adj[u].add(v); indeg[v]++; }   // dedupe
    }
  }
  if (seen.size !== n) return false;              // some value never appears

  const queue = [];
  for (let i = 1; i <= n; i++) if (indeg[i] === 0) queue.push(i);

  let head = 0, idx = 0;
  while (head < queue.length) {
    if (queue.length - head > 1) return false;    // ← TWO choices ⟹ not unique
    const node = queue[head++];
    if (node !== nums[idx++]) return false;       // ← must match nums exactly
    for (const nb of adj[node]) if (--indeg[nb] === 0) queue.push(nb);
  }
  return idx === n;
}
// O(V + E)

The uniqueness test is the key insight: at every step, if more than one node has indegree 0, then at least two different topological orders exist, so the reconstruction is not unique and the answer is false.

nums = [1,2,3], sequences = [[1,2],[1,3]]

edges: 1→2, 1→3
step 1: queue = [1]        → ok, matches nums[0]
step 2: queue = [2,3]      → TWO available ⟹ both [1,2,3] and [1,3,2] are valid ⟹ false ✓

nums = [1,2,3], sequences = [[1,2],[1,3],[2,3]]

edges: 1→2, 1→3, 2→3
step 1: queue=[1]   step 2: queue=[2]   step 3: queue=[3]   → always one choice ⟹ true ✓

Three validation checks beyond the algorithm, and each corresponds to a real failing case: values outside 1..n, values that never appear in any sequence, and the final idx === n which catches a cycle causing early termination.

Edge deduplication matters here too — the same pair can appear in several sequences, and double-counting the indegree makes a node unreachable, producing a false negative.

The general lesson is that "is the topological order unique?" has a clean operational answer — the queue never holds two nodes — and that turns an apparently hard uniqueness question into a one-line check inside the standard algorithm.

Solution 
function topoKahn(n, edges) {
  const adj = Array.from({length:n}, () => []);
  const indeg = new Array(n).fill(0);
  for (const [u,v] of edges) { adj[u].push(v); indeg[v]++; }
  const q = [];
  for (let i = 0; i < n; i++) if (indeg[i] === 0) q.push(i);
  const out = [];
  let head = 0;
  while (head < q.length) {
    const x = q[head++];
    out.push(x);
    for (const nb of adj[x]) if (--indeg[nb] === 0) q.push(nb);
  }
  return out.length === n ? out : [];
}

function topoDFS(n, edges) {
  const adj = Array.from({length:n}, () => []);
  for (const [u,v] of edges) adj[u].push(v);
  const color = new Array(n).fill(0);
  const out = [];
  let cyc = false;
  const dfs = x => {
    color[x] = 1;
    for (const nb of adj[x]) {
      if (color[nb] === 1) { cyc = true; return; }
      if (color[nb] === 0) { dfs(nb); if (cyc) return; }
    }
    color[x] = 2;
    out.push(x);
  };
  for (let i = 0; i < n && !cyc; i++) if (color[i] === 0) dfs(i);
  return cyc ? [] : out.reverse();
}

function isValidTopoOrder(n, edges, order) {
  if (order.length !== n) return false;
  const pos = new Array(n);
  order.forEach((v, i) => pos[v] = i);
  return edges.every(([u,v]) => pos[u] < pos[v]);   // every edge points forward
}

Randomised verification on DAGs and cyclic graphs:

function randomDAG(n, p) {
  const edges = [];
  const perm = Array.from({length:n}, (_, i) => i);
  for (let i = n-1; i > 0; i--) { const j = Math.floor(Math.random()*(i+1)); [perm[i],perm[j]]=[perm[j],perm[i]]; }
  for (let i = 0; i < n; i++)
    for (let j = i+1; j < n; j++)
      if (Math.random() < p) edges.push([perm[i], perm[j]]);   // always forward in perm ⟹ acyclic
  return edges;
}

function minimumSemesters(n, relations) {
  const adj = Array.from({length:n+1}, () => []);
  const indeg = new Array(n+1).fill(0);
  for (const [a,b] of relations) { adj[a].push(b); indeg[b]++; }

  let frontier = [];
  for (let i = 1; i <= n; i++) if (indeg[i] === 0) frontier.push(i);

  let studied = 0, sem = 0;
  while (frontier.length) {
    const next = [];
    for (const c of frontier) {
      studied++;
      for (const nb of adj[c]) if (--indeg[nb] === 0) next.push(nb);
    }
    frontier = next; sem++;
  }
  return studied === n ? sem : -1;
}

function allTopoOrders(n, edges) {
  const adj = Array.from({length:n}, () => []);
  const indeg = new Array(n).fill(0);
  for (const [u,v] of edges) { adj[u].push(v); indeg[v]++; }
  const res = [], cur = [], used = new Array(n).fill(false);
  const rec = () => {
    if (cur.length === n) { res.push([...cur]); return; }
    for (let i = 0; i < n; i++)
      if (!used[i] && indeg[i] === 0) {
        used[i] = true; cur.push(i);

        rec();
        indeg[i] = 0;
        for (const nb of adj[i]) indeg[nb]++;
        cur.pop(); used[i] = false;
      }
  };
  rec();
  return res;
}

function alienOrder(words) {
  const adj = new Map(), indeg = new Map();
  for (const w of words) for (const c of w)
    if (!adj.has(c)) { adj.set(c, new Set()); indeg.set(c, 0); }

  for (let i = 0; i + 1 < words.length; i++) {
    const a = words[i], b = words[i+1];
    if (a.length > b.length && a.startsWith(b)) return "";
    for (let j = 0; j < Math.min(a.length, b.length); j++) {
      if (a[j] !== b[j]) {
        if (!adj.get(a[j]).has(b[j])) {
          adj.get(a[j]).add(b[j]);
          indeg.set(b[j], indeg.get(b[j]) + 1);
        }
        break;
      }
    }
  }

  const q = [...indeg.keys()].filter(c => indeg.get(c) === 0);
  const out = [];
  let h = 0;
  while (h < q.length) {
    const c = q[h++];
    out.push(c);
    for (const nb of adj.get(c)) {
      indeg.set(nb, indeg.get(nb) - 1);
      if (indeg.get(nb) === 0) q.push(nb);
    }
  }
  return out.length === indeg.size ? out.join("") : "";
}

function sequenceReconstruction(nums, sequences) {
  const n = nums.length;
  const adj = Array.from({length:n+1}, () => new Set());
  const indeg = new Array(n+1).fill(0);
  const seen = new Set();

  for (const seq of sequences) {
    for (const v of seq) { if (v < 1 || v > n) return false; seen.add(v); }
    for (let i = 0; i + 1 < seq.length; i++) {
      const u = seq[i], v = seq[i+1];
      if (!adj[u].has(v)) { adj[u].add(v); indeg[v]++; }
    }
  }
  if (seen.size !== n) return false;

  const q = [];
  for (let i = 1; i <= n; i++) if (indeg[i] === 0) q.push(i);

  let h = 0, idx = 0;
  while (h < q.length) {
    if (q.length - h > 1) return false;           // ambiguity ⟹ not unique
    const x = q[h++];
    if (x !== nums[idx++]) return false;
    for (const nb of adj[x]) if (--indeg[nb] === 0) q.push(nb);
  }
  return idx === n;
}

  const n = nums.length;
  const edges = [];
  const seen = new Set();
  for (const s of sequences) {
    for (const v of s) { if (v < 1 || v > n) return false; seen.add(v); }
    for (let i = 0; i+1 < s.length; i++) edges.push([s[i]-1, s[i+1]-1]);
  }
  if (seen.size !== n) return false;
  const all = allTopoOrders(n, edges);
  return all.length === 1 && all[0].map(x => x+1).join() === nums.join();
}

🎯 Key Takeaways

  • A topological order arranges vertices so every edge points forward, and one exists if and only if the graph is a DAG.
  • Every topological-sort algorithm is also a cycle detector — "can this be done" and "in what order" are the same computation.
  • Kahn's algorithm repeatedly emits indegree-0 nodes; if fewer than n are emitted, the missing ones are in or downstream of a cycle.
  • The cycle check is free in Kahn's — just compare the output length to n. Omitting it silently accepts cyclic input.
  • Edge direction is the most common bug: [course, prereq] means the edge runs prereq → course, and the indegree belongs to course.
  • Sanity-check direction with [[1,0]] — a correct order must start with 0.
  • The DFS version appends nodes at finishing time and reverses the result; forgetting the reversal gives exactly the wrong order.
  • DFS topological sort needs three-colour marking, since a plain visited set reports false cycles on converging paths.
  • Kahn's is the better interview default: free cycle detection, iterative, and it extends to level counting and min-heap variants.
  • Processing a whole indegree-0 frontier per round answers "how many semesters" — and that count equals the DAG's longest path.
  • Counting nodes instead of levels answers a different question — sequential time rather than parallel rounds.
  • Swapping the queue for a min-heap yields the lexicographically smallest valid order, at O(V log V + E).
  • Topological orders are usually not unique, so tests must verify the ordering property rather than compare against one expected answer.
  • The order is unique exactly when the queue never holds two nodes at once — an equivalence verified against brute force.
  • In Alien Dictionary, only adjacent word pairs inform, only up to the first differing character, and a longer word preceding its own prefix is invalid input.
  • Deduplicate edges with a Set — double-counting an indegree makes a node unreachable and fakes a cycle, which looks like correct rejection.
  • Seed all indegree-0 nodes, or disconnected components are silently dropped.
  • With a topological order in hand, DAG shortest and longest paths are a single DP pass — no heap required even with negative weights.
