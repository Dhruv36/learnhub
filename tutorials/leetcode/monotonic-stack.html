Stack / Monotonic Stack Core Pattern

What you'll master: the "next greater element" family and why a stack that stays sorted answers all of it in one pass; the amortised argument that makes an inner while loop O(n) rather than O(n²); how to choose increasing versus decreasing and store indices rather than values; the histogram problem and why every bar's rectangle is bounded by its nearest smaller neighbours on both sides; Trapping Rain Water solved three ways with an honest comparison; and the plain-stack problems — validity, expression evaluation, path simplification — that share the same last-in-first-out reasoning. Prerequisites: Arrays & Strings, Big-O.

Part 1 — The Question a Monotonic Stack Answers

One question drives this entire pattern: for each element, what is the nearest element to its left or right that is greater (or smaller) than it?

nums  = [2, 1, 2, 4, 3]
next greater to the right:
        [4, 2, 4, -1, -1]
         ↑  ↑  ↑
         │  │  └─ 4 is the next value bigger than 2
         │  └──── 2 is the next value bigger than 1
         └─────── 4 is the next value bigger than 2

The brute force is two nested loops — O(n²). The stack version is one pass, and the idea is a single observation:

if nums[j] > nums[i]  and  j > i,
then for any k < i with nums[k] < nums[i], element i is a BETTER answer than j
⟹ once nums[i] is surpassed, it can never be the answer for anything further right
⟹ so DISCARD it — permanently

function nextGreater(nums) {                     // LC 496 / 739 core
  const n = nums.length;
  const res = new Array(n).fill(-1);
  const stack = [];                              // holds INDICES, values decreasing

  for (let i = 0; i < n; i++) {
    while (stack.length && nums[stack[stack.length-1]] < nums[i]) {
      res[stack.pop()] = nums[i];                // i is the answer for the popped index
    }
    stack.push(i);
  }
  return res;
}
// O(n) time, O(n) space
🔑 The stack holds elements still waiting for an answer, and they are necessarily sorted. That is not a design choice — it is forced. Any element that is not smaller than the one below it would already have been popped when that one arrived. So the stack is monotone as a consequence of the algorithm, and its top is always the nearest unresolved candidate. Seeing it this way is why the pattern generalises instead of being four memorised templates.

Part 2 — Why the Inner Loop Is Still O(n)

A while inside a for looks quadratic. It is not, and the argument is the same amortised reasoning as the sliding window:

each index is PUSHED exactly once      → n pushes total
each index is POPPED at most once      → ≤ n pops total
                                       ─────────────────
total stack operations                 ≤ 2n  ⟹  O(n)

The inner loop can run n times on a single iteration — a decreasing array followed by one huge value does exactly that — but then it never runs again, because the stack is empty. Cost is bounded by total pops, not by the worst single iteration.

InputInner-loop behaviourTotal work
Increasing [1,2,3,4]Pops one per stepn pops
Decreasing [4,3,2,1]Never pops; all stay0 pops
[4,3,2,1,99]Pops 4 at the last step4 pops
Any inputVaries≤ n pops

Part 3 — Choosing the Direction and What to Store

Four variants come from two independent choices, and getting them straight removes most of the confusion:

WantStack keepsPop whileIterate
Next greater to the rightDecreasingstack.top < curLeft → right
Next smaller to the rightIncreasingstack.top > curLeft → right
Previous greater to the leftDecreasingstack.top <= curLeft → right, read top before push
Previous smaller to the leftIncreasingstack.top >= curLeft → right, read top before push

"Next" fills answers when popping; "previous" reads the top before pushing. That single distinction covers all four:

// NEXT smaller to the right — answer assigned on POP
function nextSmaller(nums) {
  const res = new Array(nums.length).fill(-1), st = [];
  for (let i = 0; i < nums.length; i++) {
    while (st.length && nums[st[st.length-1]] > nums[i]) res[st.pop()] = i;
    st.push(i);
  }
  return res;
}

// PREVIOUS smaller to the left — answer read BEFORE pushing
function prevSmaller(nums) {
  const res = new Array(nums.length).fill(-1), st = [];
  for (let i = 0; i < nums.length; i++) {
    while (st.length && nums[st[st.length-1]] >= nums[i]) st.pop();
    res[i] = st.length ? st[st.length-1] : -1;   // ← read, don't assign on pop
    st.push(i);
  }
  return res;
}

Store indices, not values. Indices give you the value via nums[i] plus the distance j - i, which half these problems need — Daily Temperatures asks for the number of days, not the temperature:

function dailyTemperatures(T) {                  // LC 739
  const res = new Array(T.length).fill(0), st = [];
  for (let i = 0; i < T.length; i++) {
    while (st.length && T[st[st.length-1]] < T[i]) {
      const j = st.pop();
      res[j] = i - j;                            // ← the DISTANCE, available only with indices
    }
    st.push(i);
  }
  return res;
}

Circular arrays (LC 503) are handled by iterating twice modulo n, pushing only on the first pass:

for (let i = 0; i < 2 * n; i++) {
  const cur = nums[i % n];
  while (st.length && nums[st[st.length-1]] < cur) res[st.pop()] = cur;
  if (i < n) st.push(i);                         // ← only push in the first lap
}

Part 4 — Histogram: Both Boundaries at Once

Largest Rectangle in Histogram is the pattern's showcase problem, and it rests on one observation: the largest rectangle containing bar i has height heights[i] and extends until the first shorter bar on each side.

heights = [2,1,5,6,2,3]

bar 2 (height 5): first shorter left = index 1, first shorter right = index 4
                  width = 4 - 1 - 1 = 2   area = 5 × 2 = 10

           6
        5  █
        █  █     3
     2  █  █  2  █
     █  1  █  █  █  █

function largestRectangleArea(heights) {         // LC 84
  const st = [];                                 // indices, heights increasing
  let best = 0;

  for (let i = 0; i <= heights.length; i++) {
    const h = i === heights.length ? 0 : heights[i];   // sentinel flushes the stack
    while (st.length && heights[st[st.length-1]] >= h) {
      const height = heights[st.pop()];
      const left = st.length ? st[st.length-1] : -1;
      best = Math.max(best, height * (i - left - 1));  // ← width from BOTH boundaries
    }
    st.push(i);
  }
  return best;
}
// O(n) time

The width formula is where implementations break. When bar j is popped by bar i, the first shorter bar to the right is i and the first shorter bar to the left is whatever is now on top of the stack — because everything between them was already popped, meaning it was taller:

width = i - left - 1        left = stack top after popping, or -1 if empty

NOT  i - j          (ignores how far left the rectangle extends)
NOT  i - left       (off by one: both boundaries are exclusive)

The sentinel h = 0 at i === n forces every remaining bar to be popped and measured. Without it, a monotonically increasing histogram leaves the whole stack unprocessed and returns a wrong answer.

Maximal Rectangle (LC 85) is this function applied row by row — build a histogram of consecutive 1s ending at each row, then run the histogram solver:

function maximalRectangle(matrix) {
  if (!matrix.length) return 0;
  const heights = new Array(matrix[0].length).fill(0);
  let best = 0;
  for (const row of matrix) {
    for (let c = 0; c < row.length; c++)
      heights[c] = row[c] === '1' ? heights[c] + 1 : 0;
    best = Math.max(best, largestRectangleArea(heights));
  }
  return best;
}
// O(rows × cols)

Part 5 — Trapping Rain Water, Three Ways

Water above position i is bounded by the tallest bar on each side: min(maxLeft, maxRight) - height[i]. Three techniques compute it, and comparing them is instructive.

function trapPrefix(height) {                    // A. precomputed maxima — clearest
  const n = height.length;
  if (!n) return 0;
  const L = new Array(n), R = new Array(n);
  L[0] = height[0];
  for (let i = 1; i < n; i++) L[i] = Math.max(L[i-1], height[i]);
  R[n-1] = height[n-1];
  for (let i = n-2; i >= 0; i--) R[i] = Math.max(R[i+1], height[i]);
  let total = 0;
  for (let i = 0; i < n; i++) total += Math.min(L[i], R[i]) - height[i];
  return total;
}
// O(n) time, O(n) space

function trapTwoPointer(height) {                // B. two pointers — optimal space
  let lo = 0, hi = height.length - 1;
  let maxL = 0, maxR = 0, total = 0;
  while (lo < hi) {
    if (height[lo] < height[hi]) {               // the smaller side is the binding one
      maxL = Math.max(maxL, height[lo]);
      total += maxL - height[lo];
      lo++;
    } else {
      maxR = Math.max(maxR, height[hi]);
      total += maxR - height[hi];
      hi--;
    }
  }
  return total;
}
// O(n) time, O(1) space

function trapStack(height) {                     // C. monotonic stack — fills horizontally
  const st = [];
  let total = 0;
  for (let i = 0; i < height.length; i++) {
    while (st.length && height[st[st.length-1]] < height[i]) {
      const bottom = st.pop();
      if (!st.length) break;                     // no left wall → no water
      const left = st[st.length-1];
      const width = i - left - 1;
      const depth = Math.min(height[left], height[i]) - height[bottom];
      total += width * depth;
    }
    st.push(i);
  }
  return total;
}
// O(n) time, O(n) space
ApproachSpaceFills waterBest for
Prefix maximaO(n)Column by columnExplaining the idea
Two pointersO(1)Column by columnThe optimal answer
Monotonic stackO(n)Layer by layerShowing pattern fluency

The two-pointer version's key insight is that whichever side is shorter is the one that limits the water — so its own running maximum is enough, and the other side's exact height never needs to be known. That is the same discard argument as Container With Most Water.

Part 6 — Plain Stacks and Recognition

Not every stack problem is monotonic. The plain-stack family shares a different idea: the most recent unmatched thing is what a closing token pairs with.

function isValid(s) {                            // LC 20
  const pairs = { ')': '(', ']': '[', '}': '{' };
  const st = [];
  for (const c of s) {
    if (c === '(' || c === '[' || c === '{') st.push(c);
    else if (st.pop() !== pairs[c]) return false;  // pop() on empty gives undefined → false
  }
  return st.length === 0;                        // ← unclosed brackets remain
}

function simplifyPath(path) {                    // LC 71
  const st = [];
  for (const part of path.split('/')) {
    if (part === '' || part === '.') continue;
    if (part === '..') st.pop();                 // pop on empty is a no-op — correct at root
    else st.push(part);
  }
  return '/' + st.join('/');
}

Remove K Digits (LC 402) is the greedy variant worth knowing, because it looks unrelated and is the same machinery:

function removeKdigits(num, k) {
  const st = [];
  for (const d of num) {
    while (k > 0 && st.length && st[st.length-1] > d) { st.pop(); k--; }
    st.push(d);
  }
  st.length -= k;                                // still removals left → drop from the end
  return st.join('').replace(/^0+/, '') || '0';
}

❌ Memorising four separate templates for next-greater, next-smaller, previous-greater and previous-smaller. They differ in the comparison operator, the direction of iteration, and whether the answer is written on pop or read before push — so under pressure the wrong combination gets written, and the failure is silent: the code returns plausible numbers that are wrong at the boundaries or on ties.

✅ Derive the variant from what the stack must contain. Ask "what is still waiting for an answer?" — those elements are on the stack, and they are sorted because anything violating the order would already have been popped. If you want the next greater, the waiting elements are decreasing, so pop while the top is smaller than the current. "Next" writes the answer at pop time; "previous" reads the top before pushing. Two questions, and all four variants follow.

Interview Questions

Beginner: Find the next greater element for every position in an array. 
function nextGreater(nums) {
  const res = new Array(nums.length).fill(-1);
  const st = [];                                 // indices; their values decrease
  for (let i = 0; i < nums.length; i++) {
    while (st.length && nums[st[st.length-1]] < nums[i]) {
      res[st.pop()] = nums[i];
    }
    st.push(i);
  }
  return res;
}
// O(n) time, O(n) space

The idea: the stack holds indices that have not yet found a greater element. When a new value arrives, it resolves every pending index smaller than it — all at once — and then becomes pending itself.

nums = [2,1,2,4,3]

i=0 (2): stack empty → push 0            st=[0]
i=1 (1): 2 > 1, no pop → push 1          st=[0,1]
i=2 (2): pop 1 (1<2) → res[1]=2; push 2  st=[0,2]
i=3 (4): pop 2 (2<4) → res[2]=4
         pop 0 (2<4) → res[0]=4; push 3  st=[3]
i=4 (3): 4 > 3, no pop → push 4          st=[3,4]

res = [4,2,4,-1,-1]  ✓

Why the stack is always decreasing: it is not enforced, it is implied. If an element were larger than the one below it, that lower one would have been popped when this element arrived. So monotonicity is a consequence of the pop rule.

Why it is O(n) despite the nested loop: each index is pushed once and popped at most once, so total stack operations are bounded by 2n. A single iteration can pop many elements, but then those are gone permanently.

Store indices, not values — nums[i] recovers the value, and the index is needed for distance-based variants like Daily Temperatures, which asks how many days rather than which temperature.

Beginner: Validate a string of brackets.

A closing bracket must match the most recent unmatched opener — which is exactly a stack.

function isValid(s) {
  const pairs = { ')': '(', ']': '[', '}': '{' };
  const st = [];
  for (const c of s) {
    if (c in pairs) {                            // a closer
      if (st.pop() !== pairs[c]) return false;
    } else {
      st.push(c);
    }
  }
  return st.length === 0;
}
// O(n) time, O(n) space

"([{}])"   push ( [ {   → } matches {   → ] matches [   → ) matches (   → empty ✓
"([)]"     push ( [     → ) expects ( but top is [    → false ✓
"((("      push ( ( (   → stack not empty at the end  → false ✓
")("       pop on empty → undefined !== "("           → false ✓

Two checks are both required, and dropping either is the classic bug:

CheckCatches
Popped value matches the expected opener"([)]" — wrong nesting order
Stack empty at the end"(((" — unclosed openers

Popping an empty stack returns undefined in JavaScript, which safely fails the comparison against any opener — so ")(" is rejected without an explicit emptiness check. In a language where popping empty throws or is undefined behaviour, that guard must be added explicitly.

Why a counter is insufficient for multiple bracket types: counting opens and closes accepts "([)]", which is balanced by count but wrongly nested. A single bracket type could use a counter; three types need the ordering information a stack provides.

Mid: Daily Temperatures — for each day, how many days until a warmer one?

Same machinery as next-greater, but the answer is a distance — which is why the stack must hold indices.

function dailyTemperatures(T) {
  const res = new Array(T.length).fill(0);
  const st = [];
  for (let i = 0; i < T.length; i++) {
    while (st.length && T[st[st.length-1]] < T[i]) {
      const j = st.pop();
      res[j] = i - j;                            // days waited
    }
    st.push(i);
  }
  return res;
}
// O(n) time, O(n) space

T = [73,74,75,71,69,72,76,73]

i=1 (74): pop 0 → res[0] = 1-0 = 1
i=2 (75): pop 1 → res[1] = 2-1 = 1
i=5 (72): pop 4 (69) → res[4] = 5-4 = 1
          pop 3 (71) → res[3] = 5-3 = 2
i=6 (76): pop 5 → res[5] = 1
          pop 2 → res[2] = 6-2 = 4
i=7 (73): 76 > 73, stays

res = [1,1,4,2,1,1,0,0]  ✓   (0 = never gets warmer)

Indices are non-negotiable here. Storing temperatures would give the warmer value but not how many days elapsed — the question asks for the gap, so the position must be retained.

The default of 0 handles "never warmer" without a special case: indices left on the stack at the end were never resolved, and their result stays 0.

A useful sanity check is that the total number of pops equals the number of non-zero answers, which makes the amortised argument concrete — 6 pops for 6 resolved days in the example above.

The circular variant (LC 503) loops 2n times using i % n, pushing only while i < n. The second lap resolves indices that wrap around, and skipping the push prevents duplicate entries.

Mid: Largest rectangle in a histogram.

For each bar, the largest rectangle whose height is that bar extends left and right until it meets a shorter bar. A monotonic stack finds both boundaries in one pass.

function largestRectangleArea(heights) {
  const st = [];                                 // indices, heights increasing
  let best = 0;
  for (let i = 0; i <= heights.length; i++) {
    const h = i === heights.length ? 0 : heights[i];   // sentinel
    while (st.length && heights[st[st.length-1]] >= h) {
      const height = heights[st.pop()];
      const left = st.length ? st[st.length-1] : -1;
      best = Math.max(best, height * (i - left - 1));
    }
    st.push(i);
  }
  return best;
}
// O(n) time, O(n) space

The width derivation is the crux. When bar j is popped at position i:

BoundaryValueWhy
First shorter bar to the rightiIt is what triggered the pop
First shorter bar to the leftNew stack topEverything between was taller and already popped
Widthi - left - 1Both boundaries are exclusive
heights = [2,1,5,6,2,3]

pop 6 at i=4: left=2 (height 5)  width = 4-2-1 = 1  area = 6
pop 5 at i=4: left=1 (height 1)  width = 4-1-1 = 2  area = 10  ← best
pop 2 at i=6: left=4             width = 6-4-1 = 1  area = 3
...
answer 10 ✓

The sentinel is mandatory. On [1,2,3,4,5] nothing is ever popped during the scan, so without the trailing 0 the answer would be 0. Appending a zero-height bar forces every remaining index to be measured.

The >= in the pop condition handles duplicates. With equal heights, the earlier bar computes a narrower rectangle than it could — but the later duplicate computes the full width, so the maximum is still correct. Using > also works here; being aware of which and why is what distinguishes understanding from transcription.

Maximal Rectangle (LC 85) reduces to this: maintain a histogram of consecutive 1s ending at each row, and run this function per row — O(rows × cols) overall.

Senior: Trapping Rain Water — give multiple solutions and compare them.

Water above index i is min(maxLeft, maxRight) - height[i]. Three ways to obtain those maxima.

A. Precomputed prefix maxima — clearest, O(n) space:

function trapPrefix(height) {
  const n = height.length; if (!n) return 0;
  const L = new Array(n), R = new Array(n);
  L[0] = height[0];
  for (let i = 1; i < n; i++) L[i] = Math.max(L[i-1], height[i]);
  R[n-1] = height[n-1];
  for (let i = n-2; i >= 0; i--) R[i] = Math.max(R[i+1], height[i]);
  let t = 0;
  for (let i = 0; i < n; i++) t += Math.min(L[i], R[i]) - height[i];
  return t;
}

B. Two pointers — O(1) space, the optimal answer:

function trapTwoPointer(height) {
  let lo = 0, hi = height.length - 1, maxL = 0, maxR = 0, t = 0;
  while (lo < hi) {
    if (height[lo] < height[hi]) {
      maxL = Math.max(maxL, height[lo]);
      t += maxL - height[lo];
      lo++;
    } else {
      maxR = Math.max(maxR, height[hi]);
      t += maxR - height[hi];
      hi--;
    }
  }
  return t;
}

Why B is correct is the interesting part. If height[lo] < height[hi], then there exists some bar on the right at least as tall as height[hi], so the right maximum is guaranteed ≥ the left maximum. The water at lo is therefore limited by maxL alone — the exact right maximum never needs computing.

C. Monotonic stack — fills horizontally rather than vertically:

function trapStack(height) {
  const st = []; let t = 0;
  for (let i = 0; i < height.length; i++) {
    while (st.length && height[st[st.length-1]] < height[i]) {
      const bottom = st.pop();
      if (!st.length) break;                     // no left wall
      const left = st[st.length-1];
      t += (i - left - 1) * (Math.min(height[left], height[i]) - height[bottom]);
    }
    st.push(i);
  }
  return t;
}
TimeSpaceDirectionVerdict
Prefix maximaO(n)O(n)VerticalBest for explaining
Two pointersO(n)O(1)VerticalShip this
StackO(n)O(n)HorizontalShows pattern range

How I would present it: start with the brute force (for each index, scan both sides — O(n²)), observe that the scans are recomputing the same maxima, precompute them for O(n)/O(n), then eliminate the arrays with two pointers for O(1) space. That progression demonstrates the optimisation reasoning rather than a memorised endpoint — and the stack version is worth mentioning as a different decomposition entirely, filling water in horizontal layers instead of vertical columns.

Senior: Remove k digits to make the smallest possible number. Why does a stack solve it?

Because the greedy choice is local and the stack maintains exactly the invariant the greedy needs.

function removeKdigits(num, k) {
  const st = [];
  for (const d of num) {
    while (k > 0 && st.length && st[st.length-1] > d) { st.pop(); k--; }
    st.push(d);
  }
  st.length -= k;                                // unused removals → drop from the tail
  return st.join('').replace(/^0+/, '') || '0';
}
// O(n) time, O(n) space

The greedy argument: to minimise a number of fixed length, the leftmost digit matters most. So whenever a digit is followed by a smaller one, removing it strictly reduces the result — the smaller digit moves into a more significant position. Repeating until no such pair remains leaves a non-decreasing sequence, which is the smallest arrangement obtainable by deletion.

num = "1432219", k = 3

1        st=[1]
4        st=[1,4]
3  4>3   pop 4 (k=2)   st=[1,3]
2  3>2   pop 3 (k=1)   st=[1,2]
2  2==2  no pop        st=[1,2,2]
1  2>1   pop 2 (k=0)   st=[1,2,1]
9  k=0   no pop        st=[1,2,1,9]

→ "1219"  ✓

Three details carry the correctness:

1. st.length -= k at the end. If the input is non-decreasing — "12345" with k=2 — no pops ever happen, and the remaining removals must come from the tail, since removing a later digit is always better than an earlier one in a non-decreasing sequence.

2. Leading zeros must be stripped. "10200" with k=1 produces "0200", which is "200".

3. The empty result is "0". Removing every digit leaves an empty string, and the problem expects "0".

The same pattern appears elsewhere, which is why it is worth recognising as a family rather than a one-off:

ProblemVariation
Remove K Digits (402)Increasing stack, budget k
Remove Duplicate Letters (316)Increasing stack + "can I see this letter again?"
Smallest Subsequence of Distinct Chars (1081)Identical to 316
Create Maximum Number (321)Decreasing stack, then merge

Remove Duplicate Letters adds one condition: only pop when the popped character occurs again later, tracked with a last-occurrence table. That extra guard is what makes it harder than 402, and it is the same stack otherwise.

  const r = new Array(a.length).fill(-1), st = [];

    st.push(i);
  }
  return r;

function largestRectangleArea(h) {
  const st = []; let best = 0;
  for (let i = 0; i <= h.length; i++) {
    const cur = i === h.length ? 0 : h[i];
    while (st.length && h[st[st.length-1]] >= cur) {
      const height = h[st.pop()];
      const left = st.length ? st[st.length-1] : -1;
      best = Math.max(best, height * (i - left - 1));
    }
    st.push(i);
  }
  return best;
}

function bruteForce(h) {                         // O(n^2) reference
  let best = 0;
  for (let i = 0; i < h.length; i++) {
    let minH = h[i];
    for (let j = i; j < h.length; j++) {
      minH = Math.min(minH, h[j]);
      best = Math.max(best, minH * (j - i + 1));
    }
  }
  return best;
}

Extend to Maximal Rectangle (LC 85):

function maximalRectangle(matrix) {
  if (!matrix.length) return 0;
  const heights = new Array(matrix[0].length).fill(0);
  let best = 0;
  for (const row of matrix) {
    for (let c = 0; c < row.length; c++)
      heights[c] = row[c] === '1' ? heights[c] + 1 : 0;
    best = Math.max(best, largestRectangleArea(heights));
  }
  return best;
}

  ["1","1","1","1","1"],
  ["1","0","0","1","0"]]));                      // 6

Each row becomes a histogram of consecutive 1s ending at that row, and the answer is the best rectangle over all rows — O(rows × cols), reusing the solved subproblem entirely.

4 (medium): Implement Trapping Rain Water three ways and benchmark.
Solution 
function trapBrute(h) {                          // O(n^2) reference
  let t = 0;
  for (let i = 0; i < h.length; i++) {
    let l = 0, r = 0;
    for (let j = 0; j <= i; j++) l = Math.max(l, h[j]);
    for (let j = i; j < h.length; j++) r = Math.max(r, h[j]);
    t += Math.min(l, r) - h[i];
  }
  return t;
}

function trapPrefix(h) {
  const n = h.length; if (!n) return 0;
  const L = new Array(n), R = new Array(n);
  L[0] = h[0]; for (let i=1;i<n;i++) L[i] = Math.max(L[i-1], h[i]);
  R[n-1] = h[n-1]; for (let i=n-2;i>=0;i--) R[i] = Math.max(R[i+1], h[i]);
  let t = 0; for (let i=0;i<n;i++) t += Math.min(L[i], R[i]) - h[i];
  return t;
}

function trapTwoPointer(h) {
  let lo = 0, hi = h.length - 1, maxL = 0, maxR = 0, t = 0;
  while (lo < hi) {
    if (h[lo] < h[hi]) { maxL = Math.max(maxL, h[lo]); t += maxL - h[lo]; lo++; }
    else               { maxR = Math.max(maxR, h[hi]); t += maxR - h[hi]; hi--; }
  }
  return t;
}

function trapStack(h) {
  const st = []; let t = 0;
  for (let i = 0; i < h.length; i++) {
    while (st.length && h[st[st.length-1]] < h[i]) {
      const bottom = st.pop();
      if (!st.length) break;
      const left = st[st.length-1];
      t += (i - left - 1) * (Math.min(h[left], h[i]) - h[bottom]);
    }
    st.push(i);
  }
  return t;
}

5 (hard): Solve the greedy stack family — Remove K Digits and Remove Duplicate Letters.
Solution 
function removeKdigits(num, k) {
  const st = [];
  for (const d of num) {
    while (k > 0 && st.length && st[st.length-1] > d) { st.pop(); k--; }
    st.push(d);
  }
  st.length -= k;
  return st.join('').replace(/^0+/, '') || '0';
}

function removeDuplicateLetters(s) {             // LC 316
  const last = {};
  for (let i = 0; i < s.length; i++) last[s[i]] = i;
  const st = [], inStack = new Set();
  for (let i = 0; i < s.length; i++) {
    const c = s[i];
    if (inStack.has(c)) continue;                // already placed
    while (st.length && st[st.length-1] > c && last[st[st.length-1]] > i) {
      inStack.delete(st.pop());                  // ← only pop if we can see it AGAIN
    }
    st.push(c);
    inStack.add(c);
  }
  return st.join('');
}

function bruteRemoveK(num, k) {
  const n = num.length;
  let best = null;
  const keep = n - k;
  // try every subset of size keep
  const rec = (i, acc) => {
    if (acc.length === keep) {
      const v = acc.join('').replace(/^0+/, '') || '0';
      if (best === null || BigInt(v) < BigInt(best)) best = v;
      return;
    }
    if (i >= n) return;
    rec(i+1, [...acc, num[i]]);
    rec(i+1, acc);
  };
  rec(0, []);
  return best;
}

The shared structure across this family: an increasing stack, a budget or constraint on popping, and a tail-handling rule. Recognising it converts four "hard" problems into one pattern with three parameters.

6 (hard): Build a stack-based expression evaluator.
Solution

Two stacks — one for numbers, one for operators — handle precedence and parentheses in a single pass:

function calculate(s) {                          // LC 224/227 combined: + - * / ( )
  const nums = [], ops = [];
  const prec = { '+': 1, '-': 1, '*': 2, '/': 2 };

  const apply = () => {
    const op = ops.pop();
    const b = nums.pop(), a = nums.pop();
    if (op === '+') nums.push(a + b);
    else if (op === '-') nums.push(a - b);
    else if (op === '*') nums.push(a * b);
    else nums.push(Math.trunc(a / b));           // integer division toward zero
  };

  let i = 0;
  while (i < s.length) {
    const c = s[i];
    if (c === ' ') { i++; continue; }

    if (c >= '0' && c <= '9') {
      let n = 0;
      while (i < s.length && s[i] >= '0' && s[i] <= '9') { n = n*10 + (+s[i]); i++; }
      nums.push(n);
      continue;
    }

    if (c === '(') { ops.push(c); i++; continue; }

    if (c === ')') {
      while (ops.length && ops[ops.length-1] !== '(') apply();
      ops.pop();                                 // discard '('
      i++;
      continue;
    }

    // an operator: apply everything of >= precedence first (left associativity)
    // handle unary minus: "-5" or "(-5)"
    if (c === '-' && (nums.length === ops.filter(o => o !== '(').length)) {
      nums.push(0);                              // treat as 0 - x
    }
    while (ops.length && ops[ops.length-1] !== '(' &&
           prec[ops[ops.length-1]] >= prec[c]) apply();
    ops.push(c);
    i++;
  }
  while (ops.length) apply();
  return nums[0];
}

🎯 Key Takeaways

  • A monotonic stack answers one question: for each element, what is the nearest greater or smaller element to its left or right?
  • The stack holds elements still waiting for an answer, and it is sorted as a consequence — anything out of order would already have been popped.
  • The inner while does not make it O(n²): each index is pushed once and popped at most once, so total work is ≤ 2n.
  • Store indices, never values — indices give both the value and the distance, which half these problems need.
  • "Next" variants assign the answer when popping; "previous" variants read the stack top before pushing.
  • Want the next greater? The waiting elements are decreasing, so pop while the top is smaller.
  • Tie handling (< vs <=) only matters with duplicates — decide deliberately and test with repeated values.
  • Circular arrays iterate 2n times with i % n, pushing only during the first lap.
  • In the histogram problem, each bar's rectangle is bounded by the first shorter bar on each side, and width is right - left - 1 because both bounds are exclusive.
  • The histogram needs a trailing sentinel of height 0, or an ascending input leaves the stack unprocessed and returns 0.
  • Maximal Rectangle is the histogram solver applied per row over a running count of consecutive 1s.
  • Trapping Rain Water has three solutions; two pointers is O(1) space and fastest, the stack version fills water in horizontal layers.
  • The two-pointer water argument: whichever side is shorter is the binding constraint, so only its running maximum is needed.
  • Remove K Digits, Remove Duplicate Letters and Create Maximum Number are the same greedy increasing stack with different budgets and guards.
  • In Remove Duplicate Letters, only pop a character that appears again later — otherwise it is lost permanently.
  • Plain stacks solve bracket validity, path simplification and expression evaluation via "the most recent unmatched item is what pairs next".
  • Bracket validation needs both checks: the popped value must match, and the stack must be empty at the end.
  • In an expression evaluator, prec[top] >= prec[cur] gives left associativity; > silently makes subtraction right-associative.
