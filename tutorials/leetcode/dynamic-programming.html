Dynamic Programming Advanced Pattern

What you'll master: the two conditions that make DP applicable, and how to test for them before writing any code; the state-definition discipline that turns a vague problem into a recurrence — which is 90% of the difficulty; memoisation versus tabulation and when each is genuinely better; the classic families — 0/1 knapsack, unbounded knapsack, LCS, LIS, interval DP, digit DP — and the recurrence shape that identifies each; space optimisation from 2D to 1D and the iteration-direction rule that makes it correct; and how to reconstruct the actual solution rather than just its value. Prerequisites: Backtracking, Big-O.

Part 1 — When DP Applies

Dynamic programming needs exactly two properties. If both hold, DP works; if either fails, it does not.

PropertyMeaningTest
Optimal substructureThe optimum is built from optima of subproblems"If I knew the answer for smaller inputs, could I combine them?"
Overlapping subproblemsThe same subproblem recurs many times"Does my recursion tree repeat states?"
fib(5)
        ┌──────── fib(5) ────────┐
    fib(4)                    fib(3)
   ┌───┴───┐                ┌───┴───┐
 fib(3)  fib(2)          fib(2)  fib(1)
 ┌──┴──┐                             ← fib(3) computed twice
fib(2) fib(1)                          fib(2) computed three times
🔑 Overlapping subproblems is what separates DP from divide-and-conquer. Merge sort has optimal substructure — a sorted whole is built from sorted halves — but its subproblems are disjoint, so caching buys nothing. DP pays off precisely when the recursion revisits the same state, which is why the first diagnostic question is always "what identifies a state, and does that state repeat?" If the answer is "every call has a unique state", you have a backtracking problem, not a DP one.
// exponential: 2ⁿ calls
const fibSlow = n => n <= 1 ? n : fibSlow(n-1) + fibSlow(n-2);

// memoised: n distinct states, each computed once → O(n)
const fibMemo = (n, memo = new Map()) => {
  if (n <= 1) return n;
  if (memo.has(n)) return memo.get(n);
  const r = fibMemo(n-1, memo) + fibMemo(n-2, memo);
  memo.set(n, r);
  return r;
};

// tabulated with O(1) space
function fib(n) {
  let a = 0, b = 1;
  for (let i = 0; i < n; i++) [a, b] = [b, a + b];
  return a;
}

Part 2 — Defining the State

Choosing the state is the entire problem. Once the state is right the recurrence usually writes itself; if the recurrence feels impossible, the state is wrong.

Ask, in this order:

1. What must I know to make the next decision?     → those variables ARE the state
2. What does dp[state] MEAN, in one sentence?      → write it as a comment
3. How does dp[state] follow from smaller states?  → the recurrence
4. What are the trivial cases?                     → base cases
5. In what order must states be filled?            → iteration direction
ProblemStateMeaning
Climbing Stairsdp[i]Ways to reach step i
House Robberdp[i]Max loot from the first i houses
Coin Changedp[a]Fewest coins summing to a
0/1 Knapsackdp[i][w]Best value using items ≤ i within weight w
LCSdp[i][j]LCS length of prefixes a[0..i) and b[0..j)
LISdp[i]Longest increasing subsequence ending at i
Edit Distancedp[i][j]Edits to turn a[0..i) into b[0..j)

Note LIS: "ending at i", not "within the first i". That distinction is the difference between a workable recurrence and an impossible one — you need to know what the last element is to decide whether the next can extend it.

function rob(nums) {                             // LC 198
  // dp[i] = max loot considering houses 0..i-1
  let prev2 = 0, prev1 = 0;
  for (const x of nums) {
    const cur = Math.max(prev1, prev2 + x);      // skip this house, or take it
    prev2 = prev1;
    prev1 = cur;
  }
  return prev1;
}
// O(n) time, O(1) space

Part 3 — Memoisation Versus Tabulation

Memoisation (top-down)Tabulation (bottom-up)
DirectionRecursive, from the goalIterative, from the base
ComputesOnly reachable statesAll states

Space optimisationHardNatural
Stack overflowPossibleNone
Easier to write from a recursionYesRequires restructuring
// TOP-DOWN: closest to the brute-force recursion, just add a cache
function coinChangeMemo(coins, amount) {
  const memo = new Map();
  const go = rem => {
    if (rem === 0) return 0;
    if (rem < 0) return Infinity;
    if (memo.has(rem)) return memo.get(rem);
    let best = Infinity;
    for (const c of coins) best = Math.min(best, go(rem - c) + 1);
    memo.set(rem, best);
    return best;
  };
  const r = go(amount);
  return r === Infinity ? -1 : r;
}

// BOTTOM-UP: same recurrence, filled in order
function coinChange(coins, amount) {             // LC 322
  const dp = new Array(amount + 1).fill(Infinity);
  dp[0] = 0;                                     // base: zero coins for zero
  for (let a = 1; a <= amount; a++)
    for (const c of coins)
      if (c <= a) dp[a] = Math.min(dp[a], dp[a - c] + 1);
  return dp[amount] === Infinity ? -1 : dp[amount];
}
// O(amount × coins)

Write the memoised version first in an interview. It follows directly from the brute-force recursion — add a cache and you are done — whereas tabulation requires working out the fill order before writing anything.

Memoisation wins when the reachable state space is sparse. If only a small fraction of states are ever visited, tabulation wastes time filling the rest.

Part 4 — The Classic Families

0/1 knapsack — each item used at most once:

dp[i][w] = max(dp[i-1][w],                       // skip item i
               dp[i-1][w - wt[i]] + val[i])      // take item i

function knapsack(weights, values, W) {
  const dp = new Array(W + 1).fill(0);
  for (let i = 0; i < weights.length; i++)
    for (let w = W; w >= weights[i]; w--)        // ← BACKWARD: each item once
      dp[w] = Math.max(dp[w], dp[w - weights[i]] + values[i]);
  return dp[W];
}

Unbounded knapsack — items reusable — differs by one character:

for (let w = weights[i]; w <= W; w++)            // ← FORWARD: reuse allowed
  dp[w] = Math.max(dp[w], dp[w - weights[i]] + values[i]);

The direction is the whole distinction. Iterating backward reads dp[w - wt] from the previous item's row, so each item is used once. Iterating forward reads a value already updated for the current item, permitting reuse.

LCS and edit distance — two sequences, 2D state:

function longestCommonSubsequence(a, b) {        // LC 1143
  const dp = Array.from({length: a.length + 1}, () => new Array(b.length + 1).fill(0));
  for (let i = 1; i <= a.length; i++)
    for (let j = 1; j <= b.length; j++)
      dp[i][j] = a[i-1] === b[j-1]
        ? dp[i-1][j-1] + 1                       // characters match: extend the diagonal
        : Math.max(dp[i-1][j], dp[i][j-1]);      // else drop one character
  return dp[a.length][b.length];
}
// O(m × n)

function minDistance(a, b) {                     // LC 72 — edit distance
  const m = a.length, n = b.length;
  const dp = Array.from({length: m+1}, (_, i) => new Array(n+1).fill(0));
  for (let i = 0; i <= m; i++) dp[i][0] = i;     // delete everything
  for (let j = 0; j <= n; j++) dp[0][j] = j;     // insert everything
  for (let i = 1; i <= m; i++)
    for (let j = 1; j <= n; j++)
      dp[i][j] = a[i-1] === b[j-1]
        ? dp[i-1][j-1]
        : 1 + Math.min(dp[i-1][j-1],             // replace
                       dp[i-1][j],               // delete
                       dp[i][j-1]);              // insert
  return dp[m][n];
}

LIS — the O(n log n) version uses binary search:

function lengthOfLIS(nums) {                     // LC 300
  const tails = [];                              // tails[k] = smallest tail of an LIS of length k+1
  for (const x of nums) {
    let lo = 0, hi = tails.length;
    while (lo < hi) {                            // lower_bound
      const mid = (lo + hi) >> 1;
      if (tails[mid] < x) lo = mid + 1; else hi = mid;
    }
    tails[lo] = x;                               // replace or append
  }
  return tails.length;
}
// O(n log n) — note `tails` is NOT the LIS itself, only its length is meaningful

Part 5 — Space Optimisation

When dp[i][*] depends only on dp[i-1][*], the table collapses to one or two rows.

2D: dp[i][j] depends on dp[i-1][j], dp[i][j-1], dp[i-1][j-1]
                        ─────────   ─────────  ───────────
                        prev row    cur row    prev row, prev col

→ keep one row + one scalar for the diagonal

function lcsOptimised(a, b) {
  let prev = new Array(b.length + 1).fill(0);
  for (let i = 1; i <= a.length; i++) {
    const cur = new Array(b.length + 1).fill(0);
    for (let j = 1; j <= b.length; j++)
      cur[j] = a[i-1] === b[j-1] ? prev[j-1] + 1 : Math.max(prev[j], cur[j-1]);
    prev = cur;
  }
  return prev[b.length];
}
// O(min(m,n)) space — swap the arguments so b is the shorter string
DependencySpaceDirection constraint
Only dp[i-1][j]1 rowEither
dp[i-1][j] and dp[i-1][j-w]1 rowBackward (0/1 knapsack)
dp[i][j-w] allowed1 rowForward (unbounded)
Also dp[i-1][j-1]1 row + scalarSave the diagonal before overwriting
Constant lookbackO(1)Rolling variables

Space optimisation destroys the ability to reconstruct the answer — the discarded rows held the decisions. Keep the full table when the actual solution is required, or store parent pointers separately.

Part 6 — Reconstruction and Recognition

function lcsString(a, b) {
  const m = a.length, n = b.length;
  const dp = Array.from({length:m+1}, () => new Array(n+1).fill(0));
  for (let i = 1; i <= m; i++)
    for (let j = 1; j <= n; j++)
      dp[i][j] = a[i-1] === b[j-1] ? dp[i-1][j-1] + 1 : Math.max(dp[i-1][j], dp[i][j-1]);

  let i = m, j = n, out = "";                    // walk BACKWARD through the table
  while (i > 0 && j > 0) {
    if (a[i-1] === b[j-1]) { out = a[i-1] + out; i--; j--; }
    else if (dp[i-1][j] >= dp[i][j-1]) i--;
    else j--;
  }
  return out;
}

The last row matters: DP computes an aggregate — a count, an optimum, a boolean. If you need the actual list of every solution, the output itself is exponential and DP cannot help.

❌ Reaching for the recurrence before pinning down what dp[i] means. The usual symptom is a state that almost works: for LIS, defining dp[i] as "the longest increasing subsequence among the first i elements" produces a recurrence you cannot write, because extending requires knowing the last element's value and the state has discarded it. People then patch it with extra loops and conditionals, producing code that passes the sample and fails on the third test.

✅ Write the meaning of dp[state] as an English sentence first, and only then derive the transition. For LIS the correct definition is "the longest increasing subsequence ending exactly at index i" — which immediately gives dp[i] = 1 + max(dp[j]) over all j < i with nums[j] < nums[i], and makes the final answer max(dp) rather than dp[n-1]. If the recurrence resists being written, the state is wrong — add a dimension or change what it means, rather than patching the transition.

Interview Questions

Beginner: What is dynamic programming, and when does it apply?

DP solves problems by breaking them into overlapping subproblems and caching each subproblem's answer so it is computed once. It requires two properties:

PropertyMeaning
Optimal substructureThe optimum is built from subproblem optima
Overlapping subproblemsThe same subproblem appears repeatedly

The second is what distinguishes DP from divide-and-conquer. Merge sort has optimal substructure but disjoint subproblems, so caching gains nothing. Fibonacci's recursion tree revisits fib(3) many times, which is exactly where caching pays.

fib(5) naive:  2ⁿ calls          fib(5) memoised: n states, each computed once
      fib(5)
     /      \
  fib(4)   fib(3)   ← fib(3) also appears under fib(4)

const fibMemo = (n, memo = new Map()) => {
  if (n <= 1) return n;
  if (memo.has(n)) return memo.get(n);
  memo.set(n, fibMemo(n-1, memo) + fibMemo(n-2, memo));
  return memo.get(n);
};

The two implementation styles are memoisation (top-down: recursion plus a cache) and tabulation (bottom-up: fill an array in dependency order). They compute the same values; memoisation only computes reachable states, tabulation computes all of them but avoids recursion.

How I would recognise a DP problem: it asks for a count, an optimum, or a feasibility answer — "how many ways", "minimum cost", "can it be done" — and a brute-force recursion exists whose calls repeat the same arguments. If every recursive call has a genuinely unique state, it is backtracking instead.

Beginner: Solve Climbing Stairs and House Robber, and explain the state.

Climbing Stairs: dp[i] = number of ways to reach step i. You arrive either from step i−1 or i−2, so the ways add.

function climbStairs(n) {
  let a = 1, b = 1;                              // ways to reach step 0 and step 1
  for (let i = 2; i <= n; i++) [a, b] = [b, a + b];
  return b;
}
// dp[i] = dp[i-1] + dp[i-2]  — Fibonacci
// O(n) time, O(1) space

House Robber: dp[i] = maximum loot considering the first i houses. At each house the choice is take-it-and-skip-the-previous, or skip-it.

function rob(nums) {
  let prev2 = 0, prev1 = 0;
  for (const x of nums) {
    const cur = Math.max(prev1, prev2 + x);
    prev2 = prev1;
    prev1 = cur;
  }
  return prev1;
}
// dp[i] = max(dp[i-1], dp[i-2] + nums[i])

nums = [2,7,9,3,1]

i=0: max(0, 0+2)  = 2
i=1: max(2, 0+7)  = 7
i=2: max(7, 2+9)  = 11
i=3: max(11, 7+3) = 11
i=4: max(11, 11+1)= 12  ✓

Both have the same shape — dp[i] depends only on the previous two values — so both collapse to O(1) space with two rolling variables. Recognising that shape is what turns an O(n) array into two scalars.

House Robber II (circular street) is the natural follow-up: the first and last houses are now adjacent, so run the linear solver twice — once excluding the first house, once excluding the last — and take the maximum.

Mid: Solve Coin Change and explain memoisation versus tabulation.

dp[a] = the fewest coins summing to amount a.

In an interview I would write the memoised version first, because it follows mechanically from the recursion I have already described, then convert to tabulation if space or stack depth matters.

Memoisation genuinely wins when states are sparse. With coins [7, 11] and amount 1000, most amounts are unreachable — top-down touches only the reachable ones, while tabulation fills all 1001.

Initialising to Infinity is essential. Filling with 0 would make every Math.min return 0, and the answer would be 0 everywhere — a bug that produces plausible output with no error.

Note this is unbounded knapsack: coins are reusable, which is why the inner loop does not track which coins were used. "Coin Change 2" — counting combinations rather than minimising count — requires the loop order to be reversed, with coins outermost, or permutations get counted instead of combinations.

Mid: Explain 0/1 knapsack and why the iteration direction matters.

dp[i][w] = the best value obtainable from the first i items within capacity w.

dp[i][w] = max(dp[i-1][w],                        // skip item i
               dp[i-1][w - wt[i]] + val[i])       // take item i

function knapsack(weights, values, W) {
  const dp = new Array(W + 1).fill(0);
  for (let i = 0; i < weights.length; i++)
    for (let w = W; w >= weights[i]; w--)        // ← BACKWARD
      dp[w] = Math.max(dp[w], dp[w - weights[i]] + values[i]);
  return dp[W];
}
// O(n × W) time, O(W) space

The direction encodes the "at most once" constraint, and this is the crux of the question:

BACKWARD (w descending):
  dp[w - wt] has NOT been touched yet this iteration
  → it still holds the value from item i-1
  → item i is used at most once ✓

FORWARD (w ascending):
  dp[w - wt] was ALREADY updated for item i
  → taking it again reuses item i
  → unbounded knapsack

weights = [3], values = [10], W = 9

backward: dp[9] = max(0, dp[6]+10) = 10          one copy ✓
forward:  dp[3]=10, dp[6]=dp[3]+10=20, dp[9]=dp[6]+10=30   three copies

So a single character — w-- versus w++ — switches between the two classic knapsack variants, and both are correct code for different problems. That is why stating which variant you are solving before writing the loop is worth doing explicitly.

VariantDirectionExample problem
0/1 (each item once)BackwardPartition Equal Subset Sum
Unbounded (reusable)ForwardCoin Change

Partition Equal Subset Sum is 0/1 knapsack in disguise: ask whether a subset sums to total/2, with a boolean DP instead of a value one.

Senior: Solve Longest Increasing Subsequence in O(n log n) and explain how it works.

The O(n²) DP is the natural starting point:

function lisQuadratic(nums) {
  const dp = new Array(nums.length).fill(1);     // dp[i] = LIS ENDING AT i
  for (let i = 1; i < nums.length; i++)
    for (let j = 0; j < i; j++)
      if (nums[j] < nums[i]) dp[i] = Math.max(dp[i], dp[j] + 1);
  return Math.max(...dp, 0);                     // ← max over all, not dp[n-1]
}

The state must be "ending at i", because deciding whether element i can extend a subsequence requires knowing that subsequence's last value. Defining it as "within the first i" makes the recurrence unwritable — and the answer is then max(dp) rather than the last entry.

The O(n log n) version maintains a different array entirely:

function lengthOfLIS(nums) {
  const tails = [];                              // tails[k] = smallest possible tail
  for (const x of nums) {                        //            of an LIS of length k+1
    let lo = 0, hi = tails.length;
    while (lo < hi) {                            // lower_bound: first ≥ x
      const mid = (lo + hi) >> 1;
      if (tails[mid] < x) lo = mid + 1; else hi = mid;
    }
    tails[lo] = x;                               // replace, or append if lo === length
  }
  return tails.length;
}
// O(n log n)

nums = [10,9,2,5,3,7,101,18]

10  → tails [10]
 9  → replace 10        [9]
 2  → replace 9         [2]
 5  → append            [2,5]
 3  → replace 5         [2,3]
 7  → append            [2,3,7]
101 → append            [2,3,7,101]
18  → replace 101       [2,3,7,18]
→ length 4  ✓

The invariant: tails[k] holds the smallest value that can end an increasing subsequence of length k+1. Keeping tails as small as possible maximises future extension opportunities, and the array is necessarily sorted — which is what licenses the binary search.

The critical caveat: tails is not the LIS. Its length is correct but its contents may never have appeared together as a subsequence. Reconstructing the actual sequence requires storing predecessor indices alongside.

For the non-decreasing variant, switch the binary search to upper_bound (tails[mid] <= x) — a one-character change that is easy to get backwards.

Russian Doll Envelopes is the classic application: sort by width ascending and height descending for equal widths, then run LIS on heights. The descending tiebreak prevents two envelopes of equal width from both being counted.

Senior: Solve Edit Distance and reconstruct the actual edit sequence.

dp[i][j] = the minimum edits to transform a[0..i) into b[0..j).

function minDistance(a, b) {
  const m = a.length, n = b.length;
  const dp = Array.from({length:m+1}, () => new Array(n+1).fill(0));
  for (let i = 0; i <= m; i++) dp[i][0] = i;     // delete all of a
  for (let j = 0; j <= n; j++) dp[0][j] = j;     // insert all of b
  for (let i = 1; i <= m; i++)
    for (let j = 1; j <= n; j++)
      dp[i][j] = a[i-1] === b[j-1]
        ? dp[i-1][j-1]                           // free — characters match
        : 1 + Math.min(dp[i-1][j-1],             // replace
                       dp[i-1][j],               // delete from a
                       dp[i][j-1]);              // insert into a
  return dp[m][n];
}
// O(m×n) time and space

Each of the three transitions corresponds to one edit operation, which is what makes reconstruction possible — walk backward and record which predecessor was chosen:

function editSequence(a, b) {
  const m = a.length, n = b.length;
  const dp = Array.from({length:m+1}, () => new Array(n+1).fill(0));
  for (let i = 0; i <= m; i++) dp[i][0] = i;
  for (let j = 0; j <= n; j++) dp[0][j] = j;
  for (let i = 1; i <= m; i++)
    for (let j = 1; j <= n; j++)
      dp[i][j] = a[i-1] === b[j-1] ? dp[i-1][j-1]
        : 1 + Math.min(dp[i-1][j-1], dp[i-1][j], dp[i][j-1]);

  const ops = [];
  let i = m, j = n;
  while (i > 0 || j > 0) {
    if (i > 0 && j > 0 && a[i-1] === b[j-1]) { i--; j--; }              // keep
    else if (i > 0 && j > 0 && dp[i][j] === dp[i-1][j-1] + 1) {
      ops.push(`replace ${a[i-1]}→${b[j-1]} at ${i-1}`); i--; j--;
    } else if (i > 0 && dp[i][j] === dp[i-1][j] + 1) {
      ops.push(`delete ${a[i-1]} at ${i-1}`); i--;
    } else {
      ops.push(`insert ${b[j-1]} at ${i}`); j--;
    }
  }
  return ops.reverse();
}

editSequence("horse", "ros")
→ [ 'replace h→r at 0', 'delete o at 1', 'delete e at 4' ]     3 edits ✓

Reconstruction requires the full table, which is why the O(n)-space optimisation and the edit sequence are mutually exclusive. If both are needed, Hirschberg's algorithm computes the alignment in O(min(m,n)) space using divide-and-conquer, at the cost of doubling the time.

The base cases carry real meaning: dp[i][0] = i says turning a prefix of a into the empty string costs one deletion per character. Getting these wrong — filling zeros — makes every subsequent value wrong while the code still runs.

Weighted variants are a natural extension: give insert, delete and replace different costs and the same recurrence handles it. That is how spell-checkers and diff tools tune behaviour, and it is the shape of the Needleman–Wunsch algorithm in bioinformatics.

function knapsack01(weights, values, W) {
  const dp = new Array(W+1).fill(0);
  for (let i = 0; i < weights.length; i++)
    for (let w = W; w >= weights[i]; w--)        // BACKWARD
      dp[w] = Math.max(dp[w], dp[w - weights[i]] + values[i]);
  return dp[W];
}

function knapsackUnbounded(weights, values, W) {
  const dp = new Array(W+1).fill(0);
  for (let i = 0; i < weights.length; i++)
    for (let w = weights[i]; w <= W; w++)        // FORWARD
      dp[w] = Math.max(dp[w], dp[w - weights[i]] + values[i]);
  return dp[W];
}

function knapsack01Brute(weights, values, W) {   // try every subset
  let best = 0;
  const n = weights.length;
  for (let m = 0; m < (1 << n); m++) {
    let wt = 0, v = 0;
    for (let i = 0; i < n; i++) if (m & (1<<i)) { wt += weights[i]; v += values[i]; }
    if (wt <= W) best = Math.max(best, v);
  }
  return best;
}

function knapsackUnboundedBrute(weights, values, W) {
  const go = rem => {
    let best = 0;
    for (let i = 0; i < weights.length; i++)
      if (weights[i] <= rem) best = Math.max(best, values[i] + go(rem - weights[i]));
    return best;
  };
  return go(W);
}

function lisQuadratic(nums) {
  if (!nums.length) return 0;
  const dp = new Array(nums.length).fill(1);
  for (let i = 1; i < nums.length; i++)
    for (let j = 0; j < i; j++)
      if (nums[j] < nums[i]) dp[i] = Math.max(dp[i], dp[j] + 1);
  return Math.max(...dp);
}

function lisNLogN(nums) {
  const tails = [];
  for (const x of nums) {
    let lo = 0, hi = tails.length;
    while (lo < hi) { const mid = (lo+hi)>>1; if (tails[mid] < x) lo = mid+1; else hi = mid; }
    tails[lo] = x;
  }
  return tails.length;
}

function lisWithSequence(nums) {                 // reconstruct the actual LIS
  if (!nums.length) return [];
  const tails = [], tailIdx = [], prev = new Array(nums.length).fill(-1);
  for (let i = 0; i < nums.length; i++) {
    const x = nums[i];
    let lo = 0, hi = tails.length;
    while (lo < hi) { const mid = (lo+hi)>>1; if (tails[mid] < x) lo = mid+1; else hi = mid; }
    tails[lo] = x;
    tailIdx[lo] = i;
    prev[i] = lo > 0 ? tailIdx[lo-1] : -1;
  }
  const out = [];
  let k = tailIdx[tails.length - 1];
  while (k !== -1) { out.push(nums[k]); k = prev[k]; }
  return out.reverse();
}

function lcsLength(a, b) {
  const dp = Array.from({length:a.length+1}, () => new Array(b.length+1).fill(0));
  for (let i = 1; i <= a.length; i++)
    for (let j = 1; j <= b.length; j++)
      dp[i][j] = a[i-1] === b[j-1] ? dp[i-1][j-1]+1 : Math.max(dp[i-1][j], dp[i][j-1]);
  return dp[a.length][b.length];
}

function lcsOptimised(a, b) {
  if (b.length > a.length) [a, b] = [b, a];      // keep the shorter as the row
  let prev = new Array(b.length + 1).fill(0);
  for (let i = 1; i <= a.length; i++) {
    const cur = new Array(b.length + 1).fill(0);
    for (let j = 1; j <= b.length; j++)
      cur[j] = a[i-1] === b[j-1] ? prev[j-1]+1 : Math.max(prev[j], cur[j-1]);
    prev = cur;
  }
  return prev[b.length];
}

function lcsString(a, b) {
  const m = a.length, n = b.length;
  const dp = Array.from({length:m+1}, () => new Array(n+1).fill(0));
  for (let i = 1; i <= m; i++)
    for (let j = 1; j <= n; j++)
      dp[i][j] = a[i-1] === b[j-1] ? dp[i-1][j-1]+1 : Math.max(dp[i-1][j], dp[i][j-1]);
  let i = m, j = n, out = "";
  while (i > 0 && j > 0) {
    if (a[i-1] === b[j-1]) { out = a[i-1] + out; i--; j--; }
    else if (dp[i-1][j] >= dp[i][j-1]) i--;
    else j--;
  }
  return out;
}

function minDistance(a, b) {
  const m = a.length, n = b.length;
  const dp = Array.from({length:m+1}, () => new Array(n+1).fill(0));
  for (let i = 0; i <= m; i++) dp[i][0] = i;
  for (let j = 0; j <= n; j++) dp[0][j] = j;
  for (let i = 1; i <= m; i++)
    for (let j = 1; j <= n; j++)
      dp[i][j] = a[i-1] === b[j-1] ? dp[i-1][j-1]
        : 1 + Math.min(dp[i-1][j-1], dp[i-1][j], dp[i][j-1]);
  return dp[m][n];
}

State-machine DP — Best Time to Buy and Sell Stock with Cooldown (LC 309):

function maxProfitCooldown(prices) {
  if (!prices.length) return 0;
  let hold = -prices[0];                         // holding a stock
  let sold = -Infinity;                          // just sold (cooldown next)
  let rest = 0;                                  // free to buy
  for (let i = 1; i < prices.length; i++) {
    const prevHold = hold, prevSold = sold, prevRest = rest;
    hold = Math.max(prevHold, prevRest - prices[i]);   // keep, or buy from rest
    sold = prevHold + prices[i];                        // sell what we held
    rest = Math.max(prevRest, prevSold);                // stay free, or cooldown ends
  }
  return Math.max(sold, rest);                   // never end holding
}

function maxProfitBrute(prices) {                // exponential reference
  const go = (i, holding, cooldown) => {
    if (i >= prices.length) return 0;
    let best = go(i+1, holding, false);          // do nothing
    if (holding) best = Math.max(best, prices[i] + go(i+1, false, true));
    else if (!cooldown) best = Math.max(best, -prices[i] + go(i+1, true, false));
    return best;
  };
  return go(0, false, false);
}

Interval DP — Burst Balloons (LC 312):

function maxCoins(nums) {
  const a = [1, ...nums, 1];                     // virtual boundary balloons
  const n = a.length;
  const dp = Array.from({length:n}, () => new Array(n).fill(0));

  for (let len = 2; len < n; len++)              // interval length
    for (let lo = 0; lo + len < n; lo++) {
      const hi = lo + len;
      for (let k = lo + 1; k < hi; k++)          // k = the LAST balloon burst in (lo,hi)
        dp[lo][hi] = Math.max(dp[lo][hi],
          dp[lo][k] + a[lo]*a[k]*a[hi] + dp[k][hi]);
    }
  return dp[0][n-1];
}

function maxCoinsBrute(nums) {
  const go = arr => {
    if (!arr.length) return 0;
    let best = 0;
    for (let i = 0; i < arr.length; i++) {
      const left = i > 0 ? arr[i-1] : 1, right = i < arr.length-1 ? arr[i+1] : 1;
      const gain = left * arr[i] * right;
      best = Math.max(best, gain + go([...arr.slice(0,i), ...arr.slice(i+1)]));
    }
    return best;
  };
  return go(nums);
}

The key insight in Burst Balloons is choosing k as the balloon burst LAST, not first. If k is last, then when it pops its neighbours are exactly the interval boundaries a[lo] and a[hi] — which are known and fixed. Choosing k as the first burst leaves the neighbours depending on what was popped afterwards, and the subproblems stop being independent.

That reframing is what makes an apparently impossible problem a clean O(n³) DP, and it is the defining trick of interval DP: iterate by interval length so every subinterval is already solved.

🎯 Key Takeaways

  • DP needs optimal substructure and overlapping subproblems — the second is what distinguishes it from divide-and-conquer.
  • Defining the state is 90% of the work: write what dp[state] means as an English sentence before deriving any recurrence.
  • If the recurrence resists being written, the state is wrong — add a dimension or change its meaning rather than patching the transition.
  • LIS must be "longest subsequence ending at i", which makes the answer max(dp), not dp[n-1].
  • Write memoisation first in an interview — it follows mechanically from the brute-force recursion; convert to tabulation only if space or stack depth demands it.
  • Memoisation computes only reachable states, which wins when the state space is sparse; tabulation avoids recursion and enables space optimisation.
  • 0/1 knapsack iterates weight backward; unbounded iterates forward. One character switches between two correct algorithms for different problems.
  • Initialise minimisation DPs to Infinity — filling with 0 makes every Math.min return 0 and produces silently wrong answers.
  • Base cases carry meaning: dp[i][0] = i in edit distance says "delete every character".
  • Watch the off-by-one: dp[i] covers a[0..i-1], so compare a[i-1], not a[i].
  • The O(n log n) LIS maintains "smallest tail of an increasing subsequence of each length" — but that array is not the LIS, only its length is meaningful.
  • Space-optimise 2D to 1D when each row depends only on the previous — 2000× less memory, and often faster from cache locality.
  • Space optimisation destroys reconstruction; keep the full table or store parent pointers when the actual solution is required.
  • Reconstruct by walking the table backward from the final cell, following whichever predecessor produced the recorded value.
  • State-machine DP names each situation explicitly (hold / sold / rest), making illegal transitions impossible by construction.
  • Interval DP iterates by interval length; in Burst Balloons, choosing k as the last balloon burst is what makes the subproblems independent.
  • DP computes aggregates — counts, optima, booleans. If you need every solution listed, use backtracking; the output itself is exponential.
