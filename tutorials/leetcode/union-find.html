Union-Find Trees & Graphs

What you'll master: the disjoint-set structure and the two optimisations — path compression and union by rank — that together make operations effectively constant time, plus what α(n) actually means; when Union-Find beats DFS for connectivity, which is precisely when edges arrive incrementally; the component-count trick that turns "how many islands" into a decrement; the weighted and bipartite variants that carry extra information along the parent chain; the offline reversal technique for deletions, since Union-Find cannot un-merge; and Kruskal's algorithm as the classic application. Prerequisites: BFS / DFS, Big-O.

Part 1 — The Structure

Union-Find maintains a collection of disjoint sets under two operations: find (which set does x belong to?) and union (merge the sets containing x and y).

each set is a TREE; the root is the set's identity

     0     3        parent = [0, 0, 0, 3, 3]
    / \    |        find(1) → 0     find(4) → 3
   1   2   4        connected(1,2) → true    connected(1,4) → false

union(2,4):  attach one root to the other

     0
   / | \            parent = [0, 0, 0, 0, 3]
  1  2  3
        |
        4

class UnionFind {
  constructor(n) {
    this.parent = Array.from({length: n}, (_, i) => i);   // each node is its own root
    this.rank = new Array(n).fill(0);
    this.count = n;                                       // number of components
  }

  find(x) {
    while (this.parent[x] !== x) {
      this.parent[x] = this.parent[this.parent[x]];        // path halving
      x = this.parent[x];
    }
    return x;
  }

  union(x, y) {
    const rx = this.find(x), ry = this.find(y);
    if (rx === ry) return false;                           // already together
    if (this.rank[rx] < this.rank[ry]) { this.parent[rx] = ry; }
    else if (this.rank[rx] > this.rank[ry]) { this.parent[ry] = rx; }
    else { this.parent[ry] = rx; this.rank[rx]++; }
    this.count--;                                          // ← one fewer component
    return true;
  }

  connected(x, y) { return this.find(x) === this.find(y); }
}
🔑 The union return value is the most useful part of the whole structure. It returns false when the two nodes were already in the same set — which means the edge you just tried to add creates a cycle. That single boolean answers "does this graph have a cycle?", "is this a valid tree?", and "which edge is redundant?" without any extra code, and it is what Kruskal's algorithm uses to skip edges.
OperationMeaningComplexity
find(x)Root of x's setO(α(n)) amortised
union(x,y)Merge; false if already mergedO(α(n)) amortised
connected(x,y)Same set?O(α(n)) amortised
countNumber of disjoint setsO(1)

Part 2 — Why the Optimisations Matter

Without them, the trees degenerate into linked lists and every find is O(n):

naive union(1,0), union(2,1), union(3,2), ...

   0 ← 1 ← 2 ← 3 ← 4 ← ... ← n
   find(n) walks the entire chain  →  O(n)

Union by rank attaches the shorter tree under the taller one, bounding the height at O(log n). Path compression flattens the path during find, so repeated queries become nearly free:

before find(4):        after find(4) with full compression:

   0                        0
   |                      / | \
   1                     1  2  3
   |                            \
   2                             4      ← everyone points straight at the root
   |
   3
   |
   4
OptimisationsAmortised per operation
NeitherO(n)
Union by rank onlyO(log n)
Path compression onlyO(log n)
BothO(α(n))

α(n) is the inverse Ackermann function, and its practical meaning is worth stating plainly: α(n) ≤ 4 for any n that fits in the observable universe. It is not literally O(1), but treating it as constant is accurate for every real input.

The recursive find with full compression is shorter and equally valid:

find(x) {
  if (this.parent[x] !== x) this.parent[x] = this.find(this.parent[x]);
  return this.parent[x];
}
// full compression, but O(depth) stack — the iterative halving version is safer

Part 3 — When to Use It Instead of DFS

Both answer connectivity questions. The distinction is when the edges arrive.

SituationUseWhy
All edges known up front, one queryDFS/BFSSimpler; O(V+E) either way
Edges arrive one at a timeUnion-FindDFS would rerun from scratch per edge
Many "are these connected?" queriesUnion-FindO(α) per query after building
Need the component count as it evolvesUnion-FindMaintained incrementally
Need the actual path between nodesDFS/BFSUnion-Find does not store paths
Edges are removedNeither directlyProcess offline in reverse

Number of Islands II is the canonical example — land is added one cell at a time, and the answer is needed after each addition:

function numIslands2(m, n, positions) {          // LC 305
  const uf = new UnionFind(m * n);
  const isLand = new Array(m * n).fill(false);
  uf.count = 0;                                  // start with zero components
  const out = [];

  for (const [r, c] of positions) {
    const id = r * n + c;
    if (isLand[id]) { out.push(uf.count); continue; }   // ← duplicate positions
    isLand[id] = true;
    uf.count++;                                  // a new island appears

    for (const [dr, dc] of [[0,1],[1,0],[0,-1],[-1,0]]) {
      const nr = r + dr, nc = c + dc;
      if (nr >= 0 && nr < m && nc >= 0 && nc < n && isLand[nr * n + nc])
        uf.union(id, nr * n + nc);               // merging decrements count
    }
    out.push(uf.count);
  }
  return out;
}
// O(k·α) for k positions — DFS per step would be O(k·m·n)

The duplicate-position guard is required: adding land where land already exists must not increment the count, and it is a real test case.

Part 4 — Counting Components and Detecting Cycles

Initialising count = n and decrementing on every successful union means the component count is always available for free:

function countComponents(n, edges) {             // LC 323
  const uf = new UnionFind(n);
  for (const [a, b] of edges) uf.union(a, b);
  return uf.count;
}

function validTree(n, edges) {                   // LC 261
  if (edges.length !== n - 1) return false;      // ← a tree has exactly n-1 edges
  const uf = new UnionFind(n);
  for (const [a, b] of edges) if (!uf.union(a, b)) return false;   // cycle
  return true;
}

The two checks together are what define a tree: exactly n−1 edges and no cycle implies connected. Checking only one is insufficient — n−1 edges with a cycle leaves a disconnected component, and acyclic with fewer edges is a forest.

function findRedundantConnection(edges) {        // LC 684
  const uf = new UnionFind(edges.length + 1);
  for (const [a, b] of edges)
    if (!uf.union(a, b)) return [a, b];          // ← the first edge closing a cycle
  return [];
}

Part 5 — Carrying Information Along the Chain

A weighted (or "relative") Union-Find stores each node's relationship to its parent, and the relationship to the root accumulates during find.

function calcEquation(equations, values, queries) {   // LC 399
  const parent = new Map(), weight = new Map();

  const add = x => { if (!parent.has(x)) { parent.set(x, x); weight.set(x, 1); } };

  const find = x => {
    if (parent.get(x) !== x) {
      const root = find(parent.get(x));
      weight.set(x, weight.get(x) * weight.get(parent.get(x)));   // ← accumulate
      parent.set(x, root);
    }
    return parent.get(x);
  };

  for (let i = 0; i < equations.length; i++) {
    const [a, b] = equations[i];
    add(a); add(b);
    const ra = find(a), rb = find(b);
    if (ra !== rb) {
      parent.set(ra, rb);
      weight.set(ra, values[i] * weight.get(b) / weight.get(a));  // ratio algebra
    }
  }

  return queries.map(([a, b]) => {
    if (!parent.has(a) || !parent.has(b) || find(a) !== find(b)) return -1;
    return weight.get(a) / weight.get(b);
  });
}

The bipartite variant uses the same idea with parity instead of ratios — useful for "can these be split into two groups" problems. The alternative is a doubled structure:

// "x and y are ENEMIES": union(x, y+n) and union(y, x+n)
// a contradiction appears when find(x) === find(x+n)
const uf = new UnionFind(2 * n);
for (const [x, y] of dislikes) {
  if (uf.connected(x, y)) return false;          // forced into the same group
  uf.union(x, y + n);
  uf.union(y, x + n);
}

Part 6 — What It Cannot Do

Union-Find has no split operation. Merging is irreversible, because the tree structure records only the current parent — undoing a union would require knowing the shape before it.

edges removed over time?  →  process the queries OFFLINE, in REVERSE

original:  remove e1, query, remove e2, query, remove e3, query
reversed:  start from the FINAL graph, then ADD e3, e2, e1
           each addition is a union; record answers, then reverse the output

That reversal trick converts deletions into insertions and is the standard answer to any "connectivity with removals" problem — but it requires all queries in advance, so it does not work online.

Kruskal's minimum spanning tree is the classic application, and it is Union-Find plus a sort:

function minimumCost(n, connections) {           // LC 1135
  connections.sort((a, b) => a[2] - b[2]);       // cheapest first
  const uf = new UnionFind(n + 1);
  let total = 0, used = 0;
  for (const [a, b, cost] of connections) {
    if (uf.union(a, b)) { total += cost; used++; }   // ← skips cycle-forming edges
  }
  return used === n - 1 ? total : -1;            // -1 if not connected
}
// O(E log E) — dominated by the sort

❌ Comparing parent[x] === parent[y] instead of calling find. It looks equivalent and is often almost right — immediately after a union the two nodes do share a parent, so small tests pass. But parent holds the immediate parent, not the root, so once trees grow past depth 1 the comparison silently reports "not connected" for nodes that are in the same set. The bug produces plausible component counts that are too high, and there is no crash to point at it.

✅ Always compare roots: find(x) === find(y). The root is the set's identity; the immediate parent is an implementation detail of the tree's current shape. This also matters inside union — attaching parent[x] = y rather than parent[find(x)] = find(y) corrupts the structure by re-parenting a non-root node, which detaches its whole subtree.

Interview Questions

Beginner: What is Union-Find and what are its operations?

It is a data structure for maintaining disjoint sets under merging, supporting two operations: find(x) returns the identity of x's set, and union(x,y) merges two sets.

class UnionFind {
  constructor(n) {
    this.parent = Array.from({length: n}, (_, i) => i);
    this.rank = new Array(n).fill(0);
    this.count = n;
  }
  find(x) {
    while (this.parent[x] !== x) {
      this.parent[x] = this.parent[this.parent[x]];   // path halving
      x = this.parent[x];
    }
    return x;
  }
  union(x, y) {
    const rx = this.find(x), ry = this.find(y);
    if (rx === ry) return false;
    if (this.rank[rx] < this.rank[ry]) this.parent[rx] = ry;
    else if (this.rank[rx] > this.rank[ry]) this.parent[ry] = rx;
    else { this.parent[ry] = rx; this.rank[rx]++; }
    this.count--;
    return true;
  }
}

Each set is represented as a tree, and the root is the set's identity. Two nodes are in the same set exactly when they share a root — which is why connectivity is find(x) === find(y) and never a comparison of immediate parents.

The boolean return from union is the most useful detail: false means the nodes were already connected, so the edge just offered would create a cycle. That is how cycle detection, redundant-edge finding and Kruskal's algorithm all get implemented for free.

Maintaining count — start at n, decrement on each successful union — gives the number of connected components in O(1) at any moment.

The typical uses are connectivity queries, counting components, cycle detection in undirected graphs, and Kruskal's MST.

Beginner: Count the number of connected components in an undirected graph.

Start with n components and decrement each time two distinct components merge.

function countComponents(n, edges) {
  const uf = new UnionFind(n);
  for (const [a, b] of edges) uf.union(a, b);
  return uf.count;
}
// O(E·α(n)) ≈ O(E)

n = 5, edges = [[0,1],[1,2],[3,4]]

start:      count = 5    {0} {1} {2} {3} {4}
union(0,1): count = 4    {0,1} {2} {3} {4}
union(1,2): count = 3    {0,1,2} {3} {4}
union(3,4): count = 2    {0,1,2} {3,4}
→ 2 ✓

The decrement must be conditional on an actual merge. If the edge connects two nodes already in the same set, no component disappeared — which is why union returns a boolean and the count is decremented inside it rather than by the caller on every call.

The DFS alternative is equally valid here: loop over unvisited nodes, run a traversal from each, count the starts. Both are O(V + E).

DFSUnion-Find
All edges known up frontSimplerFine
Edges arrive incrementallyRerun everything per edgeNatural
Many connectivity queriesO(V+E) eachO(α) each

So I would use DFS if the graph is given once, and Union-Find if edges stream in or the count is needed repeatedly as the graph evolves — which is exactly the shape of Number of Islands II.

Mid: Explain path compression and union by rank, and their effect on complexity.

Both attack the same failure: without them, trees degenerate into chains and every find walks O(n) nodes.

naive: union(1,0), union(2,1), union(3,2), ...
   0 ← 1 ← 2 ← 3 ← ... ← n        find(n) is O(n)

Union by rank attaches the shorter tree beneath the taller one. Rank is an upper bound on height, and it only increases when two equal-rank trees merge — which bounds the height at O(log n).

if (rank[rx] < rank[ry]) parent[rx] = ry;
else if (rank[rx] > rank[ry]) parent[ry] = rx;
else { parent[ry] = rx; rank[rx]++; }     // only here does rank grow

Path compression flattens the path to the root during find, so subsequent queries on those nodes are O(1):

   0            find(4)          0
   |            ────────▶      / | \
   1                          1  2  3
   |                                 \
   2                                  4
   |
   3
   |
   4
OptimisationsAmortised
NeitherO(n)
Rank onlyO(log n)
Compression onlyO(log n)
BothO(α(n))

α(n) is the inverse Ackermann function, which is ≤ 4 for any n up to roughly 2^65536. It is not constant in theory, but treating it as constant is correct for every input that can physically exist.

Two implementation notes worth mentioning: the iterative "path halving" version (parent[x] = parent[parent[x]]) achieves the same asymptotic bound as full recursive compression while avoiding a deep call stack; and union by size is an equally valid alternative to rank, with the bonus that the set size is then directly available.

Mid: Determine whether a given set of edges forms a valid tree.

A graph on n nodes is a tree exactly when it has n−1 edges and no cycle — those two conditions together imply connectivity.

function validTree(n, edges) {
  if (edges.length !== n - 1) return false;
  const uf = new UnionFind(n);
  for (const [a, b] of edges) if (!uf.union(a, b)) return false;
  return true;
}
// O(n·α(n))

Both checks are necessary, and each rules out a different failure:

InputEdgesCycle?Verdict
n=4, [[0,1],[1,2],[2,3]]3 = n−1 ✓No ✓Tree
n=4, [[0,1],[1,2],[0,2]]3 = n−1 ✓YesNot a tree — node 3 is isolated
n=4, [[0,1],[2,3]]2 ≠ n−1NoForest, not a tree

The middle row is the instructive one: it has the right number of edges but wastes one on a cycle, which necessarily leaves some node unreachable. That is why "n−1 edges and acyclic" implies connected — there are exactly enough edges, and none is squandered.

The union return value does the cycle detection — false means both endpoints were already in the same component, so this edge closes a loop.

Alternatively, skip the edge-count check and verify uf.count === 1 at the end, which tests connectivity directly. Both are correct; the edge-count version fails faster on obviously wrong input.

The DFS alternative checks for a cycle with a parent-aware traversal and then confirms all nodes were visited. Same complexity — I would choose Union-Find here because the cycle check is a single boolean rather than a traversal with a parent parameter.

Senior: Solve Number of Islands II — land is added one cell at a time.

The incremental nature is what makes Union-Find the right choice: re-running DFS after each addition would be O(k·m·n), while Union-Find is O(k·α).

function numIslands2(m, n, positions) {
  const uf = new UnionFind(m * n);
  uf.count = 0;                                  // no land initially
  const isLand = new Array(m * n).fill(false);
  const DIRS = [[0,1],[1,0],[0,-1],[-1,0]];
  const out = [];

  for (const [r, c] of positions) {
    const id = r * n + c;
    if (isLand[id]) { out.push(uf.count); continue; }   // duplicate — no change
    isLand[id] = true;
    uf.count++;                                  // a new island

    for (const [dr, dc] of DIRS) {
      const nr = r + dr, nc = c + dc;
      if (nr >= 0 && nr < m && nc >= 0 && nc < n && isLand[nr * n + nc])
        uf.union(id, nr * n + nc);               // each merge decrements count
    }
    out.push(uf.count);
  }
  return out;
}

The count bookkeeping is the crux: adding land creates one new island, and each successful merge with an existing neighbour removes one. A cell touching three separate islands increments once and decrements three times, netting −2 — which is exactly right.

m=3, n=3, positions = [[0,0],[0,1],[1,2],[2,1]]

[0,0]: +1 → 1                            1
[0,1]: +1, merge with [0,0] → 1          1
[1,2]: +1, no neighbours → 2             2
[2,1]: +1, no land neighbours → 3        3
→ [1,1,2,3] ✓

Two details that are real test cases: duplicate positions must not increment the count, and isLand must be checked before unioning — otherwise a cell would merge with water, corrupting the structure.

The 2D-to-1D mapping id = r*n + c is what lets a flat Union-Find serve a grid, and it is worth stating explicitly since mixing up m and n here is a common slip.

The complexity comparison is the reason for the whole approach: for k = 10⁴ additions on a 10³×10³ grid, DFS-per-step is 10¹⁰ operations while Union-Find is about 4×10⁴.

Senior: Handle edge deletions — connectivity queries where edges are removed over time.

Union-Find cannot un-merge: the structure records only current parent pointers, so undoing a union would require the shape before it. The standard answer is to reverse time.

Given: start with all edges, then a sequence of
       "remove edge e" and "are u,v connected?" operations

Process OFFLINE, in reverse:
  1. apply ALL deletions first → the final graph
  2. build Union-Find on what remains
  3. walk the operations BACKWARDS:
       - a deletion becomes an ADDITION (a union)
       - a query is answered against the current state
  4. reverse the collected answers

function connectivityWithDeletions(n, edges, ops) {
  const removed = new Set();
  for (const op of ops) if (op.type === "remove") removed.add(op.edgeIndex);

  const uf = new UnionFind(n);
  edges.forEach(([a, b], i) => { if (!removed.has(i)) uf.union(a, b); });

  const answers = [];
  for (let i = ops.length - 1; i >= 0; i--) {
    const op = ops[i];
    if (op.type === "remove") {
      const [a, b] = edges[op.edgeIndex];
      uf.union(a, b);                            // ← re-adding, going backwards
    } else {
      answers.push(uf.connected(op.u, op.v));
    }
  }
  return answers.reverse();
}
// O((E + Q)·α)

The requirement is that all operations are known in advance — this is an offline algorithm. It does not work when queries must be answered as they arrive.

For genuinely online deletion, the options are materially heavier:

ApproachComplexityNote
Offline reversalO((E+Q)·α)Use when possible
Link-cut treesO(log n) amortisedComplex; forests only
Euler tour treesO(log n)Also forest-only
Rebuild from scratchO(V+E) per deletionFine if deletions are rare

A related technique worth knowing is rollback Union-Find: skip path compression, keep a stack of the changes each union made, and undo them in LIFO order. That supports backtracking-style undo — which is what "dynamic connectivity offline" via segment-tree-on-time uses — at O(log n) per operation because compression must be sacrificed.

In an interview I would state the limitation first — "unions are irreversible, so if deletions are involved I need all the operations up front" — because recognising that constraint is the actual insight being tested.

class UnionFind {

class ReferenceSets {                            // O(n) per op, obviously correct
  constructor(n) { this.sets = Array.from({length:n}, (_, i) => new Set([i])); }
  find(x) { return this.sets.findIndex(s => s.has(x)); }
  union(x, y) {
    const i = this.find(x), j = this.find(y);
    if (i === j) return false;
    for (const v of this.sets[j]) this.sets[i].add(v);
    this.sets.splice(j, 1);
    return true;
  }
  connected(x, y) { return this.find(x) === this.find(y); }
  get count() { return this.sets.length; }
}

function countComponentsDFS(n, edges) {
  const adj = Array.from({length:n}, () => []);
  for (const [a,b] of edges) { adj[a].push(b); adj[b].push(a); }
  const seen = new Array(n).fill(false);
  let c = 0;
  for (let i = 0; i < n; i++) {
    if (seen[i]) continue;
    c++;
    const st = [i];
    while (st.length) {
      const x = st.pop();
      if (seen[x]) continue;
      seen[x] = true;
      for (const nb of adj[x]) if (!seen[nb]) st.push(nb);
    }
  }
  return c;
}

4 (medium): Implement Number of Islands II.
Solution 
function numIslands2(m, n, positions) {
  const uf = new UnionFind(m * n);
  uf.count = 0;
  const isLand = new Array(m * n).fill(false);
  const DIRS = [[0,1],[1,0],[0,-1],[-1,0]];
  const out = [];

  for (const [r, c] of positions) {
    const id = r * n + c;
    if (isLand[id]) { out.push(uf.count); continue; }
    isLand[id] = true;
    uf.count++;
    for (const [dr, dc] of DIRS) {
      const nr = r + dr, nc = c + dc;
      if (nr >= 0 && nr < m && nc >= 0 && nc < n && isLand[nr * n + nc])
        uf.union(id, nr * n + nc);
    }
    out.push(uf.count);
  }
  return out;
}

function numIslandsBrute(m, n, positions) {      // rebuild and DFS each step
  const grid = Array.from({length:m}, () => new Array(n).fill(0));
  const out = [];
  for (const [r,c] of positions) {
    grid[r][c] = 1;
    const seen = Array.from({length:m}, () => new Array(n).fill(false));
    let count = 0;
    for (let i = 0; i < m; i++) for (let j = 0; j < n; j++) {
      if (grid[i][j] !== 1 || seen[i][j]) continue;
      count++;
      const st = [[i,j]];
      while (st.length) {
        const [x,y] = st.pop();
        if (x<0||x>=m||y<0||y>=n||grid[x][y]!==1||seen[x][y]) continue;
        seen[x][y] = true;
        st.push([x+1,y],[x-1,y],[x,y+1],[x,y-1]);
      }
    }
    out.push(count);
  }
  return out;
}

5 (hard): Implement weighted Union-Find for Evaluate Division.
Solution

Each node stores its value relative to its parent; find multiplies the weights along the path while compressing it.

function calcEquation(equations, values, queries) {
  const parent = new Map(), weight = new Map();

  const add = x => { if (!parent.has(x)) { parent.set(x, x); weight.set(x, 1); } };

  const find = x => {
    if (parent.get(x) !== x) {
      const p = parent.get(x);
      const root = find(p);
      weight.set(x, weight.get(x) * weight.get(p));   // x/root = (x/p) * (p/root)
      parent.set(x, root);
    }
    return parent.get(x);
  };

  for (let i = 0; i < equations.length; i++) {
    const [a, b] = equations[i];
    add(a); add(b);
    const ra = find(a), rb = find(b);
    if (ra !== rb) {
      parent.set(ra, rb);
      // want a/b = values[i]; we have a/ra and b/rb known
      weight.set(ra, values[i] * weight.get(b) / weight.get(a));
    }
  }

  return queries.map(([a, b]) => {
    if (!parent.has(a) || !parent.has(b)) return -1;
    if (find(a) !== find(b)) return -1;
    return weight.get(a) / weight.get(b);
  });
}

function calcEquationBFS(equations, values, queries) {
  const g = new Map();
  const link = (a,b,v) => { if (!g.has(a)) g.set(a, new Map()); g.get(a).set(b, v); };
  equations.forEach(([a,b], i) => { link(a,b,values[i]); link(b,a,1/values[i]); });

  return queries.map(([a,b]) => {
    if (!g.has(a) || !g.has(b)) return -1;
    if (a === b) return 1;
    const seen = new Set([a]);
    const q = [[a, 1]];
    let h = 0;
    while (h < q.length) {
      const [node, prod] = q[h++];
      if (node === b) return prod;
      for (const [nb, w] of g.get(node) || [])
        if (!seen.has(nb)) { seen.add(nb); q.push([nb, prod * w]); }
    }
    return -1;
  });
}

The weight algebra during union deserves a trace. We know a/ra and b/rb, and we are told a/b = v. Attaching ra under rb requires ra/rb:

ra/rb = (ra/a) × (a/b) × (b/rb)
      = (1 / weight[a]) × v × weight[b]
      = v × weight[b] / weight[a]        ← exactly the line in the code

Path compression must update the weight before reassigning the parent, because the new weight is computed from the old parent's weight — swapping those two lines silently produces wrong ratios that still look plausible.

Union-Find beats BFS here when there are many queries: BFS is O(V+E) per query, while after building, each query is O(α) — and the compression means repeated queries on the same variables become essentially free.

6 (hard): Kruskal's MST and offline deletion handling.
Solution 
function kruskal(n, edges) {                     // edges: [u, v, weight]
  const sorted = [...edges].sort((a,b) => a[2] - b[2]);
  const uf = new UnionFind(n);
  const chosen = [];
  let total = 0;
  for (const [u, v, w] of sorted) {
    if (uf.union(u, v)) { chosen.push([u,v,w]); total += w; }
  }
  return uf.count === 1 ? { total, chosen } : { total: -1, chosen: [] };
}

function primReference(n, edges) {               // independent MST for cross-checking
  const adj = Array.from({length:n}, () => []);
  for (const [u,v,w] of edges) { adj[u].push([v,w]); adj[v].push([u,w]); }
  const inTree = new Array(n).fill(false);
  const dist = new Array(n).fill(Infinity);
  dist[0] = 0;
  let total = 0;
  for (let it = 0; it < n; it++) {
    let best = -1;
    for (let i = 0; i < n; i++) if (!inTree[i] && (best === -1 || dist[i] < dist[best])) best = i;
    if (dist[best] === Infinity) return -1;      // disconnected
    inTree[best] = true;
    total += dist[best];
    for (const [nb, w] of adj[best]) if (!inTree[nb] && w < dist[nb]) dist[nb] = w;
  }
  return total;
}

Now the offline-deletion technique. Answer connectivity queries interleaved with edge removals by processing everything backwards:

function connectivityWithDeletions(n, edges, ops) {
  const removed = new Set();
  for (const op of ops) if (op.type === "remove") removed.add(op.edge);

  const uf = new UnionFind(n);
  edges.forEach(([a,b], i) => { if (!removed.has(i)) uf.union(a,b); });

  const answers = [];
  for (let i = ops.length - 1; i >= 0; i--) {
    const op = ops[i];
    if (op.type === "remove") { const [a,b] = edges[op.edge]; uf.union(a,b); }
    else answers.push(uf.connected(op.u, op.v));
  }
  return answers.reverse();
}

function bruteConnectivity(n, edges, ops) {      // rebuild after every removal
  const alive = new Set(edges.map((_, i) => i));
  const out = [];
  for (const op of ops) {
    if (op.type === "remove") { alive.delete(op.edge); continue; }
    const uf = new UnionFind(n);
    for (const i of alive) uf.union(edges[i][0], edges[i][1]);
    out.push(uf.connected(op.u, op.v));
  }
  return out;
}

The technique's constraint is worth restating: it requires every operation in advance, because the whole point is to run time backwards. For an online setting — answering each query before seeing the next — Union-Find alone is insufficient and link-cut trees or Euler tour trees are needed.

🎯 Key Takeaways

  • Union-Find maintains disjoint sets as trees; the root is the set's identity, so connectivity is always find(x) === find(y), never a parent comparison.
  • In union, attach root to root — parent[find(x)] = find(y) — since re-parenting a non-root detaches its entire subtree.
  • The boolean returned by union is the workhorse: false means the edge closes a cycle, which powers cycle detection, redundant-edge finding and Kruskal's.
  • Path compression plus union by rank gives O(α(n)) amortised, where α(n) ≤ 4 for any physically realisable input.
  • Either optimisation alone gives O(log n); neither gives O(n), which is a 100× slowdown even on modest chains.
  • Iterative path halving achieves the same bound as recursive full compression while avoiding stack overflow.
  • Maintain count by decrementing inside union only on a real merge — decrementing per edge over-counts.
  • Use DFS when all edges are known and one answer is needed; use Union-Find when edges arrive incrementally — the incremental case is ~2000× faster.
  • Union-Find cannot produce paths, only set membership; use BFS/DFS when the actual route matters.
  • A valid tree needs both n−1 edges and no cycle — either check alone is insufficient.
  • Number of Islands II needs a duplicate-position guard, or the component count is permanently inflated.
  • Map a grid into a flat structure with id = r*cols + c.
  • Weighted Union-Find carries a value relative to the parent, accumulated during find — update the weight before reassigning the parent.
  • Bipartite/enemy problems use a doubled structure: union(x, y+n) and union(y, x+n), with a contradiction when find(x) === find(x+n).
  • Unions are irreversible — handle deletions by processing all operations offline in reverse, turning removals into additions.
  • Rollback Union-Find supports undo by dropping path compression and keeping a change stack, at O(log n) per operation.
  • Kruskal's MST is a sort plus Union-Find, with the union return value skipping cycle-forming edges.
