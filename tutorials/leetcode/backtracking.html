Backtracking Advanced Pattern

What you'll master: the choose–explore–unchoose skeleton that every backtracking problem shares, and why the undo step is what makes it "backtracking" rather than plain recursion; the three structural variants — subsets, permutations, combinations — and the single parameter that distinguishes them; duplicate handling, which is the most common source of wrong answers and has exactly one correct idiom; pruning, which is the difference between a solution that passes and one that times out; and the constraint-satisfaction problems (N-Queens, Sudoku, Word Search) where the incremental validity check is the whole design. Prerequisites: BFS / DFS, Big-O.

Part 1 — The Skeleton

Backtracking explores a decision tree. At each node you make a choice, recurse, then undo the choice so the next branch starts from a clean state.

function backtrack(state, choices) {
  if (isComplete(state)) { record(state); return; }

  for (const choice of choices) {
    if (!isValid(state, choice)) continue;       // PRUNE

    apply(state, choice);                        // CHOOSE
    backtrack(state, nextChoices(choice));       // EXPLORE
    undo(state, choice);                         // UNCHOOSE  ← the "backtracking"
  }
}

                      []
            /          |          \
          [1]         [2]         [3]
         /   \         |
     [1,2]  [1,3]   [2,3]          each edge is a CHOICE
       |                           each leaf is a complete state
    [1,2,3]                        returning UP is the UNDO
🔑 The undo step exists because the state is shared across branches. A single array is mutated as you descend and must be restored on the way back up, or the next sibling branch inherits corruption from the previous one. The alternative — passing a fresh copy at every level — removes the need to undo but costs O(n) per node and turns an O(2ⁿ) algorithm into O(n·2ⁿ). Mutate-and-restore is why backtracking is memory-efficient, and forgetting the restore is the defining bug of this pattern.
function subsets(nums) {                         // LC 78
  const out = [], path = [];

  const go = start => {
    out.push([...path]);                         // ← COPY: path keeps mutating
    for (let i = start; i < nums.length; i++) {
      path.push(nums[i]);                        // choose
      go(i + 1);                                 // explore
      path.pop();                                // unchoose
    }
  };

  go(0);
  return out;
}
// O(n·2ⁿ) time — 2ⁿ subsets, each costing O(n) to copy

out.push([...path]) must copy. Pushing path itself stores a reference to an array that continues changing, so every entry in out ends up identical — usually empty.

// PERMUTATIONS — every position considers every unused element
function permute(nums) {                         // LC 46
  const out = [], path = [], used = new Array(nums.length).fill(false);

  const go = () => {
    if (path.length === nums.length) { out.push([...path]); return; }
    for (let i = 0; i < nums.length; i++) {      // ← from 0 every time
      if (used[i]) continue;
      used[i] = true;  path.push(nums[i]);
      go();
      path.pop();      used[i] = false;          // ← undo BOTH
    }
  };

  go();
  return out;
}
// O(n·n!) time

// COMBINATION SUM — reuse allowed, so recurse with i rather than i+1
function combinationSum(candidates, target) {    // LC 39
  const out = [], path = [];
  candidates.sort((a, b) => a - b);              // enables the pruning break

  const go = (start, remain) => {
    if (remain === 0) { out.push([...path]); return; }
    for (let i = start; i < candidates.length; i++) {
      if (candidates[i] > remain) break;         // ← PRUNE: sorted, so all later are worse
      path.push(candidates[i]);
      go(i, remain - candidates[i]);             // ← i, not i+1: reuse the same element
      path.pop();
    }
  };

  go(0, target);
  return out;
}

The start parameter is what prevents duplicate combinations. Without it, [2,3] and [3,2] would both be generated — which is correct for permutations and wrong for combinations.

Part 3 — Duplicates: One Correct Idiom

When the input contains repeated values, the naive recursion produces duplicate results. The fix is always the same two lines: sort, then skip repeats at the same tree level.

function subsetsWithDup(nums) {                  // LC 90
  nums.sort((a, b) => a - b);                    // ← 1. SORT so duplicates are adjacent
  const out = [], path = [];

  const go = start => {
    out.push([...path]);
    for (let i = start; i < nums.length; i++) {
      if (i > start && nums[i] === nums[i-1]) continue;   // ← 2. skip at the SAME level
      path.push(nums[i]);
      go(i + 1);
      path.pop();
    }
  };

  go(0);
  return out;
}

nums = [1,2,2]

i > start is the key: at a given level, the FIRST occurrence is used,
later identical values are skipped

level 0, start=0:  i=0 (1) ✓    i=1 (2) ✓    i=2 (2) skip — same level as i=1
level 1, start=2:  i=2 (2) ✓    ← NOT skipped: i === start, this is a deeper level

→ [], [1], [1,2], [1,2,2], [2], [2,2]     no duplicates ✓

i > start is doing precise work. It permits a duplicate to be chosen deeper in the tree (extending [2] to [2,2]) while forbidding it as a sibling alternative at the same level (which would regenerate [2]).

For permutations with duplicates, the condition uses the used array instead:

function permuteUnique(nums) {                   // LC 47
  nums.sort((a, b) => a - b);
  const out = [], path = [], used = new Array(nums.length).fill(false);

  const go = () => {
    if (path.length === nums.length) { out.push([...path]); return; }
    for (let i = 0; i < nums.length; i++) {
      if (used[i]) continue;
      if (i > 0 && nums[i] === nums[i-1] && !used[i-1]) continue;   // ← the idiom
      used[i] = true; path.push(nums[i]);
      go();
      path.pop(); used[i] = false;
    }
  };

  go();
  return out;
}

!used[i-1] means the previous identical value is not currently in the path — so we are at a sibling position, and using this duplicate would repeat a branch already explored. If used[i-1] were true, we would be extending a path that already contains the first copy, which is legitimate.

Part 4 — Pruning Is the Difference Between Pass and TLE

Backtracking is exponential by nature. Pruning does not change the asymptotic bound, but it routinely changes runtime by orders of magnitude.

Sort + break on exceeding targetPositive values, sum targetCuts entire subtrees
Remaining-capacity checkFixed-length resultsAbandons paths that cannot complete
Feasibility test before recursingConstraint problemsRejects at depth 1 instead of depth n
Symmetry breakingInterchangeable choicesHalves the search
Memoisation of failuresRepeated subproblemsTurns exponential into polynomial
// Combinations: stop when not enough elements remain to finish
function combine(n, k) {                         // LC 77
  const out = [], path = [];
  const go = start => {
    if (path.length === k) { out.push([...path]); return; }
    const need = k - path.length;
    for (let i = start; i <= n - need + 1; i++) {   // ← PRUNE the tail of the range
      path.push(i);
      go(i + 1);
      path.pop();
    }
  };
  go(1);
  return out;
}

n = 20, k = 3

without the bound:  loops to 20 at every level, then fails to complete
with the bound:     level 0 loops only to 18 — no point starting at 19
                    ~40% fewer recursive calls

Word Search shows the incremental-validity style of pruning — reject as soon as the partial path is invalid rather than at the end:

function exist(board, word) {                    // LC 79
  const R = board.length, C = board[0].length;

  const go = (r, c, k) => {
    if (k === word.length) return true;
    if (r < 0 || r >= R || c < 0 || c >= C) return false;
    if (board[r][c] !== word[k]) return false;   // ← reject IMMEDIATELY

    const saved = board[r][c];
    board[r][c] = "#";                           // mark visited in place
    const found = go(r+1,c,k+1) || go(r-1,c,k+1) || go(r,c+1,k+1) || go(r,c-1,k+1);
    board[r][c] = saved;                         // ← restore
    return found;
  };

  for (let r = 0; r < R; r++)
    for (let c = 0; c < C; c++)
      if (go(r, c, 0)) return true;
  return false;
}

Part 5 — Constraint Satisfaction

N-Queens and Sudoku share a design: maintain auxiliary structures so validity is O(1) rather than a scan.

function solveNQueens(n) {                       // LC 51
  const out = [];
  const cols = new Set(), diag = new Set(), anti = new Set();
  const queens = [];

  const go = row => {
    if (row === n) { out.push(render(queens, n)); return; }
    for (let c = 0; c < n; c++) {
      if (cols.has(c) || diag.has(row - c) || anti.has(row + c)) continue;   // O(1) check

      cols.add(c); diag.add(row - c); anti.add(row + c); queens.push(c);
      go(row + 1);
      cols.delete(c); diag.delete(row - c); anti.delete(row + c); queens.pop();
    }
  };

  go(0);
  return out;
}

diagonal identity:  cells on the same ↘ diagonal share (row - col)
                    cells on the same ↙ diagonal share (row + col)

   col:  0  1  2  3        row-col:  0 -1 -2 -3
row 0                                1  0 -1 -2
row 1                                2  1  0 -1
row 2                                3  2  1  0

Placing one queen per row is itself a pruning decision — it makes row conflicts impossible by construction, reducing the search from C(n², n) placements to n per row.

Sudoku uses the same idea with three constraint sets, and adds a powerful heuristic:

box index = Math.floor(r / 3) * 3 + Math.floor(c / 3)

// MRV heuristic: always fill the cell with the FEWEST legal candidates first
// — it fails fast, pruning far more of the tree than left-to-right order

The last two rows are the important distinction. Backtracking enumerates; if the question asks only for a count or an optimum, enumerating is exponential where DP is polynomial. "How many ways to climb stairs" is DP, not backtracking, even though a decision tree exists.

❌ Pushing the working array into the results instead of a copy. out.push(path) stores a reference to the very array the recursion keeps mutating, so every entry in out points at the same object — and once the recursion unwinds and pops everything, all of them read as empty. The code looks right, the recursion is correct, and the output is a list of identical empty arrays with the correct length, which makes it look like a subtle logic bug rather than an aliasing one.

✅ Copy at the moment of recording: out.push([...path]). The snapshot must be taken while the state is valid, because path is deliberately shared and mutated — that sharing is what makes backtracking O(1) per step instead of O(n). For nested structures use a deeper copy (path.map(row => [...row]) for a board), since a shallow spread still aliases the inner arrays.

Beginner: Generate all subsets of a set of distinct integers. 
function subsets(nums) {
  const out = [], path = [];
  const go = start => {
    out.push([...path]);                         // every node is a valid subset
    for (let i = start; i < nums.length; i++) {
      path.push(nums[i]);                        // choose
      go(i + 1);                                 // explore
      path.pop();                                // unchoose
    }
  };
  go(0);
  return out;
}
// O(n·2ⁿ) time, O(n) recursion depth

nums = [1,2,3]

                []
        /       |       \
      [1]      [2]      [3]
     /   \      |
  [1,2] [1,3] [2,3]
    |
 [1,2,3]

→ [], [1], [1,2], [1,2,3], [1,3], [2], [2,3], [3]     8 = 2³ ✓

Every node is recorded, not just the leaves — a subset can have any size, so the result is pushed on entry rather than at a termination condition.

The start parameter prevents duplicates by ensuring indices only move forward: [1,2] is generated but [2,1] never is, because once we descend past index 1 we cannot return to index 0.

The copy is essential. path is mutated throughout; pushing it directly stores a reference that ends up empty when the recursion unwinds.

The iterative alternative is worth mentioning — each new element doubles the result set:

function subsetsIterative(nums) {
  let out = [[]];
  for (const x of nums) out = [...out, ...out.map(s => [...s, x])];
  return out;
}

Same complexity, no recursion. There is also a bitmask version: iterate mask from 0 to 2ⁿ−1 and include element i when bit i is set — see Bit Manipulation.

The single difference is the loop start. Starting at start means indices only move forward, so each element is considered once and order is irrelevant. Starting at 0 with a used guard means every position considers every remaining element, so [1,2] and [2,1] are distinct.

Both mutations must be undone. Popping path but leaving used[i] = true is a common bug — it silently removes elements from consideration in sibling branches, producing far too few results.

The swap-based alternative avoids the used array:

const go = k => {
  if (k === nums.length) { out.push([...nums]); return; }
  for (let i = k; i < nums.length; i++) {
    [nums[k], nums[i]] = [nums[i], nums[k]];
    go(k + 1);
    [nums[k], nums[i]] = [nums[i], nums[k]];     // swap back
  }
};

It uses O(1) extra space but mutates the input and does not extend cleanly to the duplicate-handling variant, which is why the used version is usually preferable.

Mid: Handle duplicates — generate all unique subsets from an array with repeated values.

Two lines: sort so duplicates are adjacent, then skip repeated values at the same tree level.

function subsetsWithDup(nums) {
  nums.sort((a,b) => a - b);
  const out = [], path = [];
  const go = start => {
    out.push([...path]);
    for (let i = start; i < nums.length; i++) {
      if (i > start && nums[i] === nums[i-1]) continue;
      path.push(nums[i]);
      go(i + 1);
      path.pop();
    }
  };
  go(0);
  return out;
}

i > start is the precise condition, and understanding why it is not i > 0 is the whole question:

nums = [1,2,2]

level 0 (start=0):  i=0 (1) ✓
                    i=1 (2) ✓
                    i=2 (2) → i > start and equal to previous → SKIP
                              (choosing it here would regenerate the [2] branch)

level 1 (start=2):  i=2 (2) → i === start → ALLOWED
                              (this extends [2] to [2,2], a genuinely new subset)

→ [], [1], [1,2], [1,2,2], [2], [2,2]   ✓ no duplicates

With i > 0 instead, the second 2 would be skipped even when it is the first choice at its level — so [2,2] and [1,2,2] would never be produced.

Sorting is mandatory because the check compares adjacent elements. On unsorted input the duplicates are not neighbours and the skip does nothing.

For permutations the condition changes to use the used array:

if (i > 0 && nums[i] === nums[i-1] && !used[i-1]) continue;

!used[i-1] means the previous identical value is not in the current path, so we are at a sibling position and this branch was already explored. If it were used, we would be legitimately extending a path containing the first copy.

The alternative — deduplicating with a Set of serialised results — works but is wasteful, generating every duplicate and then discarding it. On 20 elements with many repeats that is the difference between passing and TLE.

Mid: Solve Combination Sum, and explain the pruning. 
function combinationSum(candidates, target) {
  const out = [], path = [];
  candidates.sort((a,b) => a - b);               // enables the break
  const go = (start, remain) => {
    if (remain === 0) { out.push([...path]); return; }
    for (let i = start; i < candidates.length; i++) {
      if (candidates[i] > remain) break;         // PRUNE
      path.push(candidates[i]);
      go(i, remain - candidates[i]);             // i, not i+1 → reuse allowed
      path.pop();
    }
  };
  go(0, target);
  return out;
}

Two decisions define this problem:

1. Recursing with i rather than i+1 permits an element to be reused, which is what the problem asks for. Using i+1 would give Combination Sum II (each element once).

2. break rather than continue after exceeding the remainder. Because the array is sorted, if candidates[i] is already too large then every later candidate is too, so the whole rest of the loop can be abandoned:

candidates = [2,3,6,7], target = 7

path=[2,2,2], remain=1 → 2 > 1 → break immediately
                         (without sorting, we would test 3, 6, 7 pointlessly)

The pruning does not change the asymptotic bound but routinely cuts runtime by an order of magnitude, because it eliminates entire subtrees rather than individual nodes.

Termination requires all candidates to be positive. With a zero or negative value, recursing on i would loop forever — worth stating explicitly, since the problem guarantees positives and the algorithm silently depends on it.

Combination Sum II adds duplicate handling:

if (i > start && candidates[i] === candidates[i-1]) continue;
go(i + 1, remain - candidates[i]);               // each element used at most once

Note that "how many combinations sum to the target" is a different problem — that is DP in O(n·target), not backtracking. Enumerate only when the actual combinations are required.

Senior: Solve N-Queens efficiently.

Place one queen per row — which makes row conflicts impossible by construction — and track column and diagonal occupancy in sets for O(1) validity checks.

function solveNQueens(n) {
  const out = [], queens = [];
  const cols = new Set(), diag = new Set(), anti = new Set();

  const go = row => {
    if (row === n) {
      out.push(queens.map(c => ".".repeat(c) + "Q" + ".".repeat(n - c - 1)));
      return;
    }
    for (let c = 0; c < n; c++) {
      if (cols.has(c) || diag.has(row - c) || anti.has(row + c)) continue;
      cols.add(c); diag.add(row - c); anti.add(row + c); queens.push(c);
      go(row + 1);
      cols.delete(c); diag.delete(row - c); anti.delete(row + c); queens.pop();
    }
  };

  go(0);
  return out;
}

The diagonal identities are the key insight:

cells on the same ↘ diagonal share (row − col)
cells on the same ↙ diagonal share (row + col)

        col 0  1  2  3
row 0       0 -1 -2 -3        row−col is constant along ↘
row 1       1  0 -1 -2
row 2       2  1  0 -1

That turns "is any queen attacking this square?" from an O(n) scan into three hash lookups.

Placing one queen per row is itself the largest pruning decision. Without it, the search space is C(n², n) placements; with it, n choices per row for n rows — and most are eliminated immediately.

ApproachValidity checkn=12 time
Scan the boardO(n²)Very slow
Scan placed queensO(n)Slow
Three setsO(1)Fast
BitmasksO(1), no hashingFastest

The bitmask version is the classic optimisation, and it is genuinely elegant:

const go = (row, cols, diag, anti) => {
  if (row === n) { count++; return; }
  let avail = ~(cols | diag | anti) & ((1 << n) - 1);   // 1 bits = legal squares
  while (avail) {
    const bit = avail & -avail;                          // lowest set bit
    avail ^= bit;
    go(row + 1, cols | bit, (diag | bit) << 1, (anti | bit) >> 1);
  }
};

Shifting the diagonal masks each row automatically propagates the attack lines — no arithmetic on indices, no hash sets, and no undo needed because the masks are passed by value.

Symmetry breaking halves the work for the counting variant: restrict the first queen to the left half of row 0 and double the count (adjusting for the centre column when n is odd).

Senior: Solve a Sudoku board, and describe how to make it fast.

The naive version fills cells left-to-right, trying 1–9 in each. It works, and it is dramatically slower than it needs to be.

function solveSudoku(board) {
  const rows = Array.from({length:9}, () => new Set());
  const cols = Array.from({length:9}, () => new Set());
  const boxes = Array.from({length:9}, () => new Set());
  const boxOf = (r,c) => Math.floor(r/3)*3 + Math.floor(c/3);

  const empties = [];
  for (let r = 0; r < 9; r++)
    for (let c = 0; c < 9; c++) {
      const v = board[r][c];
      if (v === ".") empties.push([r,c]);
      else { rows[r].add(v); cols[c].add(v); boxes[boxOf(r,c)].add(v); }
    }

  const go = () => {
    if (!empties.length) return true;

    // MRV: pick the empty cell with the FEWEST candidates
    let best = 0, bestCount = 10;
    for (let i = 0; i < empties.length; i++) {
      const [r,c] = empties[i];
      let count = 0;
      for (let d = 1; d <= 9; d++) {
        const v = String(d);
        if (!rows[r].has(v) && !cols[c].has(v) && !boxes[boxOf(r,c)].has(v)) count++;
      }
      if (count < bestCount) { bestCount = count; best = i; if (count <= 1) break; }
    }
    if (bestCount === 0) return false;           // dead end — fail fast

    const [r, c] = empties.splice(best, 1)[0];
    for (let d = 1; d <= 9; d++) {
      const v = String(d);
      if (rows[r].has(v) || cols[c].has(v) || boxes[boxOf(r,c)].has(v)) continue;
      board[r][c] = v;
      rows[r].add(v); cols[c].add(v); boxes[boxOf(r,c)].add(v);
      if (go()) return true;
      board[r][c] = ".";
      rows[r].delete(v); cols[c].delete(v); boxes[boxOf(r,c)].delete(v);
    }
    empties.splice(best, 0, [r,c]);              // restore the cell list
    return false;
  };

  go();
}

Three design decisions, in order of impact:

1. Constraint sets for O(1) validity. Checking a candidate by scanning the row, column and box is 27 comparisons; three hash lookups replace it.

2. MRV — minimum remaining values. Always filling the most constrained cell first is the single largest speedup: a cell with one legal candidate is forced, and a cell with zero fails immediately rather than after descending nine levels. On hard puzzles this is often 10–100× faster than left-to-right order.

3. Returning true up the stack stops the search at the first solution rather than exploring the rest of the tree — appropriate because the problem guarantees a unique solution.

OptimisationEffect
Constraint sets27 comparisons → 3 lookups
MRV orderingUsually the biggest win
Early return on successStops at the first solution
Bitmask candidatesPopcount instead of a 1–9 loop
Constraint propagationFill forced cells before branching

The box index Math.floor(r/3)*3 + Math.floor(c/3) maps the 3×3 blocks to 0–8, and getting it wrong — a common slip is r/3 + c/3 — produces a solver that accepts invalid boards.

Full constraint propagation (repeatedly filling cells with exactly one candidate before branching at all) is the next step and solves most published puzzles with almost no search.

function permuteUnique(nums) {

function nQueensCount(n) {
  let count = 0, nodes = 0;
  const cols = new Set(), d1 = new Set(), d2 = new Set();

    nodes++;

function solveNQueensSets(n) {
  const out = [], queens = [];
  const cols = new Set(), d1 = new Set(), d2 = new Set();
  const go = row => {
    if (row === n) {
      out.push(queens.map(c => ".".repeat(c) + "Q" + ".".repeat(n-c-1)));
      return;
    }
    for (let c = 0; c < n; c++) {
      if (cols.has(c) || d1.has(row-c) || d2.has(row+c)) continue;
      cols.add(c); d1.add(row-c); d2.add(row+c); queens.push(c);
      go(row+1);
      cols.delete(c); d1.delete(row-c); d2.delete(row+c); queens.pop();
    }
  };
  go(0);
  return out;
}

function totalNQueensBitmask(n) {
  let count = 0;
  const full = (1 << n) - 1;
  const go = (row, cols, diag, anti) => {
    if (row === n) { count++; return; }
    let avail = ~(cols | diag | anti) & full;
    while (avail) {
      const bit = avail & -avail;                // lowest set bit
      avail ^= bit;
      go(row+1, cols|bit, ((diag|bit) << 1) & full, (anti|bit) >> 1);
    }
  };
  go(0, 0, 0, 0);
  return count;
}

Solution 
function makeSolver(useMRV) {
  return function solve(boardIn) {
    const board = boardIn.map(r => [...r]);
    let nodes = 0;
    const rows = Array.from({length:9}, () => new Set());
    const cols = Array.from({length:9}, () => new Set());
    const boxes = Array.from({length:9}, () => new Set());
    const boxOf = (r,c) => ((r/3)|0)*3 + ((c/3)|0);

    const empties = [];
    for (let r = 0; r < 9; r++) for (let c = 0; c < 9; c++) {
      const v = board[r][c];
      if (v === ".") empties.push([r,c]);
      else { rows[r].add(v); cols[c].add(v); boxes[boxOf(r,c)].add(v); }
    }

    const candidates = (r,c) => {
      const out = [];
      for (let d = 1; d <= 9; d++) {
        const v = String(d);
        if (!rows[r].has(v) && !cols[c].has(v) && !boxes[boxOf(r,c)].has(v)) out.push(v);
      }
      return out;
    };

    const go = () => {
      nodes++;
      if (!empties.length) return true;

      let pick = 0;
      if (useMRV) {
        let bestCount = 10;
        for (let i = 0; i < empties.length; i++) {
          const n = candidates(empties[i][0], empties[i][1]).length;
          if (n < bestCount) { bestCount = n; pick = i; if (n <= 1) break; }
        }
        if (bestCount === 0) return false;
      }

      const [r,c] = empties.splice(pick,1)[0];
      for (const v of candidates(r,c)) {
        board[r][c] = v;
        rows[r].add(v); cols[c].add(v); boxes[boxOf(r,c)].add(v);
        if (go()) return true;
        board[r][c] = ".";
        rows[r].delete(v); cols[c].delete(v); boxes[boxOf(r,c)].delete(v);
      }
      empties.splice(pick, 0, [r,c]);
      return false;
    };

    const solved = go();
    return { solved, board, nodes };
  };
}

function validSolution(board) {
  const groups = [];
  for (let i = 0; i < 9; i++) {
    groups.push(board[i]);                                     // rows
    groups.push(board.map(r => r[i]));                         // columns
    groups.push(board.slice(((i/3)|0)*3, ((i/3)|0)*3+3)
                     .flatMap(r => r.slice((i%3)*3, (i%3)*3+3)));  // boxes
  }
  return groups.every(g => new Set(g).size === 9 && !g.includes("."));
}

🎯 Key Takeaways

  • Every backtracking solution is choose → explore → unchoose; the undo step is what makes it backtracking rather than plain recursion.
  • Undo every mutation — popping the path but leaving used[i] set collapses the search to a single result.
  • Record results with a copy ([...path]); pushing the shared array stores aliases that all read as empty.
  • Subsets and combinations loop from start; permutations loop from 0 with a used array. That one parameter is the whole difference.
  • Recurse with i to allow element reuse, i+1 to forbid it.
  • Duplicate handling is always: sort first, then if (i > start && nums[i] === nums[i-1]) continue.
  • i > start — not i > 0 — permits a duplicate deeper in the tree while blocking it as a sibling.
  • For permutations with duplicates the condition is i > 0 && nums[i] === nums[i-1] && !used[i-1].
  • Pruning at the branch beats generating everything and deduplicating with a Set — 45× on a duplicate-heavy input.
  • Sorting plus break on exceeding the target cuts whole subtrees; the benefit compounds with depth (9× at target 40).
  • Constraint sets make validity O(1): N-Queens uses row−col and row+col as diagonal identities.
  • Placing one queen per row is itself pruning — at n=10 it visits 35k nodes instead of 10 billion.
  • The bitmask N-Queens is ~15× faster than hash sets and needs no undo, since masks are passed by value.
  • MRV — always expanding the most constrained cell — is the single biggest Sudoku optimisation, nearly 500× on hard puzzles.
  • Restore any in-place marking (a grid cell, a board square) before returning, or later branches see corrupted state.
  • If the question asks only for a count or an optimum, use DP — enumerating is exponential where DP is polynomial.
