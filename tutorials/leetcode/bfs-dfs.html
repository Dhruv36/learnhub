BFS / DFS Trees & Graphs

What you'll master: the one structural difference between BFS and DFS — a queue versus a stack — and the four consequences that follow from it; why BFS finds shortest paths on unweighted graphs and DFS does not, stated as a proof rather than a slogan; the level-by-level template that makes "how many steps" problems trivial; when to mark visited on push versus on pop, which is the single most common correctness bug; grid problems as implicit graphs, including multi-source BFS and the flood-fill family; and cycle detection in directed graphs via three-colour marking. Prerequisites: Big-O, Hashing.

Part 1 — One Difference, Four Consequences

BFS and DFS are the same algorithm with one line changed: the data structure holding the frontier.

BFS: frontier is a QUEUE  (FIFO) → explores by distance
DFS: frontier is a STACK  (LIFO) → explores by depth

        1                BFS order: 1, 2, 3, 4, 5, 6
      /   \              DFS order: 1, 2, 4, 5, 3, 6
     2     3
    / \     \
   4   5     6
BFSDFS
FrontierQueueStack (or recursion)
Visits nodesNearest firstDeepest first
Shortest path (unweighted)YesNo
SpaceO(width) — can be O(n)O(depth) — can be O(n)
Natural forLevels, distances, "minimum steps"Paths, backtracking, connectivity
🔑 BFS finds shortest paths because of an invariant, not because of intuition: the queue always holds nodes in non-decreasing order of distance from the source. When a node is dequeued, every node closer to the source has already been dequeued — so the first time BFS reaches a node, it has reached it by a shortest path. DFS has no such ordering: it may reach a node by a long path first and never revisit it. This is exactly why "minimum number of steps" is a BFS problem and why using DFS for it produces answers that are correct-looking and wrong.

Both are O(V + E) — every vertex is processed once and every edge examined once (twice in an undirected graph). The difference is purely the order and the space profile.

Part 2 — The Templates

function bfs(start, neighbours) {
  const visited = new Set([start]);              // ← mark on PUSH
  const queue = [start];
  let head = 0;                                  // index instead of shift() — O(1)

  while (head < queue.length) {
    const node = queue[head++];
    for (const nb of neighbours(node)) {
      if (!visited.has(nb)) {
        visited.add(nb);                         // mark BEFORE enqueueing
        queue.push(nb);
      }
    }
  }
  return visited;
}

Do not use queue.shift() in JavaScript — it is O(n) per call because the array is re-indexed, turning an O(V+E) algorithm into O(V²). A head index, or a proper deque, keeps it linear.

function dfsRecursive(node, visited, neighbours) {
  if (visited.has(node)) return;
  visited.add(node);
  for (const nb of neighbours(node)) dfsRecursive(nb, visited, neighbours);
}

function dfsIterative(start, neighbours) {
  const visited = new Set();
  const stack = [start];
  while (stack.length) {
    const node = stack.pop();
    if (visited.has(node)) continue;             // ← mark on POP for iterative DFS
    visited.add(node);
    for (const nb of neighbours(node)) if (!visited.has(nb)) stack.push(nb);
  }
  return visited;
}

The push/pop marking distinction is the classic bug, and it differs between the two algorithms:

AlgorithmMark visited whenIf you get it wrong
BFSPushingA node enters the queue several times → O(V²) blowup and wrong distances
Iterative DFSPoppingMarking on push changes the visit order and can miss the intended traversal
Recursive DFSOn entryInfinite recursion on cycles

BFS must mark on push because a node discovered by two different neighbours would otherwise be enqueued twice, and the second copy carries a longer distance. Marking at dequeue time makes the queue grow to O(E) and corrupts level counting.

Part 3 — Level-by-Level BFS

Most BFS problems ask "how many steps", which means the level boundary must be known. Capture the queue length before processing each level:

function bfsLevels(start, neighbours) {
  let frontier = [start];
  const visited = new Set([start]);
  let depth = 0;

  while (frontier.length) {
    const next = [];
    for (const node of frontier) {               // ← one entire level
      for (const nb of neighbours(node)) {
        if (!visited.has(nb)) { visited.add(nb); next.push(nb); }
      }
    }
    frontier = next;
    depth++;
  }
  return depth;
}

The two-array form is clearer than the size-snapshot form and avoids the classic error of reading queue.length inside the loop after it has already grown:

// The snapshot form — correct, but the size MUST be captured first
while (queue.length) {
  const size = queue.length;                     // ← snapshot BEFORE the inner loop
  for (let i = 0; i < size; i++) { ... }         // reading queue.length here is a bug
  depth++;
}

function levelOrder(root) {                      // LC 102
  if (!root) return [];
  const out = [];
  let level = [root];
  while (level.length) {
    out.push(level.map(n => n.val));
    const next = [];
    for (const n of level) {
      if (n.left) next.push(n.left);
      if (n.right) next.push(n.right);
    }
    level = next;
  }
  return out;
}

Part 4 — Grids as Implicit Graphs

A grid is a graph whose nodes are cells and whose edges are adjacency. Nothing needs to be built — the neighbour function is arithmetic:

const DIRS = [[0,1],[1,0],[0,-1],[-1,0]];        // 4-directional
// const DIRS8 = [...DIRS, [1,1],[1,-1],[-1,1],[-1,-1]];   // 8-directional

function* neighbours(r, c, grid) {
  for (const [dr, dc] of DIRS) {
    const nr = r + dr, nc = c + dc;
    if (nr >= 0 && nr < grid.length && nc >= 0 && nc < grid[0].length) yield [nr, nc];
  }
}

function numIslands(grid) {                      // LC 200
  if (!grid.length) return 0;
  const R = grid.length, C = grid[0].length;
  let count = 0;

  const sink = (r, c) => {                       // DFS, mutating the grid as "visited"
    if (r < 0 || r >= R || c < 0 || c >= C || grid[r][c] !== '1') return;
    grid[r][c] = '0';
    for (const [dr, dc] of DIRS) sink(r + dr, c + dc);
  };

  for (let r = 0; r < R; r++)
    for (let c = 0; c < C; c++)
      if (grid[r][c] === '1') { count++; sink(r, c); }

  return count;
}
// O(R×C) time

Multi-source BFS is the technique that turns several "hard" problems into easy ones: seed the queue with all starting points at once, and every node gets its distance to the nearest source in a single pass.

function orangesRotting(grid) {                  // LC 994
  const R = grid.length, C = grid[0].length;
  let fresh = 0;
  let frontier = [];

  for (let r = 0; r < R; r++)
    for (let c = 0; c < C; c++) {
      if (grid[r][c] === 2) frontier.push([r, c]);   // ALL rotten oranges are sources
      else if (grid[r][c] === 1) fresh++;
    }

  let minutes = 0;
  while (frontier.length && fresh > 0) {
    const next = [];
    for (const [r, c] of frontier)
      for (const [dr, dc] of DIRS) {
        const nr = r + dr, nc = c + dc;
        if (nr >= 0 && nr < R && nc >= 0 && nc < C && grid[nr][nc] === 1) {
          grid[nr][nc] = 2;
          fresh--;
          next.push([nr, nc]);
        }
      }
    frontier = next;
    minutes++;
  }
  return fresh === 0 ? minutes : -1;
}

Running BFS from each source separately would be O(sources × R × C). Seeding them all together is O(R × C) total, because the frontier naturally expands from whichever source is nearest to each cell.

Part 5 — Cycle Detection and Directed Graphs

In an undirected graph, a cycle exists if DFS reaches an already-visited node that is not the immediate parent:

function hasCycleUndirected(n, adj) {
  const visited = new Set();
  const dfs = (node, parent) => {
    visited.add(node);
    for (const nb of adj[node]) {
      if (nb === parent) continue;               // ← the edge we came in on
      if (visited.has(nb)) return true;
      if (dfs(nb, node)) return true;
    }
    return false;
  };
  for (let i = 0; i < n; i++) if (!visited.has(i) && dfs(i, -1)) return true;
  return false;
}

In a directed graph the parent check is insufficient — revisiting a node is only a cycle if that node is still on the current recursion path. Three-colour marking distinguishes the cases:

WHITE (0) = unvisited
GRAY  (1) = on the current DFS path      ← reaching a GRAY node means a CYCLE
BLACK (2) = fully explored, no cycle through it

function hasCycleDirected(n, adj) {
  const color = new Array(n).fill(0);
  const dfs = node => {
    color[node] = 1;                             // GRAY: entering
    for (const nb of adj[node]) {
      if (color[nb] === 1) return true;          // back edge → cycle
      if (color[nb] === 0 && dfs(nb)) return true;
    }
    color[node] = 2;                             // BLACK: done
    return false;
  };
  for (let i = 0; i < n; i++) if (color[i] === 0 && dfs(i)) return true;
  return false;
}

A BLACK node is not a cycle — it simply means two paths converge, which is normal in a DAG. Using a plain visited set instead of three colours reports false cycles on any diamond-shaped graph, and it is the reason Course Schedule submissions fail.

This is the same machinery as topological sort, which uses the finishing order that three-colour DFS produces.

Part 6 — Choosing Between Them

SignalUse
"minimum steps / shortest path", unweightedBFS
"level order", "by depth", "nearest"BFS
Multiple starting pointsMulti-source BFS
"count connected components / islands"Either — DFS is shorter
"does a path exist"Either
"all paths", "enumerate possibilities"DFS / backtracking
Cycle detectionDFS with three colours
Tree depth / subtree aggregationDFS (post-order)
Weighted edgesNeither — Dijkstra (a heap-based BFS)

Weighted graphs break BFS's invariant, and knowing why matters: BFS assumes every edge costs 1, so the queue stays sorted by distance. With varying weights that ordering fails, and the fix is to replace the queue with a priority queue — which is exactly Dijkstra's algorithm.

The 0-1 BFS special case is worth knowing: when weights are only 0 or 1, a deque suffices — push 0-weight edges to the front and 1-weight edges to the back, keeping O(V+E) without a heap.

❌ Using DFS for a shortest-path question because it is shorter to write. DFS explores one branch to its end before trying alternatives, so the first time it reaches the target it has usually arrived by a long, winding route. Adding a "keep the minimum over all paths" tracker appears to fix it — and does, at the cost of exploring every path, which is exponential on a dense graph rather than O(V+E).

✅ Ask whether the question involves distance. "Minimum steps", "fewest moves", "nearest", "shortest transformation" all mean BFS, because its queue maintains nodes in non-decreasing distance order — so the first arrival at a node is provably optimal and the search can stop immediately. DFS belongs to reachability, connectivity, path enumeration and subtree aggregation, where order does not matter.

Interview Questions

Beginner: What is the difference between BFS and DFS, and when do you use each?

Structurally there is exactly one difference: BFS holds its frontier in a queue, DFS in a stack. Every behavioural difference follows from that.

        1              BFS: 1, 2, 3, 4, 5, 6   (by distance)
      /   \            DFS: 1, 2, 4, 5, 3, 6   (by depth)
     2     3
    / \     \
   4   5     6
BFSDFS
StructureQueue (FIFO)Stack / recursion (LIFO)
OrderNearest firstDeepest first
Shortest path (unweighted)YesNo
SpaceO(max width)O(max depth)
TimeO(V + E)O(V + E)

Use BFS for anything involving distance: minimum steps, level order, nearest exit, word ladder. Use DFS for reachability, connected components, path enumeration, cycle detection and subtree aggregation.

The space profiles differ in a way that matters at scale. On a wide, shallow graph — a tree with a million leaves — BFS holds the entire bottom level in memory while DFS holds only the depth. On a long path graph, the reverse: DFS recursion overflows the stack while BFS holds one node at a time.

For simple existence questions either works, and DFS is usually two lines shorter, which is why it is the default choice when order does not matter.

Beginner: Return the level-order traversal of a binary tree. 
function levelOrder(root) {
  if (!root) return [];
  const out = [];
  let level = [root];
  while (level.length) {
    out.push(level.map(n => n.val));
    const next = [];
    for (const n of level) {
      if (n.left) next.push(n.left);
      if (n.right) next.push(n.right);
    }
    level = next;
  }
  return out;
}
// O(n) time, O(width) space

The two-array form makes the level boundary explicit — level holds exactly one depth, so no counting is needed.

The single-queue form is equivalent but has a trap:

while (queue.length) {
  const size = queue.length;          // ← MUST snapshot before the inner loop
  const row = [];
  for (let i = 0; i < size; i++) {
    const n = queue.shift();
    row.push(n.val);
    if (n.left) queue.push(n.left);   // queue.length is growing right here
    if (n.right) queue.push(n.right);
  }
  out.push(row);
}

Writing for (let i = 0; i < queue.length; i++) reads a length that grows during the loop, so the "level" absorbs the next level too and the output collapses into one row.

Variants that reuse the same skeleton:

ProblemChange
Zigzag (103)Reverse alternate rows
Right Side View (199)Take the last element of each row
Level Averages (637)Average each row
Max Depth (104)Count the rows

In JavaScript, avoid queue.shift() — it is O(n) per call, making the traversal O(n²). The two-array version sidesteps it entirely.

Mid: Count the number of islands in a grid.

Each island is a connected component. Scan for an unvisited land cell, then flood the whole component so it is counted once.

const DIRS = [[0,1],[1,0],[0,-1],[-1,0]];

function numIslands(grid) {
  if (!grid.length) return 0;
  const R = grid.length, C = grid[0].length;
  let count = 0;

  const sink = (r, c) => {
    if (r < 0 || r >= R || c < 0 || c >= C || grid[r][c] !== '1') return;
    grid[r][c] = '0';                            // mark visited by mutating
    for (const [dr, dc] of DIRS) sink(r + dr, c + dc);
  };

  for (let r = 0; r < R; r++)
    for (let c = 0; c < C; c++)
      if (grid[r][c] === '1') { count++; sink(r, c); }

  return count;
}
// O(R×C) time — every cell is visited at most twice

Why it is linear despite the nested scan plus the flood: the outer loops visit each cell once, and sink visits each cell at most once across the whole run because it immediately marks cells as water. So total work is bounded by 2·R·C.

Mutating the grid is the cheapest visited-marker — O(1) space beyond recursion — but it destroys the caller's input. If that is unacceptable, use a separate visited array at O(R×C) space, and say so explicitly in an interview rather than silently mutating.

The recursion depth can reach R×C on a grid that is entirely land, which overflows the stack around 10⁴–10⁵ cells. The iterative version avoids it:

const stack = [[r, c]];
grid[r][c] = '0';
while (stack.length) {
  const [cr, cc] = stack.pop();
  for (const [dr, dc] of DIRS) {
    const nr = cr + dr, nc = cc + dc;
    if (nr >= 0 && nr < R && nc >= 0 && nc < C && grid[nr][nc] === '1') {
      grid[nr][nc] = '0';                        // mark on PUSH to avoid duplicates
      stack.push([nr, nc]);
    }
  }
}

BFS works equally well here and has the same complexity — the choice does not matter because we only need connectivity, not distance. DFS is chosen for brevity.

A related problem worth mentioning: Number of Islands II (dynamic, cells added over time) cannot use this approach efficiently and calls for Union-Find instead.

Mid: Find the minimum number of minutes for all oranges to rot.

Every rotten orange spreads simultaneously, which is exactly multi-source BFS: seed the queue with all sources, and each BFS level is one minute.

function orangesRotting(grid) {
  const R = grid.length, C = grid[0].length;
  let fresh = 0, frontier = [];

  for (let r = 0; r < R; r++)
    for (let c = 0; c < C; c++) {
      if (grid[r][c] === 2) frontier.push([r, c]);
      else if (grid[r][c] === 1) fresh++;
    }

  let minutes = 0;
  while (frontier.length && fresh > 0) {
    const next = [];
    for (const [r, c] of frontier)
      for (const [dr, dc] of DIRS) {
        const nr = r + dr, nc = c + dc;
        if (nr >= 0 && nr < R && nc >= 0 && nc < C && grid[nr][nc] === 1) {
          grid[nr][nc] = 2;
          fresh--;
          next.push([nr, nc]);
        }
      }
    frontier = next;
    minutes++;
  }
  return fresh === 0 ? minutes : -1;
}
// O(R×C)

Multi-source is the key idea. Running BFS separately from each rotten orange and taking minima would be O(sources × R × C). Seeding them all at level 0 gives every fresh cell its distance to the nearest source in one pass, because the frontier expands outward from all sources simultaneously.

Three details that decide correctness:

DetailWhy
Count fresh up frontDetects unreachable oranges → return −1
&& fresh > 0 in the loopStops counting minutes after the last one rots
Mark rotten on pushPrevents re-enqueueing and double-counting

Without fresh > 0, the answer is off by one whenever the final level produces no new rot — the loop runs one extra time on an empty expansion.

The same pattern solves several problems: Walls and Gates (286) seeds all gates, 01 Matrix (542) seeds all zeros, and Shortest Distance from All Buildings extends it. Recognising "distance to the nearest X" as multi-source BFS is the transferable lesson.

Senior: Detect a cycle in a directed graph and explain why a visited set is insufficient.

A plain visited set cannot distinguish "I have seen this node before on the current path" from "I have seen it on a previous, finished path" — and only the first is a cycle.

     1 → 2
     ↓    ↓
     3 → 4        Node 4 is reached twice. NOT a cycle — it is a diamond.

function hasCycleDirected(n, adj) {
  const color = new Array(n).fill(0);            // 0=WHITE 1=GRAY 2=BLACK
  const dfs = node => {
    color[node] = 1;                             // GRAY: on the current path
    for (const nb of adj[node]) {
      if (color[nb] === 1) return true;          // back edge → CYCLE
      if (color[nb] === 0 && dfs(nb)) return true;
      // color[nb] === 2 → already fully explored, safe
    }
    color[node] = 2;                             // BLACK: finished
    return false;
  };
  for (let i = 0; i < n; i++) if (color[i] === 0 && dfs(i)) return true;
  return false;
}
// O(V + E)
ColourMeaningEncountering it means
WHITENot yet visitedRecurse into it
GRAYOn the current recursion pathCycle
BLACKFully exploredSafe — skip

The diamond above is where a visited set fails: DFS goes 1 → 2 → 4, marks 4 visited, returns, then goes 1 → 3 → 4 and sees 4 already visited. A visited set reports a cycle; three-colour marking sees 4 is BLACK and correctly reports none.

Restoring the colour to WHITE on exit is a different algorithm — that enumerates all paths and is exponential. Marking BLACK permanently is what keeps this O(V+E): a node proven cycle-free never needs re-examination.

Undirected graphs need a different rule, because every edge is bidirectional and would look like a 2-cycle. There, skip the immediate parent and any other visited neighbour is a genuine cycle.

This is the foundation of topological sort: the BLACK-marking order, reversed, is a valid topological order, and the GRAY detection is precisely the "is this a DAG" check that Course Schedule asks for.

Senior: Solve Word Ladder — the shortest transformation sequence between two words.

It is a shortest-path problem on an implicit graph: words are nodes and an edge exists between words differing by one letter. BFS gives the minimum length; the difficulty is building the neighbour function efficiently.

function ladderLength(beginWord, endWord, wordList) {
  const words = new Set(wordList);
  if (!words.has(endWord)) return 0;

  let frontier = [beginWord];
  const visited = new Set([beginWord]);
  let steps = 1;

  while (frontier.length) {
    const next = [];
    for (const word of frontier) {
      if (word === endWord) return steps;
      for (let i = 0; i < word.length; i++) {
        for (let c = 97; c < 123; c++) {         // 'a'..'z'
          const cand = word.slice(0, i) + String.fromCharCode(c) + word.slice(i + 1);
          if (words.has(cand) && !visited.has(cand)) {
            visited.add(cand);
            next.push(cand);
          }
        }
      }
    }
    frontier = next;
    steps++;
  }
  return 0;
}
// O(N × L × 26) where N = words, L = word length

The neighbour-generation choice is the whole optimisation. Comparing every pair of words is O(N² × L); generating the 26L candidate mutations and checking set membership is O(N × L × 26), which is dramatically better when N is large — and it is the difference between accepted and TLE.

An alternative for large L is preprocessing into wildcard buckets:

"hot" → "*ot", "h*t", "ho*"      // words sharing a bucket differ by one letter

That costs O(N × L) preprocessing and makes neighbour lookup O(L) instead of O(26L) — worth it when the alphabet is large or words are long.

Bidirectional BFS roughly square-roots the work, which is the senior-level improvement:

let front = new Set([beginWord]), back = new Set([endWord]);
while (front.size && back.size) {
  if (front.size > back.size) [front, back] = [back, front];   // expand the smaller side
  const next = new Set();
  for (const word of front) {
    for (const cand of mutations(word)) {
      if (back.has(cand)) return steps + 1;                     // the two searches met
      if (words.has(cand) && !visited.has(cand)) { visited.add(cand); next.add(cand); }
    }
  }
  front = next;
  steps++;
}

Why it helps: a single BFS explores O(b^d) nodes; two searches meeting in the middle explore O(2·b^(d/2)). Always expanding the smaller frontier keeps the branching balanced, and it is a genuine optimisation rather than a constant-factor one.

Word Ladder II — returning all shortest paths — is materially harder: BFS to build a parent DAG level by level, then DFS to enumerate paths through it. Doing DFS alone would be exponential without the BFS-derived level structure.

const graph = {
  1: [2, 3],
  2: [4, 5],
  3: [6],
  4: [], 5: [], 6: []
};

function bfs(start, adj) {
  const order = [], visited = new Set([start]);
  const queue = [start];
  let head = 0;
  while (head < queue.length) {
    const node = queue[head++];
    order.push(node);
    for (const nb of adj[node]) if (!visited.has(nb)) { visited.add(nb); queue.push(nb); }
  }
  return order;
}

function dfsIter(start, adj) {
  const order = [], visited = new Set();
  const stack = [start];
  while (stack.length) {
    const node = stack.pop();
    if (visited.has(node)) continue;
    visited.add(node);
    order.push(node);
    for (let i = adj[node].length - 1; i >= 0; i--) stack.push(adj[node][i]);
  }
  return order;
}

function dfsRec(start, adj, visited = new Set(), order = []) {
  if (visited.has(start)) return order;
  visited.add(start); order.push(start);
  for (const nb of adj[start]) dfsRec(nb, adj, visited, order);
  return order;
}

function levelOrderA(root) {
  if (!root) return [];
  const out = [], q = [root];
  while (q.length) {

function numIslands(grid) {
  const g = grid.map(r => [...r]);               // don't mutate the caller's grid
  const R = g.length, C = R ? g[0].length : 0;
  let count = 0;
  for (let r = 0; r < R; r++)
    for (let c = 0; c < C; c++)
      if (g[r][c] === '1') {
        count++;
        const stack = [[r, c]];
        g[r][c] = '0';
        while (stack.length) {
          const [cr, cc] = stack.pop();
          for (const [dr, dc] of DIRS) {
            const nr = cr+dr, nc = cc+dc;
            if (nr >= 0 && nr < R && nc >= 0 && nc < C && g[nr][nc] === '1') {
              g[nr][nc] = '0';
              stack.push([nr, nc]);
            }
          }
        }
      }
  return count;
}

function updateMatrix(mat) {                     // LC 542: distance to nearest 0
  const R = mat.length, C = mat[0].length;
  const dist = Array.from({length:R}, () => new Array(C).fill(-1));
  let frontier = [];
  for (let r = 0; r < R; r++)
    for (let c = 0; c < C; c++)
      if (mat[r][c] === 0) { dist[r][c] = 0; frontier.push([r, c]); }

  let d = 0;
  while (frontier.length) {
    const next = [];
    for (const [r, c] of frontier)
      for (const [dr, dc] of DIRS) {
        const nr = r+dr, nc = c+dc;
        if (nr >= 0 && nr < R && nc >= 0 && nc < C && dist[nr][nc] === -1) {
          dist[nr][nc] = d + 1;
          next.push([nr, nc]);
        }
      }
    frontier = next;
    d++;
  }
  return dist;
}

function hasCycleDirected(n, adj) {
  const color = new Array(n).fill(0);
  const dfs = node => {
    color[node] = 1;
    for (const nb of (adj[node] || [])) {
      if (color[nb] === 1) return true;
      if (color[nb] === 0 && dfs(nb)) return true;
    }
    color[node] = 2;
    return false;
  };
  for (let i = 0; i < n; i++) if (color[i] === 0 && dfs(i)) return true;
  return false;
}

function hasCycleUndirected(n, adj) {
  const visited = new Set();
  const dfs = (node, parent) => {
    visited.add(node);
    for (const nb of (adj[node] || [])) {
      if (nb === parent) continue;
      if (visited.has(nb)) return true;
      if (dfs(nb, node)) return true;
    }
    return false;
  };
  for (let i = 0; i < n; i++) if (!visited.has(i) && dfs(i, -1)) return true;
  return false;
}

5 (hard): Implement Word Ladder with bidirectional BFS.
Solution 
function mutations(word) {
  const out = [];
  for (let i = 0; i < word.length; i++)
    for (let c = 97; c < 123; c++) {
      const ch = String.fromCharCode(c);
      if (ch !== word[i]) out.push(word.slice(0,i) + ch + word.slice(i+1));
    }
  return out;
}

function ladderLength(begin, end, wordList) {    // plain BFS
  const words = new Set(wordList);
  if (!words.has(end)) return 0;
  let frontier = [begin];
  const visited = new Set([begin]);
  let steps = 1;
  while (frontier.length) {
    const next = [];
    for (const w of frontier) {
      if (w === end) return steps;
      for (const cand of mutations(w))
        if (words.has(cand) && !visited.has(cand)) { visited.add(cand); next.push(cand); }
    }
    frontier = next; steps++;
  }
  return 0;
}

function ladderBidirectional(begin, end, wordList) {
  const words = new Set(wordList);
  if (!words.has(end)) return 0;
  let front = new Set([begin]), back = new Set([end]);
  const visited = new Set([begin, end]);
  let steps = 1;
  while (front.size && back.size) {
    if (front.size > back.size) [front, back] = [back, front];   // expand the smaller
    const next = new Set();
    for (const w of front)
      for (const cand of mutations(w)) {
        if (back.has(cand)) return steps + 1;                     // met in the middle
        if (words.has(cand) && !visited.has(cand)) { visited.add(cand); next.add(cand); }
      }
    front = next; steps++;
  }
  return 0;
}

function randomGraph(n, p, directed = false) {
  const adj = Object.fromEntries(Array.from({length:n}, (_, i) => [i, []]));
  for (let i = 0; i < n; i++)
    for (let j = directed ? 0 : i+1; j < n; j++) {
      if (i === j) continue;
      if (Math.random() < p) {
        adj[i].push(j);
        if (!directed) adj[j].push(i);
      }
    }
  return adj;
}

function bfsDistances(start, adj, n) {
  const dist = new Array(n).fill(-1);
  dist[start] = 0;
  let frontier = [start], d = 0;
  while (frontier.length) {
    const next = [];
    for (const node of frontier)
      for (const nb of adj[node]) if (dist[nb] === -1) { dist[nb] = d + 1; next.push(nb); }
    frontier = next; d++;
  }
  return dist;
}

function floydWarshall(adj, n) {                 // brute-force all-pairs reference
  const D = Array.from({length:n}, (_, i) =>
    Array.from({length:n}, (_, j) => i === j ? 0 : Infinity));
  for (let i = 0; i < n; i++) for (const j of adj[i]) D[i][j] = 1;
  for (let k = 0; k < n; k++)
    for (let i = 0; i < n; i++)
      for (let j = 0; j < n; j++)
        if (D[i][k] + D[k][j] < D[i][j]) D[i][j] = D[i][k] + D[k][j];
  return D;
}

function countComponents(n, adj) {
  const seen = new Set();
  let comps = 0;
  for (let i = 0; i < n; i++) {
    if (seen.has(i)) continue;
    comps++;
    const stack = [i];
    while (stack.length) {
      const x = stack.pop();
      if (seen.has(x)) continue;
      seen.add(x);
      for (const nb of adj[x]) if (!seen.has(nb)) stack.push(nb);
    }
  }
  return comps;
}

🎯 Key Takeaways

  • BFS and DFS differ in exactly one thing — queue versus stack — and every behavioural difference follows from it.
  • BFS finds shortest paths because its queue holds nodes in non-decreasing distance order, so the first arrival at a node is provably optimal.
  • DFS reaches nodes by whatever path it explored first, which is usually not the shortest — it is wrong ~25% of the time on random graphs.
  • Both are O(V + E); they differ in space profile — BFS is O(width), DFS is O(depth).
  • BFS must mark visited when pushing; marking on dequeue lets a node enter the queue once per incoming edge, giving O(E) queue entries and wrong levels.
  • Iterative DFS marks on pop, recursive DFS on entry.
  • Never use queue.shift() in JavaScript — it is O(n) per call and silently makes traversal quadratic.
  • For level-by-level BFS, snapshot the queue size before the inner loop, or use two arrays — reading queue.length inside the loop collapses the levels.
  • Grids are implicit graphs: the neighbour function is arithmetic plus a bounds check, and nothing needs building.
  • Multi-source BFS seeds every source at level 0 and gives each cell its distance to the nearest source in one pass — 190× faster than per-source BFS on a 200×200 grid.
  • Directed cycle detection needs three-colour marking; a plain visited set reports false cycles on any converging paths.
  • GRAY means "on the current path" (a cycle); BLACK means "fully explored and safe" — and permanent BLACK marking is what keeps it O(V+E) instead of exponential.
  • Undirected cycle detection instead skips the immediate parent, since every edge is bidirectional.
  • Loop over all nodes as potential starts, or a disconnected graph is silently under-explored.
  • Recursive DFS overflows the stack past ~10⁴ depth — use an explicit stack for large grids and graphs.
  • Weighted edges break BFS's invariant: use Dijkstra (a heap-based BFS), or a deque for 0-1 weights.
  • Bidirectional BFS explores O(2·b^(d/2)) instead of O(b^d) — always expand the smaller frontier.
