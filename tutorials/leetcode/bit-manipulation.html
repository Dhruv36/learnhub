Bit Manipulation Advanced Pattern

What you'll master: the six operators and the handful of idioms that cover almost every bit problem; XOR's three properties, which are why Single Number is a one-liner and why they generalise to harder variants; n & (n-1) and n & -n, the two tricks worth memorising, and exactly what they do; subset enumeration by bitmask, including the submask-enumeration loop that most people have never seen; bitmask DP for the travelling-salesman family; and JavaScript's specific hazards — 32-bit coercion, the signed right shift, and where >>> is required. Prerequisites: Big-O, Dynamic Programming.

The core single-bit idioms:

get bit i:      (n >> i) & 1
set bit i:      n | (1 << i)
clear bit i:    n & ~(1 << i)
toggle bit i:   n ^ (1 << i)
test bit i:     (n & (1 << i)) !== 0
🔑 Two identities are worth memorising because they turn loops into single operations. n & (n-1) clears the lowest set bit — subtracting 1 flips that bit to 0 and every bit below it to 1, so ANDing keeps everything above and wipes the rest. n & -n isolates the lowest set bit, because two's-complement negation is ~n + 1, which agrees with n only at that one position. Between them they give O(popcount) bit counting, power-of-two tests, and the submask enumeration in Part 4.
n     = 12 = 1100
n-1   = 11 = 1011
n&(n-1)= 8 = 1000        ← lowest set bit cleared

-n    =      0100   (two's complement: ~1100 + 1)
n & -n =      0100   ← lowest set bit isolated

Part 2 — XOR and Its Three Properties

function singleNumber(nums) {                    // LC 136
  let x = 0;
  for (const n of nums) x ^= n;                  // pairs cancel, the loner survives
  return x;
}
// O(n) time, O(1) space — no hash map needed

[4,1,2,1,2] → 4^1^2^1^2
            = 4^(1^1)^(2^2)      (reorder freely)
            = 4^0^0 = 4  ✓

Single Number III — two loners — uses n & -n to split the array:

function singleNumberIII(nums) {                 // LC 260
  let xor = 0;
  for (const n of nums) xor ^= n;                // xor = a ^ b (the two loners)

  const lowBit = xor & -xor;                     // a bit where a and b DIFFER

  let a = 0, b = 0;
  for (const n of nums) {
    if (n & lowBit) a ^= n;                      // partition by that bit
    else b ^= n;
  }
  return [a, b];
}

The insight: a ^ b has a 1 wherever a and b differ, so any such bit partitions the array into two groups — each containing one loner and pairs. XOR within each group isolates it.

Single Number II — every number appears three times except one — needs counting bits modulo 3:

function singleNumberII(nums) {                  // LC 137
  let result = 0;
  for (let bit = 0; bit < 32; bit++) {
    let count = 0;
    for (const n of nums) count += (n >> bit) & 1;
    if (count % 3) result |= (1 << bit);         // ← the loner's bit
  }
  return result | 0;                             // coerce back to signed 32-bit
}

Part 3 — Counting and Power-of-Two Tests

function hammingWeight(n) {                      // LC 191 — count set bits
  let count = 0;
  while (n !== 0) { n &= n - 1; count++; }       // ← loops once PER SET BIT
  return count;
}
// O(popcount), not O(32)

n = 11 = 1011
1011 & 1010 = 1010   count 1
1010 & 1001 = 1000   count 2
1000 & 0111 = 0000   count 3   → 3 set bits ✓

const isPowerOfTwo = n => n > 0 && (n & (n - 1)) === 0;   // exactly one set bit
const isPowerOfFour = n => n > 0 && (n & (n-1)) === 0 && (n & 0x55555555) !== 0;

The n > 0 guard is not optional — 0 & -1 === 0, so zero would otherwise report as a power of two.

Counting Bits (LC 338) is DP over bits, and both recurrences are worth knowing:

function countBits(n) {
  const dp = new Array(n + 1).fill(0);
  for (let i = 1; i <= n; i++)
    dp[i] = dp[i >> 1] + (i & 1);                // half's count, plus the last bit
    // alternative: dp[i] = dp[i & (i-1)] + 1;   // one more than with the low bit cleared
  return dp;
}
// O(n)

Part 4 — Subsets and Submasks

A bitmask of n bits enumerates all 2ⁿ subsets directly — no recursion needed:

function subsets(nums) {                         // LC 78, bitmask version
  const out = [];
  for (let mask = 0; mask < (1 << nums.length); mask++) {
    const sub = [];
    for (let i = 0; i < nums.length; i++)
      if (mask & (1 << i)) sub.push(nums[i]);
    out.push(sub);
  }
  return out;
}
// O(n · 2ⁿ) — same as backtracking, but iterative

Enumerating every submask of a mask is the technique most people have not seen, and it is the key to several hard DP problems:

for (let sub = mask; sub > 0; sub = (sub - 1) & mask) {
  // sub takes every non-empty submask of mask, exactly once
}
// total over ALL masks: 3ⁿ, not 4ⁿ

mask = 1011

sub = 1011 → 1010 → 1001 → 1000 → 0011 → 0010 → 0001 → 0
      (subtracting 1 then masking skips every value not contained in mask)

Why the total is 3ⁿ: each bit is in the mask and the submask, in the mask only, or in neither — three possibilities per bit.

Bitmask DP uses the mask as a "which items are used" state, which is what makes travelling-salesman-style problems tractable for n ≤ 20:

function tsp(dist) {                             // shortest tour visiting all nodes
  const n = dist.length;
  const FULL = (1 << n) - 1;
  const dp = Array.from({length: 1 << n}, () => new Array(n).fill(Infinity));
  dp[1][0] = 0;                                  // start at node 0, only it visited

  for (let mask = 1; mask <= FULL; mask++)
    for (let last = 0; last < n; last++) {
      if (dp[mask][last] === Infinity || !(mask & (1 << last))) continue;
      for (let next = 0; next < n; next++) {
        if (mask & (1 << next)) continue;        // already visited
        const nm = mask | (1 << next);
        dp[nm][next] = Math.min(dp[nm][next], dp[mask][last] + dist[last][next]);
      }
    }

  return Math.min(...dp[FULL].map((v, i) => v + dist[i][0]));
}
// O(2ⁿ · n²) — feasible to about n = 20

Part 5 — JavaScript's Bit Hazards

JavaScript numbers are 64-bit floats, but bitwise operators coerce to signed 32-bit integers. That produces several traps.

HazardExampleFix
Coercion to 32 bits2**32 | 0 === 0Use BigInt beyond 32 bits
Sign bit1 << 31 === -2147483648Use >>> 0 for unsigned
Signed right shift-8 >> 1 === -4>>> fills with zeros
Shift counts wrap mod 321 << 32 === 1Keep shifts in 0–31
Operator precedencea & b === c parses as a & (b === c)Parenthesise
console.log(1 << 31);        // -2147483648   ← sign bit set
console.log((1 << 31) >>> 0); // 2147483648   ← unsigned view
console.log(-8 >> 1);        // -4           sign-preserving
console.log(-8 >>> 1);       // 2147483644   zero-filled
console.log(1 << 32);        // 1            ← shift wrapped to 1 << 0

Iterating bits of a possibly-negative number must use >>>, or the loop never terminates — the sign bit keeps refilling:

// INFINITE LOOP on negative input
while (n !== 0) { count += n & 1; n >>= 1; }

// correct
while (n !== 0) { count += n & 1; n >>>= 1; }

❌ Using >> to iterate over the bits of a number that might be negative. The signed right shift preserves the sign bit, so a negative value shifts toward −1 and never reaches 0 — while (n !== 0) { …; n >>= 1; } hangs forever. It passes every test with positive input, which is most of them, and then times out on the one case containing a negative number with no indication of why.

✅ Use >>> whenever the value may be negative, or bound the loop to 32 iterations. The unsigned shift fills with zeros, so any 32-bit value reaches 0 within 32 steps. The same care applies to output: 1 << 31 is negative in JavaScript, so a result built by setting the top bit needs >>> 0 to be read as unsigned — and anything beyond 32 bits needs BigInt, because the operators silently truncate.

function singleNumber(nums) {

  for (const n of nums) x ^= n;
  return x;

The alternatives are worse in exactly the way the problem is testing: a hash map is O(n) space, sorting is O(n log n). XOR is O(1) space and one line, which is why the problem exists.

Beginner: Count the set bits in an integer, and test for a power of two. 
function hammingWeight(n) {
  let count = 0;
  while (n !== 0) { n &= n - 1; count++; }
  return count;
}
// O(number of set bits) — not O(32)

Why n & (n-1) clears the lowest set bit: subtracting 1 turns that bit into 0 and every bit below it into 1. ANDing the two keeps everything above the lowest set bit and wipes the bit itself plus everything below.

n     = 12 = 1100
n-1   = 11 = 1011
n&(n-1)=  8 = 1000        ← the lowest set bit (100) is gone

The naive version is O(32) regardless:

let count = 0;
for (let i = 0; i < 32; i++) if (n & (1 << i)) count++;

The n &= n-1 version loops only as many times as there are set bits — a real saving on sparse numbers.

Power of two follows directly: a power of two has exactly one set bit, so clearing it yields zero.

const isPowerOfTwo = n => n > 0 && (n & (n - 1)) === 0;

8  = 1000, 8 & 7 = 1000 & 0111 = 0  ✓
12 = 1100, 12 & 11 = 1100 & 1011 = 1000 ≠ 0  ✗

The n > 0 guard is essential — for n = 0, 0 & -1 === 0, so zero would be reported as a power of two. Negative numbers would also slip through.

The related identity is n & -n, which isolates the lowest set bit rather than clearing it — used to split arrays in Single Number III and to walk indices in a Fenwick tree.

Mid: Two numbers appear once and all others twice. Find both.

XOR everything to get a ^ b, then use any differing bit to partition the array so each group contains exactly one loner.

function singleNumberIII(nums) {
  let xor = 0;
  for (const n of nums) xor ^= n;                // = a ^ b

  const lowBit = xor & -xor;                     // isolate a bit where a and b DIFFER

  let a = 0, b = 0;
  for (const n of nums) {
    if (n & lowBit) a ^= n;
    else b ^= n;
  }
  return [a, b];
}
// O(n) time, O(1) space

The reasoning in two steps:

1. xor = a ^ b, and it is non-zero because a ≠ b. Every bit set in it is a position where a and b differ.

2. Partitioning on any such bit separates a from b. Every duplicated pair has identical bits, so both copies land in the same group and cancel. Each group therefore contains one loner and some complete pairs.

nums = [1,2,1,3,2,5]
xor = 3 ^ 5 = 0011 ^ 0101 = 0110
lowBit = 0110 & -0110 = 0010    ← bit 1

group with bit 1 set:  2, 3, 2  → XOR = 3
group without:         1, 1, 5  → XOR = 5
→ [3, 5] ✓

x & -x works because of two's complement: -x is ~x + 1, which matches x only at the lowest set bit. Any other set bit would work equally well — the lowest is simply the cheapest to extract.

Single Number II — every number three times except one — cannot use XOR at all, since XOR only cancels pairs. Counting each bit position modulo 3 works instead:

let result = 0;
for (let bit = 0; bit < 32; bit++) {
  let count = 0;
  for (const n of nums) count += (n >> bit) & 1;
  if (count % 3) result |= (1 << bit);
}
return result | 0;                               // restore the sign for negative results
Mid: Generate all subsets using bitmasks, and explain submask enumeration. 
function subsets(nums) {
  const out = [];
  for (let mask = 0; mask < (1 << nums.length); mask++) {
    const sub = [];
    for (let i = 0; i < nums.length; i++)
      if (mask & (1 << i)) sub.push(nums[i]);
    out.push(sub);
  }
  return out;
}
// O(n · 2ⁿ)

Each mask value is a subset — bit i set means element i is included. For n = 3, masks 000 through 111 enumerate all 8 subsets, with no recursion and no explicit backtracking state.

mask 000 → []        mask 100 → [c]
mask 001 → [a]       mask 101 → [a,c]
mask 010 → [b]       mask 110 → [b,c]
mask 011 → [a,b]     mask 111 → [a,b,c]

Submask enumeration is the less familiar technique, and it visits every subset of a given mask:

for (let sub = mask; sub > 0; sub = (sub - 1) & mask) {
  // sub takes every non-empty submask of mask, exactly once, descending
}

mask = 1011
1011 → 1010 → 1001 → 1000 → 0011 → 0010 → 0001 → 0

Why (sub - 1) & mask: subtracting 1 moves to the next lower value, and ANDing with mask skips every value containing a bit not in the mask. The result is exactly the submasks, in descending order.

The total cost over all masks is 3ⁿ, not 4ⁿ, which is the fact that makes this practical: each bit is either in both mask and submask, in the mask only, or in neither — three choices.

n = 20:   4ⁿ ≈ 1.1 × 10¹²    (infeasible)
          3ⁿ ≈ 3.5 × 10⁹     (borderline but doable)

This underpins set-partition DP — problems like "partition into k subsets with equal sums" iterate over each mask's submasks to try every way of forming the next group.

A useful constraint signal: when a problem says n ≤ 20, a 2ⁿ bitmask approach is almost certainly intended — 2²⁰ is about a million, which is comfortable.

Senior: Solve a bitmask DP problem — assigning tasks to workers.

The mask encodes which items are already used, which turns an assignment problem into a DP over 2ⁿ states.

function minCostAssignment(cost) {               // cost[worker][task]
  const n = cost.length;
  const FULL = (1 << n) - 1;
  const dp = new Array(1 << n).fill(Infinity);
  dp[0] = 0;

  for (let mask = 0; mask < FULL; mask++) {
    if (dp[mask] === Infinity) continue;
    const worker = popcount(mask);               // ← #assigned tasks = next worker index
    for (let task = 0; task < n; task++) {
      if (mask & (1 << task)) continue;          // task already taken
      const nm = mask | (1 << task);
      dp[nm] = Math.min(dp[nm], dp[mask] + cost[worker][task]);
    }
  }
  return dp[FULL];
}

function popcount(x) { let c = 0; while (x) { x &= x-1; c++; } return c; }
// O(2ⁿ · n)

The key simplification is that the worker index is implied by the mask. Since workers are assigned in order, the number of set bits tells you which worker is next — so the state needs only the mask, not a (worker, mask) pair. That halves the state space.

mask 0000 → worker 0 picks a task
mask 0010 → 1 task assigned → worker 1 picks next
mask 0111 → 3 tasks assigned → worker 3 picks next

The TSP variant needs the extra dimension, because the cost of the next move depends on where you currently are:

function tsp(dist) {
  const n = dist.length, FULL = (1 << n) - 1;
  const dp = Array.from({length: 1 << n}, () => new Array(n).fill(Infinity));
  dp[1][0] = 0;
  for (let mask = 1; mask <= FULL; mask++)
    for (let last = 0; last < n; last++) {
      if (!(mask & (1 << last)) || dp[mask][last] === Infinity) continue;
      for (let next = 0; next < n; next++) {
        if (mask & (1 << next)) continue;
        const nm = mask | (1 << next);
        dp[nm][next] = Math.min(dp[nm][next], dp[mask][last] + dist[last][next]);
      }
    }
  return Math.min(...dp[FULL].map((v, i) => v + dist[i][0]));
}
// O(2ⁿ · n²), feasible to about n = 20

So the constraint tells you the technique. A problem stating n ≤ 20 with an assignment or tour flavour is signalling bitmask DP; if n were 100, an entirely different approach — flow, or a heuristic — would be required.

Iterating masks in increasing order is what makes it correct: adding a task only ever increases the mask value, so every state's dependencies are already computed.

Senior: What are JavaScript's bitwise pitfalls, and when do they matter?

JavaScript numbers are 64-bit floats, but every bitwise operator first coerces to a signed 32-bit integer. That produces four distinct hazards.

1. Silent truncation beyond 32 bits:

console.log(2 ** 32 | 0);          // 0        ← the value is gone
console.log(2 ** 31 | 0);          // -2147483648
console.log(Number.MAX_SAFE_INTEGER | 0);  // -1

Any problem involving more than 32 bits needs BigInt, which has its own bitwise operators.

2. The sign bit:

console.log(1 << 31);              // -2147483648, not 2147483648
console.log((1 << 31) >>> 0);       // 2147483648   ← unsigned view

3. Signed versus unsigned right shift — this is the one that causes infinite loops:

console.log(-8 >> 1);              // -4           sign-extended
console.log(-8 >>> 1);             // 2147483644   zero-filled

// hangs forever on negative n:
while (n !== 0) { count += n & 1; n >>= 1; }
// correct:
while (n !== 0) { count += n & 1; n >>>= 1; }

4. Shift counts wrap modulo 32:

console.log(1 << 32);              // 1   ← same as 1 << 0
console.log(1 << 33);              // 2

And a syntax trap: === binds tighter than &, so if (a & b === c) parses as a & (b === c) — almost always wrong, and it does not error.

SituationUse
Values might be negative>>>
Result should read as unsignedx >>> 0
More than 32 bitsBigInt
Mixing bitwise and comparisonParentheses

When these matter in practice: Reverse Bits and Number of 1 Bits explicitly pass negative or high-bit values; Single Number II builds a result that may have the sign bit set and needs | 0; and any problem with values near 2³¹ can overflow silently. In other languages the details differ — Java has >>> too, Python has arbitrary-precision integers and no unsigned shift at all — so the hazard set is language-specific and worth stating explicitly.

3 (medium): Solve the Single Number family.
Solution 
function singleNumber(nums) {                    // others twice
  let x = 0;
  for (const n of nums) x ^= n;
  return x;
}

function singleNumberII(nums) {                  // others three times
  let result = 0;
  for (let bit = 0; bit < 32; bit++) {
    let count = 0;
    for (const n of nums) count += (n >>> bit) & 1;
    if (count % 3) result |= (1 << bit);
  }
  return result | 0;
}

function singleNumberIII(nums) {                 // TWO appear once
  let xor = 0;
  for (const n of nums) xor ^= n;
  const low = xor & -xor;
  let a = 0, b = 0;
  for (const n of nums) { if (n & low) a ^= n; else b ^= n; }
  return [a, b].sort((x,y) => x-y);
}

function missingNumber(nums) {
  let x = nums.length;
  for (let i = 0; i < nums.length; i++) x ^= i ^ nums[i];
  return x;
}

  const out = [];
  for (let mask = 0; mask < (1 << nums.length); mask++) {

5 (hard): Solve a bitmask DP problem end to end.
Solution 
function minCostAssignment(cost) {               // cost[worker][task]
  const n = cost.length, FULL = (1 << n) - 1;
  const dp = new Array(1 << n).fill(Infinity);
  dp[0] = 0;
  for (let mask = 0; mask < FULL; mask++) {
    if (dp[mask] === Infinity) continue;
    const worker = popcount(mask);
    for (let task = 0; task < n; task++) {
      if (mask & (1 << task)) continue;
      const nm = mask | (1 << task);
      dp[nm] = Math.min(dp[nm], dp[mask] + cost[worker][task]);
    }
  }
  return dp[FULL];
}

function minCostBrute(cost) {                    // try every permutation
  const n = cost.length;
  let best = Infinity;
  const go = (worker, used, total) => {
    if (worker === n) { best = Math.min(best, total); return; }
    for (let t = 0; t < n; t++)
      if (!used[t]) { used[t] = true; go(worker+1, used, total + cost[worker][t]); used[t] = false; }
  };
  go(0, new Array(n).fill(false), 0);
  return best;
}

function tsp(dist) {
  const n = dist.length, FULL = (1 << n) - 1;
  const dp = Array.from({length: 1 << n}, () => new Array(n).fill(Infinity));
  dp[1][0] = 0;
  for (let mask = 1; mask <= FULL; mask++)
    for (let last = 0; last < n; last++) {
      if (!(mask & (1 << last)) || dp[mask][last] === Infinity) continue;
      for (let next = 0; next < n; next++) {
        if (mask & (1 << next)) continue;
        const nm = mask | (1 << next);
        dp[nm][next] = Math.min(dp[nm][next], dp[mask][last] + dist[last][next]);
      }
    }
  return Math.min(...dp[FULL].map((v,i) => v + dist[i][0]));
}

function tspBrute(dist) {
  const n = dist.length;
  let best = Infinity;
  const go = (at, visited, cost) => {
    if (visited.length === n) { best = Math.min(best, cost + dist[at][0]); return; }
    for (let v = 0; v < n; v++)
      if (!visited.includes(v)) go(v, [...visited, v], cost + dist[at][v]);
  };
  go(0, [0], 0);
  return best;
}

🎯 Key Takeaways

  • Five idioms cover most problems: get, set, clear, toggle and test bit i via shifts and masks.
  • n & (n-1) clears the lowest set bit — giving popcount in O(number of set bits), not O(32).
  • n & -n isolates the lowest set bit, because two's-complement negation agrees with n only there.
  • Power of two is n > 0 && (n & (n-1)) === 0 — the n > 0 guard is required, since 0 & -1 === 0.
  • XOR is self-inverse, has identity 0, and is commutative — which makes Single Number a one-line O(1)-space solution.
  • XOR only cancels pairs; "appears three times" needs bit counts modulo 3.
  • For two loners, XOR everything then split the array on any bit of the result — x & -x is the cheapest such bit.
  • A bitmask enumerates all 2ⁿ subsets iteratively, with the mask itself usable as a DP state.
  • sub = (sub - 1) & mask enumerates every submask exactly once; plain sub - 1 visits values outside the mask.
  • The total submask work over all masks is 3ⁿ − 2ⁿ, verified empirically — which is what makes submask DP feasible.
  • Bitmask DP handles assignment and TSP-style problems at O(2ⁿ·n²): comfortable to n = 18, borderline at 20, impossible at 25.
  • A constraint of n ≤ 20 is a strong signal that a 2ⁿ bitmask solution is intended.
  • JavaScript's bitwise operators coerce to signed 32-bit: 2**32 | 0 === 0 and 1 << 31 is negative.
  • Use >>> for any value that may be negative — >> sign-extends and loops forever on negative input.
  • Apply >>> 0 to read a result as unsigned, and reach for BigInt beyond 32 bits.
  • Shift counts wrap modulo 32, so 1 << 32 is 1, not 4294967296.
  • === binds tighter than & — always parenthesise bitwise tests.
  • Use bit tricks where they are the point of the problem; elsewhere they cost readability for no measurable gain.
