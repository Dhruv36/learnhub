Binary Tree Patterns Trees & Graphs

What you'll master: the two directions information flows through a tree — top-down via parameters and bottom-up via return values — and why choosing the wrong one turns an easy problem into an impossible one; the four traversal orders and what each is actually for; the "return one thing, track another" technique that solves diameter, max path sum and balanced-check in one pass; BST problems and why in-order traversal is the whole answer; lowest common ancestor in both the generic and BST cases; and tree construction, serialisation and the null-marker requirement. Prerequisites: BFS / DFS, Big-O.

Part 1 — Two Directions of Information Flow

Almost every tree problem is one question: does a node need information from above it, or from below it? Get that right and the code writes itself.

TOP-DOWN (pass down as parameters)        BOTTOM-UP (return values up)
──────────────────────────────────        ────────────────────────────
        root(depth=0)                            root ← combines
         ↓                                        ↑  ↑
     child(depth=1)                          left    right
         ↓                                     ↑        ↑
    grandchild(depth=2)                     leaves return base values

"what do I know from my ancestors?"       "what did my subtrees compute?"

// TOP-DOWN: depth is known from the parent
function maxDepthTopDown(node, depth = 0, best = { v: 0 }) {
  if (!node) return best.v;
  best.v = Math.max(best.v, depth + 1);
  maxDepthTopDown(node.left, depth + 1, best);
  maxDepthTopDown(node.right, depth + 1, best);
  return best.v;
}

// BOTTOM-UP: depth is computed from the children
function maxDepth(node) {                        // LC 104 — the natural version
  if (!node) return 0;
  return 1 + Math.max(maxDepth(node.left), maxDepth(node.right));
}
🔑 The choice is not stylistic — it decides whether the problem is solvable in one pass. Ask "to compute my answer, do I need to know where I am (path from the root, accumulated value, valid range), or what is beneath me (height, sum, count)?" Path-dependent facts must come down as parameters, because a node cannot see its ancestors. Subtree-dependent facts must come up as return values, because a node cannot see its descendants without recursing. Problems needing both — diameter, max path sum — are the ones where you return one thing and record another in an outer variable.

Part 2 — The Four Traversal Orders

        1
      /   \            pre-order  (node, left, right):  1 2 4 5 3
     2     3           in-order   (left, node, right):  4 2 5 1 3
    / \                post-order (left, right, node):  4 5 2 3 1
   4   5               level-order (BFS):               1 2 3 4 5
OrderVisits nodeUse it for
Pre-orderBefore childrenCopying a tree, serialisation, top-down propagation

function inorder(node, out = []) {
  if (!node) return out;
  inorder(node.left, out);
  out.push(node.val);                            // ← between the two recursions
  inorder(node.right, out);
  return out;
}

The iterative in-order traversal is worth knowing because it underpins the BST iterator and several "kth smallest" problems:

function inorderIterative(root) {
  const out = [], stack = [];
  let cur = root;
  while (cur || stack.length) {
    while (cur) { stack.push(cur); cur = cur.left; }   // dive left
    cur = stack.pop();
    out.push(cur.val);                                 // visit
    cur = cur.right;                                   // then go right
  }
  return out;
}

Post-order iteratively is the awkward one. The trick is to do a modified pre-order (node, right, left) and reverse the result:

function postorderIterative(root) {
  if (!root) return [];
  const out = [], stack = [root];
  while (stack.length) {
    const n = stack.pop();
    out.push(n.val);
    if (n.left) stack.push(n.left);              // left first → popped LAST
    if (n.right) stack.push(n.right);
  }
  return out.reverse();                          // node,right,left reversed = left,right,node
}

Part 3 — Return One Thing, Track Another

The hardest tree problems share a shape: the recursion must return a value useful to the parent, while the actual answer is something else entirely, recorded as you go.

function diameterOfBinaryTree(root) {            // LC 543
  let best = 0;

  const height = node => {
    if (!node) return 0;
    const L = height(node.left), R = height(node.right);
    best = Math.max(best, L + R);                // ← the ANSWER: path THROUGH this node
    return 1 + Math.max(L, R);                   // ← the RETURN: height, for the parent
  };

  height(root);
  return best;
}
// O(n) time, O(h) space

The two values are different and must not be confused. A parent needs its child's height to compute its own; the diameter is the best path found anywhere, which may not pass through the root at all.

function maxPathSum(root) {                      // LC 124
  let best = -Infinity;

  const gain = node => {
    if (!node) return 0;
    const L = Math.max(0, gain(node.left));      // ← clamp: a negative branch is skipped
    const R = Math.max(0, gain(node.right));
    best = Math.max(best, node.val + L + R);     // ANSWER: a path bending at this node
    return node.val + Math.max(L, R);            // RETURN: a straight path upward
  };

  gain(root);
  return best;
}

Math.max(0, ...) is the whole trick. A subtree with a negative sum should simply not be used — taking zero instead of a negative gain is what makes the greedy correct.

The balanced-tree check uses a sentinel to abort early rather than recomputing heights:

function isBalanced(root) {                      // LC 110
  const check = node => {
    if (!node) return 0;
    const L = check(node.left);
    if (L === -1) return -1;                     // propagate failure
    const R = check(node.right);
    if (R === -1) return -1;
    if (Math.abs(L - R) > 1) return -1;          // ← -1 means "unbalanced"
    return 1 + Math.max(L, R);
  };
  return check(root) !== -1;
}
// O(n) — the naive version calling height() at each node is O(n²)

Part 4 — Binary Search Trees

A BST's defining property is global, not local: every node in the left subtree is smaller, every node in the right subtree is larger — not just the immediate children.

        10
       /  \             INVALID as a BST:
      5    15           15's left child is 6, which is < 10
          /  \          but it sits in 10's RIGHT subtree
         6    20

function isValidBST(root) {                      // LC 98
  const check = (node, lo, hi) => {              // ← range narrows on the way DOWN
    if (!node) return true;
    if (node.val <= lo || node.val >= hi) return false;
    return check(node.left, lo, node.val) &&
           check(node.right, node.val, hi);
  };
  return check(root, -Infinity, Infinity);
}

Comparing only against the parent is the classic wrong answer — it accepts the invalid tree above. The valid range must be threaded down as parameters, which is a top-down problem.

In-order traversal of a BST yields sorted order, and that single fact solves a whole family:

function kthSmallest(root, k) {                  // LC 230
  const stack = [];
  let cur = root;
  while (cur || stack.length) {
    while (cur) { stack.push(cur); cur = cur.left; }
    cur = stack.pop();
    if (--k === 0) return cur.val;               // ← stop early; no full traversal
    cur = cur.right;
  }
  return -1;
}
// O(h + k) — not O(n)

Part 5 — Lowest Common Ancestor

For a general binary tree, LCA is a bottom-up problem with an elegant formulation:

function lowestCommonAncestor(root, p, q) {      // LC 236
  if (!root || root === p || root === q) return root;

  const L = lowestCommonAncestor(root.left, p, q);
  const R = lowestCommonAncestor(root.right, p, q);

  if (L && R) return root;                       // found on BOTH sides → this is the LCA
  return L || R;                                 // otherwise pass up whichever was found
}
// O(n) time, O(h) space

The return value means "the highest relevant node found in this subtree", which is either p, q, or their LCA. When both children report a find, the current node is the meeting point.

For a BST it is far simpler, because the values tell you which way to go:

function lcaBST(root, p, q) {                    // LC 235
  let cur = root;
  while (cur) {
    if (p.val < cur.val && q.val < cur.val) cur = cur.left;
    else if (p.val > cur.val && q.val > cur.val) cur = cur.right;
    else return cur;                             // the split point IS the LCA
  }
  return null;
}
// O(h) time, O(1) space

Part 6 — Construction and Serialisation

Building a tree from traversals requires knowing what each order tells you:

pre-order: [ROOT, ...left subtree, ...right subtree]     → the root is FIRST
in-order:  [...left subtree, ROOT, ...right subtree]     → the root SPLITS it
post-order:[...left subtree, ...right subtree, ROOT]     → the root is LAST

function buildTree(preorder, inorder) {          // LC 105
  const idx = new Map(inorder.map((v, i) => [v, i]));   // O(1) root lookup
  let p = 0;

  const build = (lo, hi) => {
    if (lo > hi) return null;
    const val = preorder[p++];
    const node = { val, left: null, right: null };
    const mid = idx.get(val);
    node.left = build(lo, mid - 1);              // ← left FIRST: pre-order consumes it next
    node.right = build(mid + 1, hi);
    return node;
  };
  return build(0, inorder.length - 1);
}
// O(n) with the index map; O(n²) without it

Pre-order + post-order is not enough to reconstruct a tree uniquely — a node with one child is ambiguous. In-order is what disambiguates, which is why every construction problem includes it.

Serialisation must record nulls, or the structure is lost:

function serialize(root) {
  const out = [];
  const go = n => {
    if (!n) { out.push("#"); return; }           // ← the null marker is essential
    out.push(String(n.val));
    go(n.left); go(n.right);
  };
  go(root);
  return out.join(",");
}

function deserialize(data) {
  const vals = data.split(",");
  let i = 0;
  const go = () => {
    const v = vals[i++];
    if (v === "#") return null;
    return { val: Number(v), left: go(), right: go() };
  };
  return go();
}

❌ Calling a helper that recomputes a subtree property at every node. The balanced-tree check written as "at each node, compute the height of both subtrees and compare" calls a height function that itself walks the entire subtree — so the work at the root is O(n), at each child O(n/2), and the total is O(n log n) on a balanced tree and O(n²) on a skewed one. It passes small tests and times out on the real input.

✅ Compute the property once, on the way up, and carry the answer with it. A single post-order pass returns the height while simultaneously checking the balance condition — using a sentinel like -1 to mean "already failed" so the failure propagates without further work. Every node is visited exactly once, giving O(n). The same restructuring turns the naive diameter and max-path-sum solutions from quadratic into linear.

Interview Questions

Beginner: Find the maximum depth of a binary tree, and explain the recursion. 
function maxDepth(root) {
  if (!root) return 0;
  return 1 + Math.max(maxDepth(root.left), maxDepth(root.right));
}
// O(n) time, O(h) space

This is bottom-up: a node cannot know its own depth without being told, but it can always compute its height from what its children return. The base case — an empty tree has depth 0 — seeds the recursion, and every node adds one to the deeper of its two subtrees.

        3           maxDepth(3) = 1 + max(maxDepth(9), maxDepth(20))
       / \                      = 1 + max(1, 2) = 3
      9   20
         /  \       maxDepth(20) = 1 + max(1, 1) = 2
        15   7      maxDepth(9)  = 1 + max(0, 0) = 1

The space is O(h), not O(1) — the recursion stack holds one frame per level. On a balanced tree that is O(log n); on a degenerate tree (a linked list) it is O(n), which can overflow.

The iterative BFS version avoids the stack and is worth mentioning:

function maxDepthBFS(root) {
  if (!root) return 0;
  let level = [root], depth = 0;
  while (level.length) {
    const next = [];
    for (const n of level) { if (n.left) next.push(n.left); if (n.right) next.push(n.right); }
    level = next;
    depth++;
  }
  return depth;
}

It uses O(width) space instead of O(height) — better on a deep narrow tree, worse on a shallow wide one.

A top-down variant exists — pass the depth down and track a maximum — but it is more code for the same result. Recognising that this problem is naturally bottom-up is the actual skill being tested.

Beginner: What are the traversal orders and when do you use each?

They differ only in when the node is visited relative to its children.

        1
      /   \        pre-order   1 2 4 5 3     node, left, right
     2     3       in-order    4 2 5 1 3     left, node, right
    / \            post-order  4 5 2 3 1     left, right, node
   4   5           level-order 1 2 3 4 5     by depth (BFS)
OrderUse forWhy
Pre-orderCopy a tree, serialise, propagate downwardThe node is handled before its children exist/are needed
In-orderBSTsProduces values in sorted order
Post-orderDelete a tree, aggregate subtree resultsChildren are finished before the parent needs them
Level-orderLevel/distance questionsVisits by depth — see BFS

In-order on a BST giving sorted order is the single most useful fact here, and it follows directly from the BST property: everything left is smaller, so visiting left-then-node-then-right emits values in increasing order. That one observation solves validation, kth-smallest, range queries and the "recover a swapped BST" problem.

Post-order for deletion matters because freeing a node before its children would lose the references to them — the children must be handled first.

The iterative in-order is worth being able to write, since it powers the BST iterator:

const out = [], stack = [];
let cur = root;
while (cur || stack.length) {
  while (cur) { stack.push(cur); cur = cur.left; }
  cur = stack.pop();
  out.push(cur.val);
  cur = cur.right;
}
Mid: Find the diameter of a binary tree.

The diameter is the longest path between any two nodes, which may not pass through the root. The key realisation: for each node, the longest path bending at that node is leftHeight + rightHeight.

function diameterOfBinaryTree(root) {
  let best = 0;
  const height = node => {
    if (!node) return 0;
    const L = height(node.left), R = height(node.right);
    best = Math.max(best, L + R);                // path THROUGH this node
    return 1 + Math.max(L, R);                   // height, for the parent
  };
  height(root);
  return best;
}
// O(n) time, O(h) space

The function returns one thing and records another, and that separation is the whole pattern. The parent needs the child's height to compute its own; the answer is the best bend found anywhere in the tree, which is tracked in an outer variable.

        1
       / \          at node 2: L=1, R=1 → path 4-2-5 has length 2
      2   3         at node 1: L=2, R=1 → path 4-2-1-3 has length 3  ← best
     / \
    4   5

Returning the diameter instead of the height is the classic error. The parent cannot use a diameter — it needs to know how far down the subtree extends in a straight line.

The naive approach is O(n²): for each node, compute the height of both subtrees with a separate helper. That recomputes the same heights repeatedly. The single-pass version computes each height once and uses it for both purposes.

Note the diameter is counted in edges, not nodes — L + R rather than L + R + 1. If the problem counts nodes, add one; misreading this is a common off-by-one.

The same shape solves Max Path Sum (124), with the added detail of clamping negative subtree gains to zero — which is the natural extension of "a bad branch simply is not used".

Mid: Validate a binary search tree.

The BST property is global: every node in the left subtree must be smaller than the current node, not just the immediate child. So a valid range must be threaded downward.

function isValidBST(root) {
  const check = (node, lo, hi) => {
    if (!node) return true;
    if (node.val <= lo || node.val >= hi) return false;
    return check(node.left, lo, node.val) &&
           check(node.right, node.val, hi);
  };
  return check(root, -Infinity, Infinity);
}
// O(n) time, O(h) space

The counterexample that kills the parent-only check:

        10
       /  \
      5    15
          /  \
         6    20      6 < 15 ✓ (parent check passes)
                      but 6 < 10 and it is in 10's RIGHT subtree ✗

Comparing each node only with its parent accepts this tree. Threading the range down catches it: when descending into 15's left child, the range is (10, 15), and 6 falls outside it.

The alternative is an in-order traversal checking strict increase:

function isValidBSTInorder(root) {
  let prev = -Infinity, ok = true;
  const go = n => {
    if (!n || !ok) return;
    go(n.left);
    if (n.val <= prev) { ok = false; return; }   // ← strictly increasing
    prev = n.val;
    go(n.right);
  };
  go(root);
  return ok;
}

Both are O(n). The in-order version is arguably more elegant because it reduces the problem to the known fact that a BST's in-order traversal is sorted.

Two details worth stating: the comparison must be strict (<= fails), since standard BSTs disallow duplicates; and using -Infinity/Infinity rather than integer sentinels avoids a bug when the tree actually contains Number.MIN_SAFE_INTEGER.

Senior: Find the maximum path sum in a binary tree, where a path can start and end anywhere.

Same structure as diameter — return one value, track another — with the added subtlety that negative subtrees should be excluded entirely.

function maxPathSum(root) {
  let best = -Infinity;
  const gain = node => {
    if (!node) return 0;
    const L = Math.max(0, gain(node.left));      // ← clamp negatives to 0
    const R = Math.max(0, gain(node.right));
    best = Math.max(best, node.val + L + R);     // a path BENDING here
    return node.val + Math.max(L, R);            // a STRAIGHT path upward
  };
  gain(root);
  return best;
}
// O(n) time, O(h) space

Two different quantities, and conflating them is the error:

MeaningCan it bend?
bestThe answer — best path anywhereYes, at this node
Return valueBest downward path from this nodeNo — a parent extends it

A path that bends at a node cannot be extended upward — the node is already used twice. So the return value must commit to a single branch.

Math.max(0, ...) encodes "skip a harmful subtree":

        2
       / \          gain(-5) = -5 → clamped to 0
      1   -5        best at 2 = 2 + 1 + 0 = 3   (the -5 branch is simply not used)

Without the clamp, the answer would be 2 + 1 + (−5) = −2, which is wrong because nothing forces the path to include that branch.

best must start at -Infinity, not 0 — a tree of all-negative values has a negative answer (the least-negative single node), and initialising to 0 would wrongly return 0.

The transferable insight: whenever a subtree's contribution is optional, clamp it at zero and let the maximum decide. The same idea appears in Kadane's algorithm for maximum subarray, which is this problem on a path graph.

Senior: Serialise and deserialise a binary tree.

The requirement is a round trip: deserialize(serialize(t)) must reproduce the exact structure, including which child a single child is.

function serialize(root) {
  const out = [];
  const go = n => {
    if (!n) { out.push("#"); return; }
    out.push(String(n.val));
    go(n.left);
    go(n.right);
  };
  go(root);
  return out.join(",");
}

function deserialize(data) {
  const vals = data.split(",");
  let i = 0;
  const go = () => {
    const v = vals[i++];
    if (v === "#") return null;
    return { val: Number(v), left: go(), right: go() };
  };
  return go();
}
// O(n) both ways

The null markers are what make it work, and omitting them is the classic failure:

     1          without markers: "1,2"
    /
   2            but this is also "1,2":     1
                                             \
                                              2

With markers the two are distinct: 1,2,#,#,# versus 1,#,2,#,#. This is the same reason pre-order plus post-order cannot reconstruct a tree — single-child nodes are ambiguous without additional information.

Pre-order is the natural choice because the root comes first, so deserialisation can build top-down while consuming the stream in order. In-order would not work at all — you cannot tell where the root is.

The BFS alternative is what LeetCode's own display format uses, and it is more compact for wide trees since trailing nulls can be dropped:

function serializeBFS(root) {
  if (!root) return "";
  const out = [], q = [root];
  let head = 0;
  while (head < q.length) {
    const n = q[head++];
    if (!n) { out.push("#"); continue; }
    out.push(String(n.val));
    q.push(n.left); q.push(n.right);
  }
  while (out[out.length-1] === "#") out.pop();   // trim trailing nulls
  return out.join(",");
}

function preIter(root) {
  if (!root) return [];
  const o = [], st = [root];
  while (st.length) {
    const n = st.pop();
    o.push(n.val);
    if (n.right) st.push(n.right);               // right first → left popped first
    if (n.left) st.push(n.left);
  }
  return o;
}

function inoIter(root) {
  const o = [], st = [];
  let cur = root;
  while (cur || st.length) {
    while (cur) { st.push(cur); cur = cur.left; }
    cur = st.pop();
    o.push(cur.val);
    cur = cur.right;
  }
  return o;
}

function postIter(root) {
  if (!root) return [];
  const o = [], st = [root];
  while (st.length) {
    const n = st.pop();
    o.push(n.val);
    if (n.left) st.push(n.left);
    if (n.right) st.push(n.right);
  }
  return o.reverse();
}

Randomised agreement check between recursive and iterative:

function randomTree(n) {
  if (n === 0) return null;
  const nodes = Array.from({length:n}, (_, i) => ({ val: i, left: null, right: null }));
  for (let i = 1; i < n; i++) {
    const p = nodes[Math.floor(Math.random() * i)];
    if (!p.left && (!p.right || Math.random() < 0.5)) p.left = nodes[i];
    else if (!p.right) p.right = nodes[i];
    else { i--; }                                // retry
  }
  return nodes[0];
}

function diameter(root) {
  let best = 0;
  const h = n => {
    if (!n) return 0;
    const L = h(n.left), R = h(n.right);
    best = Math.max(best, L + R);
    return 1 + Math.max(L, R);
  };
  h(root);
  return best;
}

function isBalanced(root) {
  const check = n => {
    if (!n) return 0;
    const L = check(n.left);
    if (L === -1) return -1;
    const R = check(n.right);
    if (R === -1) return -1;
    return Math.abs(L - R) > 1 ? -1 : 1 + Math.max(L, R);
  };
  return check(root) !== -1;
}

function maxPathSum(root) {
  let best = -Infinity;
  const gain = n => {
    if (!n) return 0;
    const L = Math.max(0, gain(n.left)), R = Math.max(0, gain(n.right));
    best = Math.max(best, n.val + L + R);
    return n.val + Math.max(L, R);
  };
  gain(root);
  return best;
}

function longestUnivaluePath(root) {             // LC 687
  let best = 0;
  const go = n => {
    if (!n) return 0;
    const L = go(n.left), R = go(n.right);
    const l = (n.left && n.left.val === n.val) ? L + 1 : 0;
    const r = (n.right && n.right.val === n.val) ? R + 1 : 0;
    best = Math.max(best, l + r);
    return Math.max(l, r);
  };
  go(root);
  return best;
}

function bruteMaxPath(root) {
  const nodes = [];
  const collect = n => { if (n) { nodes.push(n); collect(n.left); collect(n.right); } };
  collect(root);
  if (!nodes.length) return -Infinity;

  // path between a and b = sum over the unique path in the tree
  const pathTo = (from, target, acc) => {
    if (!from) return null;
    acc.push(from);
    if (from === target) return [...acc];
    const L = pathTo(from.left, target, acc);
    if (L) { acc.pop(); return L; }
    const R = pathTo(from.right, target, acc);
    acc.pop();
    return R;
  };

  let best = -Infinity;
  for (const a of nodes) for (const b of nodes) {
    // path from a to b: go up to LCA. Simplest: path from root to each, then merge.
    const pa = pathTo(root, a, []), pb = pathTo(root, b, []);
    let i = 0;
    while (i < pa.length && i < pb.length && pa[i] === pb[i]) i++;
    const lcaIdx = i - 1;
    const path = new Set([...pa.slice(lcaIdx), ...pb.slice(lcaIdx)]);
    let s = 0;
    for (const n of path) s += n.val;
    best = Math.max(best, s);
  }
  return best;
}

4 (medium): Solve BST problems using in-order order.
Solution 
function isValidBST(root) {
  const check = (n, lo, hi) =>
    !n || (n.val > lo && n.val < hi && check(n.left, lo, n.val) && check(n.right, n.val, hi));
  return check(root, -Infinity, Infinity);
}

function kthSmallest(root, k) {
  const st = [];
  let cur = root;
  while (cur || st.length) {
    while (cur) { st.push(cur); cur = cur.left; }
    cur = st.pop();
    if (--k === 0) return cur.val;
    cur = cur.right;
  }
  return -1;
}

function rangeSumBST(root, low, high) {          // LC 938 — with pruning
  if (!root) return 0;
  if (root.val < low) return rangeSumBST(root.right, low, high);   // prune left
  if (root.val > high) return rangeSumBST(root.left, low, high);   // prune right
  return root.val + rangeSumBST(root.left, low, high) + rangeSumBST(root.right, low, high);
}

function recoverTree(root) {                     // LC 99 — two nodes swapped
  let first = null, second = null, prev = null;
  const go = n => {
    if (!n) return;
    go(n.left);
    if (prev && n.val < prev.val) {              // an inversion
      if (!first) first = prev;                  // first inversion: take the LARGER
      second = n;                                // last inversion: take the SMALLER
    }
    prev = n;
    go(n.right);
  };
  go(root);
  [first.val, second.val] = [second.val, first.val];
  return root;
}

Solution 
function buildFromPreIn(preorder, inorder) {
  const idx = new Map(inorder.map((v, i) => [v, i]));
  let p = 0;
  const go = (lo, hi) => {
    if (lo > hi) return null;
    const val = preorder[p++];
    const mid = idx.get(val);
    const node = { val, left: null, right: null };
    node.left = go(lo, mid - 1);                 // LEFT first — pre-order order
    node.right = go(mid + 1, hi);
    return node;
  };
  return go(0, inorder.length - 1);
}

function buildFromPostIn(postorder, inorder) {
  const idx = new Map(inorder.map((v, i) => [v, i]));
  let p = postorder.length - 1;
  const go = (lo, hi) => {
    if (lo > hi) return null;
    const val = postorder[p--];
    const mid = idx.get(val);
    const node = { val, left: null, right: null };
    node.right = go(mid + 1, hi);                // RIGHT first — post-order reversed
    node.left = go(lo, mid - 1);
    return node;
  };
  return go(0, inorder.length - 1);
}

function serialize(root) {
  const out = [];
  const go = n => {
    if (!n) { out.push("#"); return; }
    out.push(String(n.val));
    go(n.left); go(n.right);
  };
  go(root);
  return out.join(",");
}

function deserialize(data) {
  const vals = data.split(",");
  let i = 0;
  const go = () => {
    const v = vals[i++];
    if (v === "#") return null;
    const node = { val: Number(v), left: null, right: null };
    node.left = go();
    node.right = go();
    return node;
  };
  return go();
}

function structurallyEqual(a, b) {
  if (!a && !b) return true;
  if (!a || !b) return false;
  return a.val === b.val && structurallyEqual(a.left, b.left) && structurallyEqual(a.right, b.right);
}

🎯 Key Takeaways

  • Every tree problem is one question: does this node need information from above (top-down parameters) or from below (bottom-up return values)?
  • Path-dependent facts — depth, accumulated sum, valid BST range — must be passed down; subtree facts — height, count, sum — must be returned up.
  • Problems needing both are solved by returning one value for the parent and recording the real answer in an outer variable.
  • Diameter returns the height and tracks L + R; returning the diameter instead breaks the parent's computation.
  • Max path sum clamps negative child gains to zero, and best must start at −Infinity so all-negative trees work.
  • The balanced check uses a −1 sentinel to fail fast in one pass — the naive recompute-height version is O(n²) and ~3800× slower on a skewed tree.
  • In-order traversal of a BST yields sorted order, and that single fact solves validation, kth-smallest, range sums and node recovery.
  • Validating a BST against the immediate parent is wrong — the property is global, so a (lo, hi) range must be threaded downward.
  • kth smallest should stop as soon as k is reached: O(h + k), not O(n).
  • Generic LCA returns "the highest relevant node in this subtree"; when both children report a find, the current node is the answer.
  • LCA in a BST is just a descent to the split point — O(h) time and O(1) space.
  • Tree construction needs an index map from value to in-order position, or indexOf plus slice makes it O(n²) in both time and memory.
  • From pre-order, recurse left before right; from post-order consumed backwards, recurse right before left.
  • Pre-order plus post-order cannot reconstruct a tree — single-child nodes are ambiguous, and in-order is what disambiguates.
  • Serialisation must emit null markers; without them, 64% of random small trees collide with a differently-shaped tree.
  • Recursion depth is O(h), which overflows on a degenerate tree past ~10⁴ nodes — use an explicit stack when the input is untrusted.
